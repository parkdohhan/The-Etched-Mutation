# 씬은 사건이다 — 플레이 형식 결정 + 0단계 수리 (260727)

> 사용자 결정 2026-07-27. 발단: "플레이어가 궤적 기반 진행을 Twine 트리와 구분하지 못한다.
> '그것이 저곳에 이미 존재한다'는 감각 때문이다. 위상수학적으로 위치가 상관없게 할 수 없나."

## 1. 개념 동결

**씬은 장소가 아니라 사건이다.**

- **지형(바닥) = 과거의 것.** 세계 고정, 지속. 작가 바닥 + 선행자 침식·퇴적(이본지층). "이미 존재한다"는 느낌은 지층에 대해서만 정당하다 — 그것은 남들의 과거이므로.
- **씬(사건) = 현재의 것.** 고정 주소를 갖지 않는다. 내 궤적이 지금 이 지형 위에 응결시키는 사건.
- 접촉 재정의(260716, "해냈다"가 아니라 "일어났다")와 같은 문법. 접촉도 사건, 씬도 사건.

## 3. 0단계 구현 기록 (260727 완료)

### 3-1. 발견된 결함 2건

1. **`updateAccess` 가 원칙 1 위반** — 패턴은 `TRANSITION_RULES` 반경만 골랐고, 중심은 항상
   "유저 감정 지도좌표와 직전 핀의 평균". CLAUDE.md §6.5 #1 이 명시한 WRONG 모델 그대로.
   올바른 모델(js/core/SceneNavigator.js `PATTERN_CENTER`)은 존재했으나 play-test 미사용.
2. **대화 경로(v21-phase1)가 접근 재계산을 아예 안 함** — `onSceneEnd` 가 `handleEmotionResult`
   미호출 + `pattern: 'bridge'` 하드코딩. 즉 현행 1인칭 플레이에서 궤적 기하는 **한 번도 안 돌았고**
   접근 핀은 입장 초기 3개(scene_order 순)에서 갱신되지 않았다. "Twine 같다"는 체감의 배선 원인.
   (R2-3 이 오염 집계만 dialogSession 으로 봉합하고 "transition_pattern 복원은 후속 항목"으로
   남겨둔 그 자리다.)

### 3-2. 수술 내용 (play-test.html 단일 파일)

1. **`PATTERN_CENTER` + `computeAccessCenter()` 신설** — SceneNavigator 와 동일 규칙 복사
   (모듈 경계 사본, 변경 시 양쪽 동기화). 중심을 지도좌표 평균이 아니라 **감정 공간(17축)에서
   블렌드한 뒤 AF 투영**:
   - echo_follow 0.7:0.3 (원본 쪽) / bridge 0.5:0.5 / displacement 0.3:0.7
   - contradiction = 유저 벡터 반전(1−v) 후 투영
   - avoidance = voidPin 좌표로 중심 이동 (없으면 유저 위치)
   - fixation = 현재 씬 감정 투영 (선택은 기존대로 originPin 단독)
2. **Fallback B 로 교체** — 반경(×1.85 확장 포함) 밖이면 "미방문 전부 개방"이 아니라
   **중심에서 가장 가까운 미방문 핀 1개만**. 구버전은 패턴이 중심을 멀리 보낸 순간
   전부 열려 기하가 무효화되는 구멍이었다. (원칙 4 서사 자막 연결은 후속.)
3. **대화 경로 배선** — `onSceneEnd` 에서 `byeoriCalculateStep` 실행(입력 재료는 고전 경로와
   동일 함수 재사용: `buildOriginalVectorFromScene`/`parseAnchorEmotions` + 궤적 배열들) →
   궤적 배열 push → `handleEmotionResult` 호출. traces 의 pattern 하드코딩도 엔진 산출로 교체.
   **`game.lastResult` 는 세우지 않음** — 봉인 오염 집계는 R2-3 dialogSession 경로 유지(이중 집계 방지).

### 3-3. 검증 (실제 경로, 260727)

로컬 서버 + 실 Supabase 데이터("발자국", 씬 6) 로 실플레이: 씬 진입 → 발화 입력 → LEAVE.

```
발화 분류: {joy 0.1, fear 0.2, anger 0.45, shame 0.35}
엔진: alignment 0.557, bucket HIGH → pattern echo_follow
중심: (0.579, 0.443) — 원본 핀(0.575, 0.422) 쪽으로 끌림 (유저 위치는 (0.613, 0.493))
      ※ 구모델이면 (0.594, 0.458) 중간점이었을 자리
결과: 접근 집합 {order 0,1,2} → {0,2,3,5} — order 1 닫히고 3·5 열림. plays 저장 정상.
```

대화 자체의 공명 라벨(vague, 0.406)과 엔진 판정(HIGH, 0.557)은 **서로 다른 어휘로 공존** —
전자는 유령 연출용, 후자는 접근 기하용. 의도된 이원화.
