## 🔄 Claude의 수정 제안

### 순서 재배치
원안 순서 (용어 → 테스트 → K/L/M → 단순 기억 → play 개선)는 **K/L/M을 테스트 베드 없이 만드는** 문제가 있음. L/M은 씬 여러 개가 있어야 의미 있는데, 장황한 기존 기억으론 효과 확인 어려움.

**제안 순서**:

1. **용어 합의 md** (원안 그대로 1순위)
   - 산출: `docs/용어사전-260415.md`
   - 포함: 잔상(각 세부 개념 분리), 파동함수/감정파동, 포트/브릿지/앵커, 오염 vs 변질 vs 이본, strata pin vs scene pin, accessiblePinIds 등
   - 각 용어마다 **(a) 정의 (b) 저장 위치 (c) 누가 쓰나 (d) 혼동 주의** 4항목

2. **단순 데모 기억 1개 생성** ← **원안보다 앞당김**
   - 장면 3-4개, 짧은 텍스트, 감정 벡터 극명하게 구분
   - 이유: 이후 모든 테스트/개발의 공통 픽스처. K/L/M 검증 전제.
   - Admin UI로 직접 만들기 (Canvas 통합 UX 자체 점검도 겸함)

3. **Admin 동작 테스트 1차** (현재 기능만)
   - 콘솔: `test/exclusion_console_tester.js` 외 기존 테스터 목록화 후 일괄 실행
   - play 연동: 데모 기억으로 Record → Play → Archive → Strata 한 바퀴
   - 산출: 버그 리스트 → Feedback.md에 번호 부여

4. **연출 레이어 K 완성 (Canvas 이관)**
   - Canvas 씬 편집 패널에 exclusions UI 추가 (`scenes.meta.exclusions` OR column 통일 결정 필요 — **선결 이슈**)
   - K-6~K-10 플레이 검증 (데모 기억 + 제약 1~2개 삽입)
   - 레거시 textarea 제거는 Phase 4 때

5. **play UX/버그 정리 1차** ← 원안 5를 여기로
   - 3단계 테스트에서 나온 리스트 소화
   - 데모 기억으로 계속 돈다

6. **L. 포트 경향성** (신규)
   - 스키마 설계부터: `scenes.meta.ports: [{emotion_bias, weight, hint_text?}]`
   - 엔진: 궤적 엔진 출력 재정렬
   - UI: Canvas 씬 편집 패널에 포트 CRUD
   - 데모 기억에 포트 2-3개 달아서 play 확인

7. **M. 유령 경로** (신규)
   - `memories.ghost_paths` 스키마
   - Canvas에서 씬 클릭 시퀀스로 경로 지정
   - strata 렌더

8. **Admin 테스트 2차 + 데모 기억 다듬기**

9. **Phase 4 레거시 정리 + SoundscapeBeta 대청소** (Feedback.md 기존 계획)

## 🧪 play-test 리팩토링 타이밍

**결론: 이 전체 사이클 끝나고 (Phase 4 직전 또는 직후).**

이유:
- play-test는 현재 데모 기억/K/L/M 검증의 **도구**. 도구를 손보며 검사하면 원인 분리 불가.
- 단, 테스트 중 **블로킹 버그만** 최소 수정 (리팩토링 아님, 패치). 이건 5단계 play UX 정리에 포함.
- 본격 리팩토링은 레거시 정리(Phase 4)와 묶어서. 그때 SoundscapeBeta 제거 + editorScreen 제거 + play-test 구조 개선을 한 브랜치에서.

- **데모 기억을 앞당기는 비용**: 아직 Canvas UX가 완성 안 됐을 수 있어, 만들다가 Canvas 버그 먼저 잡게 될 가능성. → 오히려 좋음 (진짜 작가 시나리오 테스트)
