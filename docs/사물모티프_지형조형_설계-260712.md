## 1. 무엇인가 / 왜인가

지형 위에 서 있는 것이 전부 **사람의 잔상**(유령·마네킹·발자국)뿐이라, 걷다 보면
"기억의 장소"라기보다 유령 전시장에 가깝다. 장면에 이미 데이터로 존재하는
사물 단어(`scenes.meta.motif_tags`)를 **장소의 잔상**으로 지형에 세운다.

단순 장식이 아니다. 되새김 앵커(260709)의 구조적 빈틈을 메우는 조각이다:
되새김은 "플레이어가 그 장면의 사물을 입에 담으면" 발동하는데, 그 사물이
화면 어디에도 안 보여서 플레이어가 단서 없이 우연에 기대야 했다. 사물이
지형에 서 있으면 고리가 닫힌다:

```
지형에서 사물을 본다 → 유령과의 대화에서 입에 담는다 → 되새김으로 떠오른다
                                                  → 지형의 그 사물도 또렷해진다
```

**문학적 구도** (사용자 확정 2026-07-12):
> 시계는 처음부터 거기 있었지만, 그대로 있는 건 아니다.
> 남들의 말은 유령을 물들이고, 나의 기억은 시계를 무너뜨린다.

- 유령을 바꾸는 건 **남들** — 응답 누적·시간에 따른 물듦 (전이). 나는 못 막는다.
- 사물을 바꾸는 건 **나** — 입에 담을수록 또렷해지고, 과하면 무너진다.
  = 기억유전학 Destructive Replication의 지형 대응물. 되새김 3단계 곡선과 동형.

## 2. 확정 결정 3가지

### 2.1 생김새 — 절차적 블록/초성 조형
단어 해시 → 항상 같은 형체의 블록 클러스터 (결정적 PRNG는
`lumen_recalled_anchors.js`의 `_hash`/`_mulberry32` 문법 재사용).

- 이유 = 룩이 아니라 **확장성**: 기억은 Record에서 계속 생성됨. 단어별 수제
  에셋은 "Record = first Play" 확장을 막는다. 절차적이면 어떤 기억의 어떤
  모티프든 즉시 조형화.
- 해시 덩어리는 사물처럼 안 생겼으므로 **근접 시 단어 라벨이 조형 곁에 배어남**
  (유령 텍스트 스프라이트 문법). 이게 없으면 되새김 단서 역할 실패.
- 작가 오버라이드 자리는 열어둔다 (전시용 대표 기억 소수만, pin_override와 같은
  10~15% 원칙). v1 범위 밖.

### 2.2 등장 — 처음부터 무대에 있음. 거리 안개만, 오염 게이팅 없음
유령의 문지기 둘(거리+오염) 중 **거리만** 태운다.

- 오염 게이팅을 버린 이유: 사물의 존재 이유가 되새김 고리의 *첫 단서*인데,
  오염이 쌓여야 나타나면 첫 회차에 단서가 0개 → 고리가 영영 안 닫힘.
- 철학적 역할 분리: **사물 = 첫 서술이 남긴 가구** (처음부터 존재),
  **유령 = 오염이 쌓이며 찾아오는 손님** (누적 후 발현). 존재의 출발점이 다르다.
- "안개 속 감각"은 거리 감쇠로 유지 (유령 검증값 차용: near 6 / far 26,
  baseOpacity 0.14 / nearOpacity 0.72 근방에서 튜닝 시작).

### 2.3 상태 — 되새김 3단계와 동기
| 언급 횟수 | 되새김 앵커 (화면 글자) | 지형 조형 |
|---|---|---|
| 0회 | (없음) | 흐릿한 실루엣 (기본) |
| 1회 | 흐릿하게 떠오름 | 밝아지기 시작 |
| 2회 | 또렷하게 빛남 | 또렷한 형체 |
| 3회+ | 아스키/블록 붕괴 | 블록이 부서져 흩어짐 |

새 규칙 발명 아님 — 260709에 확정한 곡선을 한 겹 더 입히는 것.

### 2.4 문장 운반자 (v1.1 신설) — 사물이 잘린 서사를 나른다

배경: 대화창의 씬 서사는 본문 앞 2~3문장에서 잘린다 (`scene_context` slice).
발자국 씬 4의 반전("사진 뒷면에는 '사랑하는 나의 아내'")처럼 문단 뒤쪽의
핵심 사실은 플레이어에게 영영 전달되지 않았다 — "대화만으로 정보량이
되는가" 고민의 실체.

해법: 근접 시 배어나는 것 = **단어 + 그 사물이 등장하는 원문 한 문장**.

- 문장은 씬 `text`에서 그 모티프 단어가 포함된 문장을 **자동 추출** (저작 비용 0).
  같은 단어가 여러 문장에 있으면 해시로 결정적 픽. 못 찾으면 단어만 (v1 동작).
- 작가 오버라이드 자리: `scenes.meta.object_lines = { "사진": "..." }` (반전급 지정용).
- 오염이 깊으면 원문 대신 `text_stage_N`에서 추출 — **증거물마저 변질**되는 연출.
- 역할 분담 확정: **대화 = 관계·해석, 사물 = 사실·증거, 되새김 = 둘을 잇는 기억.**
  대화에게 이야기꾼 역할까지 시키지 않는다.
- **260730 개정 (사용자 결정)**: 공중 부유 라벨 폐지 → **길게 눌러 열람**으로 대체.
  사물을 겨눠 길게 누르면 하단 대화창풍 창에 `단어 + 원문 문장` 표시(4.2초 후 페이드).
  속삭임(bottom:120)과 층 분리(word 196 / 문장 160). `labelMode:'float'` 로 롤백 가능.
  같은 날 씬(대화) 진입도 강화 — 근접만으로 열리던 것을 **근접 + 실제 조준**(핀 구슬
  + 마네킹 몸통 레이캐스트)으로. "길게 눌러" 안내도 조준했을 때만 표시.
- **동작 통일 (같은 날 2차 결정)**: 짧은 클릭 폐기. 지형의 모든 상호작용이
  **"겨누고 길게 누르기"** 하나 — 겨눈 대상이 사물이면 열람, 유령이면 씬 진입,
  출구문이면 퇴장. 판정 시간은 `LONG_PRESS_MS`(800ms) 공유
  (play-test 가 `window.__temLongPressMs` 로 공개, 모듈이 참조).
  - 누르는 동안 그 사물만 최대 1.4배로 또렷해짐 = 열람 임박 신호 (자체 피드백).
  - 조준 시 안내 "길게 눌러 들여다보기" (유령 안내와 같은 자리 bottom:90, 배타적).
  - **이중 발화 방지**: 사물 메시를 씬 진입 레이캐스트의 **가림막**으로 등록
    (`api.meshes()`). 사물 뒤에 유령이 서 있어도 사물이 앞을 막으면 열람만 발동.
  - 모바일은 touchstart/touchend 로 같은 동작 (탭 아님).

### 2.5 배치 — 길목 자동 + 작가 지정 소수 (v1.1 변경, 사용자 확정)

v1의 "핀 위치에서 오프셋 2~4유닛"을 대체한다. 사물의 임무가 *걷는 시간의
공백*을 메우는 것이므로 핀 곁이 아니라 **핀 사이 길목**에 선다:

- 기본: scene_order 사슬(씬1→2→…)의 각 선분 위 t≈0.35~0.65 지점 + 수직
  오프셋 1~3유닛. 전부 단어 해시 기반 결정적.
- 발견→대화→되새김 순서가 몰입 루프가 된다 (장화를 먼저 보고, 유령에게
  장화 얘기를 꺼낸다).
- 작가 지정 소수: `scenes.meta.object_pos` 좌표 직접 지정 (반전급 1~2개,
  pin_override와 같은 10~15% 원칙).
  → **260730 구현 완료** (§7). 형태 = `{ 단어: { x, z } }` (씬별). admin 위치 화면에서
  마커를 끌면 저장, 두 번 클릭하면 지정 해제(자동 자리 복귀).

**함정 회피 (중요)**: 접근 가능 핀 집합은 턴마다 바뀌고 핀은 턴마다 재구축된다.
길목을 "접근 가능 핀 사이"로 계산하면 사물이 턴마다 순간이동 — "처음부터
거기 있던 가구"라는 §2.2 존재론이 깨진다. 따라서 배치는 **접근성과 무관하게
전 장면 사슬의 고정 좌표**로 한 번만 계산한다 (회차 내내·회차 간 불변).
접근성 게이팅은 어차피 §2.2에서 배제했으므로 철학도 일치. rebuild 시에도
좌표 재계산 없이 유지 (마네킹과 다른 점 — 마네킹은 접근 핀 종속, 사물은 아님).

## 7. 사물 위치 작가 지정 (2026-07-30 — admin 배선)

사물 배치가 자동 계산뿐이어서 "이 욕조만 저 언덕 위로"가 불가능했다. §2.5에 예약돼 있던
`object_pos` 를 실제로 읽고, admin 위치 화면에서 끌어 옮길 수 있게 했다.

### 7.1 자리 계산 단일화 (선행 작업)
**신규 `js/shared/tem_object_anchors.js`** — 자리 수식이 플레이 모듈 안에만 있으면 admin 이
같은 수식을 베껴야 하고, 그 순간부터 두 계산은 서로 모르게 어긋난다(= pin_override 가 죽은
레버가 된 것과 같은 사고). 그래서 계산을 이 파일 하나에만 둔다.
- `layout(items, opts)` — 정렬·단어 선정·길목 좌표·작가 지정 우선을 모두 처리.
- 난수 소비 순서 **t → side → perp → rotY 고정**. 바꾸면 기존 모든 사물이 이동한다.
- 이식 검증: 팬티 기억 사물 23개 좌표가 이식 전과 소수점까지 동일 (12개 표본 대조, 불일치 0).

### 7.2 기준틀 통일 — 예상 못 한 선행 결함
사물의 자리는 씬 핀의 자리에서 파생되는데, **두 화면의 핀 좌표 공식이 달랐다**:
- 팬티 기억 13씬 중 `stage_position` 보유 = **1개**. 나머지 12개는 자동 투영.
- 플레이 = 감정 투영(`H2=23` + 기억 해시 오프셋). admin = AF 투영 → VAD → 원형 순.
- 결과: 같은 씬이 두 화면에서 다른 자리 → admin 에서 사물을 배치해도 의미가 없다.

`resolvePinPos(scene, memoryId)` 를 공용 모듈에 두고 **관객이 걷는 쪽(플레이) 규칙으로 통일**.
admin `getStagePosition` 이 이를 먼저 쓰고, 감정도 없는 씬만 옛 폴백으로 내려간다.
(실측: admin 상태줄 "수동 1 · AF 0 · 감정 12" — 12개가 플레이 공식으로 전환됨.)

### 7.3 admin 조작
- 사물 = **흙빛 상자 + 바닥 디스크 + 이름표**. 작가 지정 사물은 밝은 금빛.
- 끌어 옮기면 `scenes.meta.object_pos[단어]` 에 저장. **두 번 클릭 = 지정 해제**(자동 복귀).
- 집기 우선순위: 장면 유령(핀) → 사물 → 잔상 유령.
- 함정 2건 (둘 다 실측으로 발견):
  1. `pointerdown` 에서 `preventDefault()` 를 하면 Chrome 이 뒤따르는 dblclick 을 만들지
     않는다 → 두 번 클릭이 영영 안 먹었다. 사물을 집은 경우만 기본동작을 살린다.
  2. 이름표 스프라이트(6유닛, depthTest 없음)가 옆 사물의 몸통보다 카메라에 가까워
     raycast 를 가로챘다 ("피" 를 겨눴는데 "눈" 이 잡힘). 이름표는 `raycast` 무력화.
- 점검용: `LumenAdminStageView._debugObjects()` — 단어·좌표·지정여부·화면좌표.

## 8. 자동 생성 파이프라인 (2026-07-30 — 수동 → 서버 자동)

그전까지 모델 생성은 전부 수동이었다(명령줄 실행 + SQL 기록). 그래서 대표 기억 하나만
3D 였고, RECORD 로 새로 태어난 기억은 사물 태그까지는 자동으로 생기지만 형체는 블록.
이 절이 그 사이를 잇는다.

### 8.1 왜 두 몫으로 쪼갰나
모델 하나에 60~120초. 서버 함수 하나가 8개를 다 기다리면 실행 시간 제한에 걸린다.
→ **주문(enqueue)** 과 **수확(collect)** 분리. 양쪽 모두 여러 번 불러도 안전(idempotent).

| 몫 | 언제 | 하는 일 |
|---|---|---|
| enqueue | 관객이 기억을 묻은 직후 (`confession.js`) | 모델 없는 단어에 Tripo 작업 생성 → task_id 를 meta 에 적어둠 |
| collect | 그 기억을 열 때 (`play-test.html` loadMemoryData) | 완성분만 내려받아 Storage 저장 → `meta.object_models` 기록 |
| sync | 수동 호출 | collect → enqueue 를 한 번에 |

관객이 만들고 떠나도, **다음 방문자가 그 기억을 열면 그때 수확**된다 (자연 완성).
예약 실행(pg_cron)은 이 프로젝트에서 꺼져 있어 쓰지 않았다 — 필요해지면 추가 후보.

### 8.2 구성
- 서버: **`supabase/functions/generate-object-model/index.ts`** (verify_jwt 없음 — 다른
  record-* 함수와 같은 결. 남용 가드는 아래 8.4).
- 창고: Storage 버킷 **`object_models`** (public, 20MB 상한, glb). 경로 = `기억id/task_id.glb`.
  파일명에 한글 단어를 넣지 않는다 — 공개 주소 만들 때 이중 인코딩 위험.
- 상태 (새 테이블 없이 memories.meta):
  - `object_models` = `{ 단어: { path, source, prompt, bytes, created_at } }` ← 완성품
  - `object_model_jobs` = `{ 단어: { task_id, prompt, created_at } }` ← 진행 중
- 키: `TRIPO_API_KEY` 를 Edge Function 시크릿으로 (`supabase secrets set`, 260730 설정 완료).

### 8.3 프롬프트 자동 생성 (설계 §6 원칙의 자동화)
단어만으로는 부실하다("눈"=snow/eye). 함수가 **씬 본문에서 그 단어가 든 문장**을 뽑아
Claude Haiku 에게 넘기고, 다음 규칙으로 영어 프롬프트를 만든다:
① 원문 문장으로 뜻 확정 ② 만질 수 있는 단일 물체로만, 추상어·소리는 담고 있던 물건으로
치환(벨소리→낡은 전화기) ③ 사람 전신 금지(유령의 몫), 신체는 조각·석고 파편으로 사물화
④ 로우폴리 문구 포함 ⑤ 영어 한 줄 25단어. Claude 실패 시 규칙 기반 폴백.

실측 효과 (발자국): "핫초코" → *a cup of hot chocolate from a vending machine*,
"노란 장화" → *yellow rain boots standing in an entryway*, "슬리퍼" → *worn house slipper
with footprint marks*. 원문 맥락이 형체에 실렸다.

### 8.4 가드 (반복 호출·비용)
- 기억당 단어 상한 `MAX_WORDS_PER_MEMORY = 14` (≈ $4).
- 이미 모델 있거나 주문 중인 단어는 건너뜀 → **같은 기억에 몇 번 호출해도 추가 크레딧 0**.
- 30분 넘게 안 끝난 주문은 버리고 다음 호출에서 재주문(`JOB_STALE_MS`).
- **속도 제한 (260730 실측)**: 주문을 연달아 쏘면 6번째부터 Tripo 가 429. 그래서
  한 번 호출에 `ENQUEUE_BATCH = 5` 개까지만, 사이에 1.5초 간격, 429 면 4초 쉬고 1회 재시도.
  남은 단어는 `deferred` 로 보고되고 다음 호출이 잇는다.

### 8.5 e2e 실측 (260730, 발자국 기억)
사물 태그 8개(슬리퍼·샤넬 구두·핫초코·부츠·노란 장화·사진·아스팔트·발자국) 중
1차 주문 5개 → 수확 5개(483~900KB) → 남은 3개 주문. 크레딧 소모 ≈ $2.2.
대표 기억 외 두 번째 기억이 3D 화된 첫 사례.

### 8.6 예약 수확 (같은 날 추가) — 방문 없이도 완성된다
`pg_cron` + `pg_net` 확장을 켜고(둘 다 꺼져 있었음) 2분 주기 작업 `object-models-collect` 등록:

```
굽고 있는 주문이 있는 기억만 골라 collect 를 두드린다
→ 진행 중 주문이 없으면 대상 행 0개 = 아무 일도 안 함 (비용·부하 0)
```

함수가 `verify_jwt` 없음이라 **키를 Vault 에 보관할 필요가 없다** (헤더 없이 호출 확인).
이로써 수확 경로가 셋 — 예약(2분) / 관객이 그 기억을 열 때 / admin 버튼. 서로 무해하게 겹친다.

**무인 검증 (260730)**: 발자국의 "사진" 모델 기록만 지우고 주문을 넣은 뒤 아무도 건드리지
않고 대기 → 예약 작업이 스스로 수확해 목록에 복귀. 사람 개입 0 으로 파이프라인이 닫혔다.

### 8.7 admin 조작
사이드바 도구에 **"사물 3D 모델 뽑기"** 버튼 (`tvObjectModelsBtn`). 한 번 누르면 sync —
완성분 수확 + 모델 없는 단어 주문. 결과를 버튼 아래 한 줄로 보고한다:
`거둠 n: … · 주문 n: … · 굽는 중 n: … · 대기 n: … · 실패 n: … — 완성 N개 / 진행 M개`
(실패·거절이 있으면 주황색). 누른 뒤 1~2분 지나 다시 누르면 나머지가 붙는다.

### 8.8 회차 일지 — 알파 데이터 구멍 봉합 (2026-07-31)

새 플레이 방식(회상 게이트·길게 눌러 열람·침묵 허용 대화)이 만든 미기록 3종을 막았다.
원칙: **회차에 일어난 일은 전부 run_id 를 달고 남는다. 단, plays 에는 섞지 않는다** —
plays 행 수를 세는 소비자(오염도 평균·방문 깊이·겹 수)가 여럿이라 지표가 오염되므로,
전용 테이블 `run_journals` 신설 (회차당 1행, 사건마다 patch, 첫 사건 때 지연 생성).

| 사건 | 언제 기록 | 칸 |
|---|---|---|
| 회상 대답 (침묵 포함) | 대답한 그 순간 (브라우저 닫아도 남게) | `recall_answer {text, silent, ts}` |
| 침묵 방문 | 씬 대화가 무언으로 끝날 때 | `silent_visits [{scene_id, ts}]` |
| 사물 열람 | 봉인 때 스냅샷 (`getViewLog()` — lumen_scene_objects 열람 장부) | `object_views [{word, count}]` |
| 되새김 도달 | 봉인 때 스냅샷 (`LumenRecalledAnchors.getState()`) | `recall_stages {단어: stage}` |
| 회상 게이트 여부 | 봉인 때 | `rep_gate` |

- 헬퍼 = play-test `_journalPatch` (`window.__temJournal` — 회상 게이트 스코프에서도 호출).
  동시 생성 경합은 생성 약속 공유로 차단. 회차 시작 시 일지 상태 리셋 (_runId 옆).
- RLS 는 plays 와 같은 결 (익명 삽입 + 24시간 내 갱신).
- e2e (260731): 실제 페이지에서 3종 patch → DB 왕복 전 항목 확인 후 시험 행 삭제.
- 알파 분석: 정량 = plays (형식 도장 포함) / 정성·행동 = run_journals. run_id 로 join.

## 9. 대표 앵커 (rep_anchors) — 회상 연출의 연료 (260731)

> 하나라도)" 으로 재연출. 이 절은 그 1단계 — 데이터·admin·자동배선.

### 9.1 스키마
`memories.meta.rep_anchors = ["팬티", "지갑"]` — 이 기억의 얼굴이 되는 사물 단어, 최대 3개.
단어는 씬들의 `object_tags` 어휘와 같은 것을 쓴다 (GLB 는 `meta.object_models[단어]`).

### 9.2 admin 지정 (lumen_admin_stage_view.js, 260731a)
- 위치(stage) 탭에서 사물 마커 **Alt+클릭 = 대표 토글**. 최대 3개(넘으면 콘솔 경고).
- 대표 마커는 보랏빛(0xcbb8e8) + 이름표 ★ + 바닥 링. 색 우선순위: 대표 > 작가 지정 위치 > 자동.
- 저장은 fetch→merge→update — Edge Function 이 같은 meta 에 쓰는 object_models 를 안 덮게.
- 기존 인터랙션 불변: 드래그=위치, 클릭=씬 편집, 더블클릭=위치 해제.

### 9.3 RECORD 자동 추출 (confession.js, 260731a)
저장 두 경로(saveConfessionToDB·saveRecordMemory) 모두 저장 직후 `saveRepAnchors()` 호출.
규칙: **여러 씬에 반복 등장 우선(동률이면 앞 씬 우선), 최대 3개** — 반복해서 돌아가는
사물이 그 기억의 얼굴이라는 가정. 이미 작가 지정(rep_anchors 존재)이면 자동이 덮지 않음.

## 10. 유령 외관=사물 (260802, 사용자 결정)
