## 1. 무엇인가 / 왜인가

지형 위에 서 있는 것이 전부 **사람의 잔상**(유령·마네킹·발자국)뿐이라, 걷다 보면
"기억의 장소"라기보다 유령 전시장에 가깝다. 장면에 이미 데이터로 존재하는
사물 단어(`scenes.meta.motif_tags`)를 **장소의 잔상**으로 지형에 세운다.

단순 장식이 아니다. 되새김 앵커(260709)의 구조적 빈틈을 메우는 조각이다:
되새김은 "플레이어가 그 장면의 사물을 입에 담으면" 발동하는데, 그 사물이
화면 어디에도 안 보여서 플레이어가 단서 없이 우연에 기대야 했다. 사물이
지형에 서 있으면 고리가 닫힌다:

```
지형에서 사물을 본다 → 유령과의 대화에서 입에 담는다 → 되새김으로 떠오른다
                                                  → 지형의 그 사물도 또렷해진다
```

**문학적 구도** (사용자 확정 2026-07-12):
> 시계는 처음부터 거기 있었지만, 그대로 있는 건 아니다.
> 남들의 말은 유령을 물들이고, 나의 기억은 시계를 무너뜨린다.

- 유령을 바꾸는 건 **남들** — 응답 누적·시간에 따른 물듦 (전이). 나는 못 막는다.
- 사물을 바꾸는 건 **나** — 입에 담을수록 또렷해지고, 과하면 무너진다.
  = 기억유전학 Destructive Replication의 지형 대응물. 되새김 3단계 곡선과 동형.

## 2. 확정 결정 3가지

### 2.1 생김새 — 절차적 블록/초성 조형
단어 해시 → 항상 같은 형체의 블록 클러스터 (결정적 PRNG는
`lumen_recalled_anchors.js`의 `_hash`/`_mulberry32` 문법 재사용).

- 이유 = 룩이 아니라 **확장성**: 기억은 Record에서 계속 생성됨. 단어별 수제
  에셋은 "Record = first Play" 확장을 막는다. 절차적이면 어떤 기억의 어떤
  모티프든 즉시 조형화.
- 해시 덩어리는 사물처럼 안 생겼으므로 **근접 시 단어 라벨이 조형 곁에 배어남**
  (유령 텍스트 스프라이트 문법). 이게 없으면 되새김 단서 역할 실패.
- 작가 오버라이드 자리는 열어둔다 (전시용 대표 기억 소수만, pin_override와 같은
  10~15% 원칙). v1 범위 밖.

### 2.2 등장 — 처음부터 무대에 있음. 거리 안개만, 오염 게이팅 없음
유령의 문지기 둘(거리+오염) 중 **거리만** 태운다.

- 오염 게이팅을 버린 이유: 사물의 존재 이유가 되새김 고리의 *첫 단서*인데,
  오염이 쌓여야 나타나면 첫 회차에 단서가 0개 → 고리가 영영 안 닫힘.
- 철학적 역할 분리: **사물 = 첫 서술이 남긴 가구** (처음부터 존재),
  **유령 = 오염이 쌓이며 찾아오는 손님** (누적 후 발현). 존재의 출발점이 다르다.
- "안개 속 감각"은 거리 감쇠로 유지 (유령 검증값 차용: near 6 / far 26,
  baseOpacity 0.14 / nearOpacity 0.72 근방에서 튜닝 시작).

### 2.3 상태 — 되새김 3단계와 동기
| 언급 횟수 | 되새김 앵커 (화면 글자) | 지형 조형 |
|---|---|---|
| 0회 | (없음) | 흐릿한 실루엣 (기본) |
| 1회 | 흐릿하게 떠오름 | 밝아지기 시작 |
| 2회 | 또렷하게 빛남 | 또렷한 형체 |
| 3회+ | 아스키/블록 붕괴 | 블록이 부서져 흩어짐 |

새 규칙 발명 아님 — 260709에 확정한 곡선을 한 겹 더 입히는 것.

### 2.4 문장 운반자 (v1.1 신설) — 사물이 잘린 서사를 나른다

배경: 대화창의 씬 서사는 본문 앞 2~3문장에서 잘린다 (`scene_context` slice).
발자국 씬 4의 반전("사진 뒷면에는 '사랑하는 나의 아내'")처럼 문단 뒤쪽의
핵심 사실은 플레이어에게 영영 전달되지 않았다 — "대화만으로 정보량이
되는가" 고민의 실체.

해법: 근접 시 배어나는 것 = **단어 + 그 사물이 등장하는 원문 한 문장**.

- 문장은 씬 `text`에서 그 모티프 단어가 포함된 문장을 **자동 추출** (저작 비용 0).
  같은 단어가 여러 문장에 있으면 해시로 결정적 픽. 못 찾으면 단어만 (v1 동작).
- 작가 오버라이드 자리: `scenes.meta.object_lines = { "사진": "..." }` (반전급 지정용).
- 오염이 깊으면 원문 대신 `text_stage_N`에서 추출 — **증거물마저 변질**되는 연출.
- 역할 분담 확정: **대화 = 관계·해석, 사물 = 사실·증거, 되새김 = 둘을 잇는 기억.**
  대화에게 이야기꾼 역할까지 시키지 않는다.

### 2.5 배치 — 길목 자동 + 작가 지정 소수 (v1.1 변경, 사용자 확정)

v1의 "핀 위치에서 오프셋 2~4유닛"을 대체한다. 사물의 임무가 *걷는 시간의
공백*을 메우는 것이므로 핀 곁이 아니라 **핀 사이 길목**에 선다:

- 기본: scene_order 사슬(씬1→2→…)의 각 선분 위 t≈0.35~0.65 지점 + 수직
  오프셋 1~3유닛. 전부 단어 해시 기반 결정적.
- 발견→대화→되새김 순서가 몰입 루프가 된다 (장화를 먼저 보고, 유령에게
  장화 얘기를 꺼낸다).
- 작가 지정 소수: `scenes.meta.object_pos` 좌표 직접 지정 (반전급 1~2개,
  pin_override와 같은 10~15% 원칙).

**함정 회피 (중요)**: 접근 가능 핀 집합은 턴마다 바뀌고 핀은 턴마다 재구축된다.
길목을 "접근 가능 핀 사이"로 계산하면 사물이 턴마다 순간이동 — "처음부터
거기 있던 가구"라는 §2.2 존재론이 깨진다. 따라서 배치는 **접근성과 무관하게
전 장면 사슬의 고정 좌표**로 한 번만 계산한다 (회차 내내·회차 간 불변).
접근성 게이팅은 어차피 §2.2에서 배제했으므로 철학도 일치. rebuild 시에도
좌표 재계산 없이 유지 (마네킹과 다른 점 — 마네킹은 접근 핀 종속, 사물은 아님).

## 3. 구현 계획

### 3.1 1단계 — 조형이 안개 속에 서 있음 (독립 완결 슬라이스)

`lumen_scene_mannequins.js`와 같은 attach 패턴:

```js
LumenSceneObjects.attach(rt, {
  getScenePins: function () { return _fpScenePins; },  // 마네킹과 동일 소스
});
// rt.__lumenSceneObjects.rebuild() — 핀 재구축 후 호출 (마네킹 rebuild 옆)
```

내부 동작:
1. 핀별로 `pin.scene.meta.motif_tags`에서 최대 2개 선정
   (해시 기반 결정적 선택 — 같은 장면은 항상 같은 사물).

3. 조형: 단어 해시 → 블록 클러스터 (BoxGeometry 병합 or InstancedMesh,

4. 거리 페이드: 유령 문법 이식 (§2.2 수치에서 시작).
5. 근접 라벨: near 안쪽에서 단어 스프라이트 페이드인 (유령 스프라이트 문법).

## 5. v1에서 하지 않는 것 (후속 후보로만 기록)
- 오염 게이팅 (§2.2에서 의도적으로 배제)
- 전이 물듦 — 사물이 시간×오염으로 남들 쪽에 물드는 것 (유령 전용 유지)
- 릴레이/화석 승계 — 앞사람이 되새긴 사물이 다음 사람 지형에 잔존 (지형모델 v2 연결, V3 거리)
- 작가 커스텀 조형 오버라이드 (10~15% 원칙 하에 후속)
