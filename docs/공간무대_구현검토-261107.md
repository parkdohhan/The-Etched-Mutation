## 0. 쉬운 판 — 결론 여섯 줄

1. **제안의 뼈대는 맞다.** "방+통로, 엔진이 길을 안 고름, 흔적은 보이되 유리하지 않음, 끝나면 내 실 조각, 집단은 나중에"는 11-05 정의(실의 그물)와 11-06에 접수된 무대 결정 "(가) 몸통 하나·보이는 것만 다름"과 같은 방향이다. 9월 통로 3D 실험이 이 무대의 절반(통로·공간 종류·흔적)을 이미 코드로 세워 놨다.
2. **고쳐야 할 곳 (11-07 사용자 교정 반영 — 첫 판의 셋 중 둘은 내가 틀렸다).** ① **거리는 미리 그린 지도가 아니다.** 관객이 그 씬의 유령·사물과 나눈 상호작용의 결과(별이엔진 출력)가 다음 방까지의 통로 길이·모양·밝기를 그 자리에서 정한다. 통로 3D 실험이 이미 그렇게 돼 있다(정렬도→길이, 패턴→모양). 첫 판의 "작가 감정 거리로 정적 배치"는 폐기. ② **별이엔진은 살아 있다.** 들이지 않는 것은 감정값 문턱으로 길을 열고 닫는 **이진 잠금**뿐. 엔진은 거리·모양·가시성을 연속으로 정하고 어떤 방도 잠그지 않는다. 첫 판의 "엔진 접근 집합 은퇴"는 철회. ③ **관객은 장면(점)을 추가할 수 있다** — 이본론(변이 = 재창조·재조합). 홍길동전을 들은 B가 장면을 더해도 홍길동전이듯. 같은 기억의 기준은 "같은 점 집합"이 아니라 **계보**(어느 기억의 어느 실에서 어느 점 뒤에 붙었나). 정의 v1 §1의 "점 = 작가가 쓴 것, 고정" 문구가 수정 대상(§9 D8). ④ 이론 문서 후보 "관 굵기 → 복도 폭"은 쏠림 금지 제약과 충돌해 폐기, 굵기는 표면(마모·빛·잔향)에만.
3. **기술 방향.** 방을 통째로 AI가 만드는 것은 1순위가 아니다 — 조사 결과 "걸을 수 있는 방 전체를 편집 가능 메시로, 16GB에서, 한국에서 합법으로" 내주는 공개 도구가 없고(Hunyuan 계열은 라이선스가 대한민국 제외), 연결·통로·출입구·충돌 층은 어떤 도구도 안 준다. 1순위 = 절차 골격(벽·바닥·문턱·닫힘 정도·하늘·안개·빛을 코드가 세움, 이미 있음) + 검수된 CC0 자산(재질 약 2,900종·사물) + 서사 고유 사물만 형상 생성(TripoSG 로컬 또는 현행 Tripo 상위 등급, 재질은 자산으로). **로컬 생성기가 Tripo보다 낫다는 근거는 없다**(공개 아레나 Tripo 1위) — 근접 디테일 문제의 답은 생성기 교체가 아니라 재질 자산이다. 방 전체 사전 생성(Infinigen·Marble)은 "그 씬에 특별한 셸이 필요할 때"의 2순위. 근거와 도구별 실행 조건은 §3·§4.
4. **렌더러.** 현행 three.js r128 전역 빌드를 유지하되 새 무대는 **별도 모듈(ESM)로 최신 three를 따로 띄워** 병행하는 안이 1순위 — 지형 셰이더·마네킹·FBX를 안 건드리고, KTX2·최신 로더·충돌 라이브러리를 쓸 수 있다. 전역 THREE 충돌 조건은 §3-D.
5. **장비.** 이 책상 컴퓨터 = i7-13700KF(16코어) · 64GB · Windows 11 · RTX 5080 16GB · WSL2 우분투(그래픽카드 인식됨) · Blender 4.4. 리눅스 전용 연구 코드는 WSL2에서 돌릴 수 있다. 단 RTX 50 세대(Blackwell)는 옛 PyTorch를 고정한 저장소에서 깨질 수 있어, 도구마다 §3에 적었다.
6. **다음 한 수 = 결정 문서(§9) → 실험 페이지 P1(본 코드 0줄) → 자산 생성 시험 P2 → 로컬 분할안 시험 P3.** 측정 항목은 §7.

**왜 1순위인가**
1. "방 전체를 걸을 수 있는 편집 메시로, 16GB에서, 한국 합법으로" 내주는 공개 도구가 없다(§3-B) → 방 전체 AI 생성에 기대는 구성은 애초에 성립하지 않는다.
2. 연결·통로·출입구·충돌 층은 어떤 도구도 안 준다(§3-A) → 어차피 우리 코드이고, 그 절반(T1b 빌더·규칙·이동·흔적)은 이미 있다.
3. 품질 병목은 형상이 아니라 재질·근접 디테일이고, 답은 CC0 PBR 자산이다(§3-C). 생성기 교체는 답이 아니다.
4. 외부 전송 0 경로가 자연스럽다(§8): 배치·골격·통로는 브라우저, 재질은 파일, 형상 생성은 로컬.
5. 롤백 = 플래그 하나 + 폴더 하나(§5.4).

**비용·한계(정직)**
- **룩 위험**: 절차 골격 + CC0 재질이 "그 기억의 분위기"가 아니라 "시스템의 분위기"로 읽힐 수 있다(T1b 판정 질문 5). 완화 = 공간 태그를 기억이 직접 말하게 + 서사 사물 + 씬별 셸 옵션. P1에서 판정.
- two-three 비용: 번들 2개·WebGL 컨텍스트 2개(메모리 **추정** +100~200 MB, P1 측정).
- 유령(FBX 마네킹)·사물 로더는 r128 자산 → 새 무대에서는 r187 쪽 로더로 다시 로드(r184 FBX 축 변환 확인). 대화 UI는 DOM이라 그대로.
- 통로가 늘수록 BVH 갱신 비용 — P1 측정 항목.
- TRELLIS.2(PBR 생성)는 nvdiffrast 법적 판단 전까지 보류.

### 4.2 대안 B안 — "방을 미리 통째로 만들어 불러온다" (사전 생성 방 셸 중심, 현행 r128 GLB 경로 유지)

| 층 | 선택 |
|---|---|
| 렌더러 | **r128 유지**. GLTFLoader에 DRACO/meshopt 디코더 연결(glb-room 실험 그대로), 충돌은 three-mesh-bvh **0.5.23 UMD** |
| 방 | 씬마다 셸 GLB 사전 생성 — (B-1) **Infinigen Indoors** 평면 JSON(방 Polygon·문 LineString 직접 지정) → solve(CPU, WSL2) → .blend → Blender glTF → gltf-transform / (B-2) **Marble Pro**(텍스트·이미지·Chisel → HQ 메시 GLB + 충돌 메시 GLB, $35/월) |
| 배치·통로·흔적·조각·사물 | A안과 동일(절차, 브라우저) — 단 r128 안에서 |

**선택 이유**: 공학 변경이 가장 적고(새 three 인스턴스 없음), 작가가 "사진 같은 특정 장소"를 원하는 씬에 한 방에 그 밀도를 준다. Infinigen은 LLM 0·BSD·CPU라 원고가 안 나가고 16GB·Blackwell도 무관.

**왜 1순위가 아닌가**: ① Infinigen 룩은 "현실적 일반 실내"로 고정돼 "공간은 기억이 말한 것"과 어긋나기 쉽고, 방 1개 8~13분 + WSL2 experimental + GLB 변환·텍스처 베이크 손실(§3-A) ② Marble은 유료·외부 생성, HQ 셸 약 60만 삼각형은 Khronos 3MB 지침의 수십 배라 다이어트 필수, 문 위치 통제는 Chisel 수준(§3-B) ③ r128에 묶이면 KTX2·스플랫·최신 충돌 라이브러리가 전부 닫힘(§3-D) ④ 방 셸 N개 = 자산 무게 N배, 열린 땅·무 공간엔 셸이 무의미.

**B안이 이기는 조건**: P1에서 절차 방이 "시스템 분위기"로 판정되거나, 작가가 씬 대부분에 사진적 특정 장소를 요구할 때. 그때도 A안의 `space.shell` 포인터로 **씬 단위 흡수**가 되므로 전면 전환은 아니다.

### 4.3 제안 4단계와의 대응
1 생성/절차 → A안: 절차(골격) + 자산(재질·사물) + 선택 생성(형상·셸). 2 검수·최적화·저장 → `asset_check` + gltf-transform + Storage(§5). 3 실시간 구성 → 배치·골격·통로·흔적 전부 브라우저. 4 별채 비동기 → 통로에 붙는 관객 발화·흔적(동기, 가벼움) / 새 점은 RECORD 별도 기억(기존 비동기 틀) — §2 #9-4.

### 11.2 통로 폭 문제 — 생각한 것 (D21)

구술 "많이 들어갔으면 넓게, 적으면 기어서"는 오전 제안문의 "넓어진 통로가 더 빠르거나 쉬운 경로가 되어 쏠림을 강화하지 않아야"와 정면으로 부딪힌다. 둘 다 사용자 말이라 어느 쪽을 택하든 결정이지만, 결과가 다르다.

- **기어가기 = 느림 = 마찰.** 행동 연구에서 마찰은 선택 빈도를 떨어뜨린다(목표 경사·수고 회피). 샛길이 기어가는 길이면 샛길 선택이 줄고, 등뼈가 더 굵어지는 되먹임이 생긴다. 이본론이 바라는 "변이 축적"과 반대 방향(수렴). 11-05 측정의 소멸 긴장(모두 이어짐)이 아니라 그 반대 극(한 길만 남음)으로 간다.
- **반면 수고는 기능이기도 하다.** 전쟁·심금 §17(IKEA·martyrdom 효과)·생애그릇의 "수고로운 채록이 맞다"처럼, 기어서 들어간 길은 기억에 남고 뜻이 붙는다. 적게 걸은 길을 몸으로 겪게 하는 건 작품으로서 강한 신호다.
- **후보 셋**: (가) 폭·천장·조명은 굵기를 따르되 **이동 속도는 고정**(T1b 1.15 m/s) — 좁고 낮아 보여도 걸리는 시간은 같음. 신호는 남고 마찰은 최소. (나) 사용자안 그대로 — 기어가기(속도 ½) 허용, 대신 **문 앞 예고를 폭과 무관하게 동일**하게 주고, P1에서 "폭 vs 선택 비율"을 측정해 쏠림 크기를 숫자로 본 뒤 유지/철회. (다) 역전 — 굵은 길은 넓지만 닳아 바닥이 꺼져 느리고, 샛길은 좁지만 매끈 — 인위적이라 비추천.
- **내 추천 = (가)로 시작해 (나)를 실험으로.** 이유: 쏠림은 한번 생기면 데이터가 되돌리기 어렵다(굵기는 줄지 않음, D4). 시각·자세 신호(눈높이 0.9 = 기어가는 시선)는 속도를 안 건드려도 줄 수 있다.
- **어느 쪽이든 굵기의 자는 그대로**: 가닥 수(D4). "넓다/좁다"의 눈금은 절대 폭이 아니라 그 기억 안 굵기 분포의 상대 위치(정의 규율 6).
