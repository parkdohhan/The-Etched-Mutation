> 폐기 선언: 이 문서는 `Record_flow_v3-260405.md`를 **공식 폐기**한다. v3는 설계만 있고 구현된 적 없으며,

## 0. 한 줄 요약

관객이 "또다른 나"와 대화하며 기억을 서술하면 — 그 대화가 **감정 요동이 잦아드는 자리에서** 씬으로 잘리고, 관객이 실제로 뱉은 말이 **다음 사람이 만날 유령의 씨앗**이 되며, 작가가 무대를 설치하면 다른 관객이 들어와 그 유령을 만난다. 이 한 바퀴가 TEM의 "1인칭 생성형" 주장을 문자 그대로 참으로 만든다.

## 3. 다섯 원칙 (8-07 기하/위상 세션 반영 — 협상 불가)

1. **절단 기준 = 감정 소강.** 대화는 주제 전환이 아니라 **감정 요동이 잦아드는 자리**(era 경계)에서 자른다. 작가 원고의 절단 지문(촉발력 규칙)과 같은 이론의 두 번째 적용. 정본: `docs/era이론_v1_동결-260722.md`.
2. **원시 벡터 보존.** 기록 중 모든 감정 측정은 **17축 원시값 그대로** 저장한다. 뭉개기 금지. 이 기억만의 자(기억별 좌표계)는 씬 저장 **후에야** 생기므로, 소급 재측정의 재료가 남아 있어야 한다.
3. **유령 씨앗 = 최소 변환 + 원문 병행 저장.** 관객 발화를 회상 실패자 화법으로 굴리되 **어미 수준만**. 원문을 반드시 옆에 저장한다. AI가 많이 다듬으면 변이의 발생 지점이 사람→AI로 바뀌어 "참여자가 변이 지점"이라는 1인칭 생성형 주장이 무너진다.
4. **거리는 관찰이지 성적이 아니다.** record 어디에도 점수·등급·완성도 표기 금지. 작가 마감은 품질 검사가 아니라 **무대 설치**다 (§6-①).
5. **5단계 = 증거 생산.** A기록→B플레이 한 바퀴 검증은 기능 테스트가 아니라 논문(ICIDS)·도큐멘테이션(Prix Ars 2027, 1차 심사=도큐멘테이션)의 증거 촬영이다. 화면 녹화 + 데이터 보존을 검증 절차에 포함.

## 4. 새 흐름 — 관객이 겪는 순서

```
문을 연다
 → "또다른 나"가 조용히 곁에 선다 (플레이 유령 대화와 같은 화면 결)
 → 관객이 말한다. "또다른 나"는 해석하지 않고 되묻는다 (감각 질문, 침묵 허용)
 → 매 턴: 안전 필터 통과 → 감정 17축 원시 측정 (화면에는 아무 수치도 안 보임)
 → 관객이 "없어" / 침묵 → 봉인어 한 마디
 → [뒤에서] 대화가 감정 소강 지점에서 씬들로 잘림 → 씬·감정·유령 씨앗 저장
 → 관객 눈앞에서 자기 기억의 지형이 솟는다 (이본지층 실지형 — 옛 매장 애니메이션 아님)
 → 들어가 볼 수 있다 (기록 = 첫 플레이, 정렬 1.0)
```

## 5. 단계별 사양

### 5-1. 말하는 자리 교체

- 옛 대화 화면 은퇴. 플레이 유령 대화 엔진의 **화면 껍데기·타이핑 연출·안전 배선**을 가져오되, **씬 없는 진입 모드**(record mode)를 새로 뚫는다.
- 씬 의존 중 record에서 **끄는 것**: 정렬도 계산(기록=자기 정렬 1.0 정의), 유령 이름 공개, 이어받기 지문(절단은 봉인 후에 일어남), 오염 표출.
- 씬 의존 중 **대체하는 것**: 유령 페르소나 → "또다른 나" 페르소나(해석·진단·조언 금지, 반향과 감각 질문만 — v3의 프롬프트 원칙 계승).
- 안전: `js/safety.js`로 단일화. 옛 대화 화면에 복사돼 있던 시제 감지·에스컬레이션을 이관. 위기 응답은 시스템 경고가 아니라 "또다른 나"의 육성으로(기존 원칙).

### 5-2. 대화 → 씬 절단

- 매 턴 감정 17축 측정값이 이루는 궤적에서 **요동 소강 지점**을 경계로 삼는다. 도구는 절단 지문 생성기(`test/tools/stem_cuts_emit_asset.mjs`의 촉발력 규칙)를 대화 입력용으로 변형.
- 잘린 조각(씬)마다: 본문(관객 발화 재구성 최소화), original_emotion(17축 원시), 사물·모티프 태그.
- **⚠️ 14축 함정**: `claude-scene emotion_analysis`는 anchorEmotions를 안 넘기면 **기본 14축**으로 잰다(정본 17축과 불일치 — relief/peace/love/gratitude가 섞이고 disgust/surprise 등이 빠짐). record 호출은 **반드시 정본 17축 목록을 명시적으로 전달**한다. 옛 record를 죽인 6축↔17축 불일치의 재발 방지 조항.
- 절단 결과가 3씬 미만이면 저장하지 않고 대화를 연장한다 (§6-③).

### 5-3. 저장 + 유령 씨앗

- memories/scenes 저장은 기존 골격 유지 (status='Fetus' = 씨앗 상태. **새 테이블 0, 새 컬럼 0**).
- 관객 발화 → 유령 씨앗: `ghost_variants`에 저장. **원문 그대로 + 굴린 판(어미만 회상 실패자 화법) 두 벌.**
  - ⚠️ 현행 쓰기 문은 반대로 잠겨 있다: `insert-ghost-variant`는 플레이어 기여를 is_seed=false로 강제하고, 씨앗(is_seed=true)은 admin 전용. **기록자는 그 기억의 작가**이므로 기록자 발화는 씨앗이 맞다 — 씬 생성 서버 함수가 service role로 직접 심거나, insert-ghost-variant에 record 경로를 추가 (둘 중 택일은 구현 시).
- 저장 직후 기존 후단 그대로: 대표 사물 앵커 → 3D 모델 주문 → 잔상 수확 → 첫 플레이(정렬 1.0) 자동 생성.
- 진입점 3곳(index.html / play-test.html / demoFlow.js) 전수 배선 + 캐시버스터 갱신 (재발 방지 규칙).

### 5-4. 묻는 의례 재구축

- 옛 매장 애니메이션 폐기. 봉인어 각인(음각) 순간 → **이본지층 실지형이 관객 눈앞에서 솟는** 연출로 교체. 이미 있는 지형 엔진(`tem_variant_strata`) 위에 record 데이터를 태우는 것이지 새 지형 코드가 아니다.
- 솟은 지형에 바로 들어가 볼 수 있게 (record → 첫 플레이의 시각적 연결).

### 5-5. 한 바퀴 검증 = 증거 촬영

- 절차: A가 기록·봉인 → (작가 무대 설치) → B가 플레이 → B가 만난 유령이 **A의 원문 계보로** 말하는지 확인.
- 실제 경로로만 밟는다(콘솔 세팅·심어둔 전제 금지 — 260717 교훈). 화면 녹화 + run 데이터 보존 = 논문·출품 증거 자료.
- 통과 기준: B의 유령 대사가 A 발화 원문에서 계보 추적 가능할 것(ghost_variants 계보 무결성).

## 7. 위험·미지수

1. **씬 없는 진입 모드의 작업량** — 대화 엔진이 씬 본문·원본 감정·대사 설정을 곳곳에서 읽는다(코드 확인 260807). 정렬도·이어받기·오염을 끄면 의존 절반이 사라지지만, 남는 절반(프롬프트 조립·overlay 생명주기)의 분리 난이도가 이 계획의 유일한 큰 미지수. **1단계 착수 전 반나절 스파이크로 확인 후 진행.**
2. **14축 기본값** — §5-2 조항 미준수 시 옛 record 사인(축 불일치) 재발. 리뷰 체크리스트에 포함.
3. **AI 재구성의 유혹** — 씬 본문을 "읽기 좋게" 다듬을수록 §3-3이 무너진다. 본문 재구성도 최소 원칙(발화 이어붙이기 + 접속 최소).

## 8. 규모·롤백·대안

- **규모**: 화면 1 신규(엔진 개조), 서버 함수 1 신규(절단+저장)·1 은퇴, 흐름 파일 수술 1, 지형 연출 배선 1. 새 테이블/컬럼 0.
- **롤백**: 낮음. 옛 파일 이름 변경 보존 → 복귀 한 줄. 데이터 구조 무변경이라 기존 기억 무사.
- **대안**: ① 옛 흐름 유지 + 17축만 교정 — 싸지만 유령·이어받기 영영 부재, 1인칭 생성형 한 바퀴 불가. ② 완전 신규 대화 화면 — 플레이와 다시 갈라져 통합 비용 이중 지불. 채택안이 유일하게 "record = 첫 play"를 화면 수준에서 실현.

## 9. 착수 순서

```
[스파이크] 대화 엔진 씬 없는 진입 — 반나절 확인   ← 여기부터
→ 1단계 말하는 자리 → 2단계 절단 → 3단계 저장+씨앗 → 4단계 의례 → 5단계 증거 촬영
```

각 단계 완료 시 이 문서의 해당 절에 완료 일자·산출물 경로를 병기한다.
