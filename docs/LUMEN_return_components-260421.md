# LUMEN 귀환 8 컴포넌트 최소 작동 정의

**용도**: Sprint 3 귀환 작업(작업 2-A/B/C/D, 총 3.5 세션)의 **객관적 작동 기준**. 5-01 통합일에 재검토, 5-02 Sprint 3 착수 전 최종 확정, 5-06 통합일에 항목별 Y/N 체크.

**SCOPE 참조**: [docs/LUMEN_DEMO_SCOPE-260424.md §4 작업 2](LUMEN_DEMO_SCOPE-260424.md), §8.5.

**원칙**: 각 컴포넌트는 "최소 작동(MVP)" 기준만 기록. 정교화·튜닝은 이 기준 통과 후 잔여 시간에 할당. **기준 미충족 시 해당 컴포넌트는 시나리오 A로 포기 후보**.

---

## 1. 궤적 기록 (작업 2-A 전반)

- **무엇**: 관객의 FP 공간 이동을 시간별로 기록.
- **트리거**: 지형 진입 시점부터 세션 종료까지 계속.
- **입력**: 매 tick(150ms) 플레이어 pose
- **저장**: `plays.spatial_trajectory` JSONB array — `[{t, x, z, h, yaw, cont}, ...]`
- **최소 작동**:
  - 세션 종료 후 DB 조회 시 `spatial_trajectory` length > 10
  - t 단조 증가
  - x, z가 실제 이동 경로와 일치 (admin에서 시각 재생 확인)
- **검증**: Supabase SQL `SELECT jsonb_array_length(spatial_trajectory) FROM plays ORDER BY created_at DESC LIMIT 1;`

## 2. rewind 재생 (작업 2-A 후반)

- **무엇**: void 도달 후 카메라가 궤적을 역순으로 재생.
- **트리거**: void 진입 이벤트 (`onEnterVoid` from adapter).
- **입력**: 현재 세션의 `spatial_trajectory`.
- **출력**: 관객이 WASD 입력 없이 카메라만 진입구 방향으로 자동 이동.
- **최소 작동**:
  - rewind 시작 → void 방향에서 진입구 방향으로 카메라 이동
  - 진입 경로의 절반 이상을 역추적
  - 관객 입력 무시 (WASD 잠금)
- **검증**: 본인 플레이 + rewind 관찰. 카메라가 역방향 움직이면 OK.

## 3. 색감 shift (작업 2-B 첫 레버)

- **무엇**: 귀환 중 화면 색조 변화.
- **트리거**: rewind 시작과 동시.
- **출력**: 색온도·채도 한 방향으로 이동. 예: 채도 -20%, hue +10 degrees warm → cool.
- **최소 작동**:
  - rewind 시 진입 때와 **확연히 다른** 색감
  - 귀환 완료 후 원복 (또는 귀환 완료 = fade to black)
- **검증**: 스크린샷 진입 vs 귀환 비교. 동일 지점인데 색이 다르면 OK.

## 4. 속도 ×1.5 (작업 2-B 둘째 레버)

- **무엇**: rewind 재생 속도 = 원본 궤적 속도 × 1.5.
- **트리거**: rewind 시작.
- **구현**: trajectory 재생 시 각 frame dt를 1.5로 나눠 샘플링.
- **최소 작동**:
  - rewind 총 시간 ≈ 진입 시간 / 1.5
  - 체감적으로 "급하게 돌아온다"
- **검증**: 진입 시간 대비 rewind 시간 스톱워치 측정 × 3세션.

## 5. 유령 자세 변화 (작업 2-B 셋째 레버)

- **무엇**: rewind 동안 이미 조우한 유령의 자세·opacity 변화.
- **트리거**: rewind 시작과 동시.
- **대상**: 시선 교차로 만난 유령만 (작업 11 기준).
- **최소 작동**:
  - 진입 때 standing → rewind 때 turned away or dimmer opacity
  - 최소 1개 유령에서 관찰 가능
- **검증**: 진입 시 유령 스크린샷 vs rewind 시 유령 스크린샷. 육안 구분 가능해야.

## 6. 유령 말투 미세 변화 (작업 2-C 첫 레버)

- **무엇**: 조우한 유령의 whisper/monologue 톤이 rewind 때 다른 버전.
- **트리거**: rewind 중 해당 유령 근접.
- **구현**: `monologue_templates`의 rewind 버전 추가. Ghost type별 1~2개씩.
- **최소 작동**:
  - 진입 시 "…그게 무슨 냄새였더라." → rewind 시 "…그건 그냥 그런 거였어." 식
  - 최소 2 유령 타입에 적용 (Core, Contaminated)
- **검증**: 텍스트 로그에서 한 세션 내 동일 유령의 2가지 monologue 출력 확인.

## 7. 입력 파편 재셔플 (작업 2-C 둘째 레버)

- **무엇**: 오프닝에서 관객이 입력한 텍스트가 rewind 중 조각내어 재등장.
- **트리거**: rewind 중 특정 포인트 (예: 유령 근처, 전환점).
- **저장**: 관객 오프닝 입력을 세션에 캐시 (plays에 저장된 baseline도 활용 가능).
- **출력**: 텍스트 fragment가 floating으로 잠깐 뜨고 사라짐.
- **최소 작동**:
  - 관객이 입력한 문장에서 1~3 단어 fragment가 rewind 중 1~2회 등장
  - 페이드 인/아웃 자연스러움 (타이포그래피 안정)
- **검증**: 녹화 영상에서 fragment 등장 프레임 확인.

## 8. 귀환 전용 사건 (작업 2-D)

- **무엇**: rewind 경로상 2~3개 사건. 진입 때는 없던 연출.
- **예시**:
  - 특정 좌표 지점 진입 시 fragment 공중 등장 (7번과 결합)
  - 천장에서 echo word 비처럼 떨어짐
  - 이미 조우한 유령 하나가 길을 막다가 사라짐
- **최소 작동**:
  - 2개 이상의 사건이 rewind 중 발생
  - 각 사건은 rewind 에만 발생 (진입 시에는 없음)
- **검증**: 한 메모리를 진입-only vs 진입+rewind 두 번 플레이 → rewind에만 있는 사건 2개 이상 확인.

## 시나리오 A 포기 우선순위

SCOPE §8.6: "5-09까지 3-A/B/C 중 하나라도 미완이면 2-D를 즉시 V2로 포기."

이에 더해 Sprint 3 중 예산 초과 시 **이 순서로 포기**:

1. **#8 귀환 전용 사건** — 가장 비싸고 생략해도 귀환 구조 붕괴 안 함
2. **#7 입력 파편 재셔플** — 텍스트 관리 복잡. 단순화 가능 (일반 fragment로 대체)
3. **#6 유령 말투 미세 변화** — 2 타입으로 시작, 확장 포기
4. **#5 유령 자세 변화** — opacity 변경만으로도 단순 충족 가능

**포기 불가 (귀환 구조 최소 요소)**:
- #1 궤적 기록
- #2 rewind 재생
- #3 색감 shift
- #4 속도 ×1.5

위 4개만 있어도 "관객이 돌아갈 때 공간이 다르게 보인다"는 작품 명제는 구현됨.
