# 글 방 — 가짜 관객 걸음꾼과 변이 굽기 (2026-11-20)

> 발단(작가): "팬티만 입은 내여자 데이터 분석해서 사람들 어떻게 다니는지 파악해놓고, 권역 전문 줄 테니 알아서 나눠서 장면별로 확실히 끝나게 하고, 그다음 사람들 시뮬레이션 넣어서 변이 일어나게."
> 원고 문장은 이 문서에 없다(공개 저장소 규칙). 장면 본문·이전 판 보관·미리 써 둔 관객 말은 `Tem - gwonyeok/backup/`(공개 제외).

## 0. 지금 상태 한 줄

권역(GWON-001)은 새 원고 기준 19장면이다. 같은 날 밤 계정을 충전한 뒤 **가짜 걸음 30번을 장부에 넣었고, 15장면에 2겹·3겹 글을 구웠고, 기억의 깊이는 30이 되었다**(§8). 권역을 지금 걸으면 첫 방문부터 3겹 글이 나온다.

## 1. 팬티녀(UNDW-001) 걸음 — 옛 지형 무대 37걸음 216줄 (2026-07-30 … 09-30)

| 본 것 | 값 |
|---|---|
| 한 걸음에 지난 장면 수 가운데값 | 5 (전체 13) |
| 한 장면만 보고 끝난 걸음 | 37 중 8 |
| 13장면을 다 본 걸음 | 3 |
| 원고 순서의 바로 다음 장면으로 간 이동 | 179 중 20 |
| 원고 순서를 거슬러 간 이동 | 179 중 72 |
| 같은 걸음 안 재방문 | 0 (옛 무대에는 돌아가는 길이 없었다) |

- 굵은 길: 2 → 6 → 5 → 9 → 13. 덜 닿는 장면: 8·12(37 중 7), 1·7(37 중 10). 정렬 평균 최저 = 침묵 장면 10(0.25), 최고 = 7(0.64).
- 한계: 엔진이 열어 준 장면 안에서 고른 결과다(사람의 뜻과 접근 기하가 섞임). 장부는 사람을 구분하지 않는다(걸음 단위).
- 쓰임: 걸음꾼이 떠날 확률표(§3 LEAVE)의 재료.

## 2. 권역 새 원고 반영 (19장면)

- 구성: 척추 5(외출·갈림길·노란 띠·계산대·엎드림) + 갈비뼈 14(마당·윗마을 길·공사장·은수의 열쇠·현관·싱크대·콘센트·뒤꿈치·[침묵]·장부의 이름·거짓말·청라·사진과 칼[잠금]·빈방). 본문 63~106자, 전부 원고 문장(앞머리 이음말만 덜어 냄). 오염 1단(text_stage_1)은 9-15 방식대로 내가 쓴 초안 — **작가 감수 대상**.
- 뺀 것: 옛 원고에만 있던 한우·호랭이 대면·정류장·발전소 박자. 그 세 장면의 줄은 지우지 않고 새 장면(마당·윗마을 길·은수의 열쇠) 자리로 고쳐 썼다(저장소가 지우기 문장을 거절해서). 그래서 옛 무대 기록 3줄(9-15 1줄, 시험 2줄)이 다른 내용의 장면에 붙어 있다.
- 감정값·잔향 단어·사물 태그·소리 문구는 새로 붙였다(감수 대상). 소리 7개 새로 생성(새 장면 6 + 끝 장면). 지문(첫 방문에 보이는 끊긴 글) 18개 다시 도출 → `js/shared/tem_stem_cuts.js`.
- 장면이 확실히 끝나게: `?way=1` 에서 장면의 마지막 토막은 원고의 마침표 그대로 끝난다(이전: 마지막 문장도 "…"로 흐림). 결정 문서 §8 W13.
- 남은 옛 흔적: 기억의 감각 앵커("탁. 탁. 탁."), 옛 원고에서 온 떠도는 말 3줄(그 애·보조개·턱선), 사물 모형 목록의 한우.
- 되돌리기: `Tem - gwonyeok/backup/GWON-001_before_v2-261120.json`(기억·장면 15·떠도는 말 27 전체), `…_plays_before_v2-261120.json`.

## 3. 걸음꾼 — `tools/room-sim/walk.mjs`

글 방이 하는 일을 화면 없이 그대로 한다: 방의 글을 읽고 → 한 줄 잇고 → 무대와 같은 감정 측정(claude-scene) → **같은 엔진**(`js/roomplay/engine.js`)이 한 걸음 → 문 하나 → 다음 방. 장부 줄 모양도 무대와 같고 `persona_id = 'room-sim'` 꼬리표가 붙는다.

- 관객 = `tools/persona-sim/data` 의 인물 30명. 말은 두 길: ① API 로 그때그때 쓰기 ② **미리 써 둔 말**(`--lines`). 11-20 에는 API 잔액이 없어 ②로 준비했다 — 인물 30 × 장면 19, 첫 방문 말과 다시 왔을 때 말(1,110줄, 이 세션의 보조 작업자가 씀). 첫 방문에 보이는 글은 장면마다 정해져 있으므로 미리 써도 같은 질문에 대한 답이다.
- 자유 값(정의 아님): LEAVE = k번째 방 뒤 떠날 확률, §1의 실측 멈춤 비율 / REVISIT 0.1 = 옛 문으로 돌아갈 확률(자료 없음, 가정) / ABSORB 0.25 = 그 말이 떠도는 말 풀에 들어갈 비율(무대는 전부 넣는다).
- 사람이 아니다: 심심해서 창을 닫지 않고, 떠남은 표에서 뽑는다. "어느 장면이 심심한가"는 못 잰다. 잴 수 있는 것은 "감정 자리가 외져 문이 잘 안 나는 장면". 증거 등급은 [예비]까지.
- 측정이 빈 벡터를 돌려주면 멈춘다(대역 값으로 채우지 않는다).

## 4. 변이 굽기 — `tools/room-sim/bake_stage.mjs`

글 방은 기억이 깊이 걸어질수록 장면 글의 다음 겹을 읽는다(깊이 5 이상 2겹, 15 이상 3겹, 다시 오면 한 겹 더). 그런데 글 방 자신은 그 겹도 깊이도 쓰지 않았다. 이 도구가 장부에서 만든다. 걸음이 쌓이면 다시 돌린다.

- **정의** — 정의역 = 한 기억의 글 방 줄(시험 걸음 제외).
  - 깊이 = 그 줄들의 서로 다른 걸음 수. 0 = 글 방에서 아무도 안 걸음.
  - 2겹(해석 병치) = 1겹 글의 마지막 문장 앞에 관객의 말 두 줄을 끼운 것: 그 장면에 가장 맞았던 말과 가장 어긋났던 말. 장면의 첫 문장과 마지막 문장은 그대로다.
  - 3겹(과완결) = 2겹을 오염 글 함수(contaminate-text)의 과완결 방식에 한 번 통과시킨 것.
- **측정** — 맞음/어긋남 = 장부에 이미 적힌 정렬 값의 최고/최저(새 판정·모델 호출 없음). 서로 다른 걸음의 말. 줄이 하나뿐이면 한 줄, 없으면 2겹 없음.
- 기억의 오염 상태는 무대의 정식 길(record-contamination)로 쓴다. 장면 글은 SQL 로 내놓는다(익명 열쇠는 장면을 못 고침).
- 되돌리기: `update scenes set text_stage_2 = null, text_stage_3 = null, meta = meta - 'stage_bake' where memory_id = …`.
- 주의: 7-9 결정("AI 인물의 걸음을 앞사람의 흔적으로 내보이지 않는다")을 권역에 한해 뒤집는다(작가 11-20). 권역은 비공개 상태다. 공개 전에 가짜 줄을 뺄지 정해야 한다.

## 5. 막힌 것 — 감정 측정이 죽어 있다

2026-11-20 저녁, Anthropic API 가 "잔액 부족"으로 모든 호출을 거절한다. 로컬 열쇠(`tools/persona-sim/.env`)와 서버 함수(claude-scene)가 같은 계정이다. 이날 지문 도출 102회와 시험 호출 십여 회가 남은 잔액을 썼다.

- **무대에도 영향이 있다.** claude-scene 은 모델 호출이 실패하면 오류 대신 "모든 축 0, 빈 말"을 정상 응답처럼 돌려준다. 글 방은 그것을 측정값으로 받아 모든 관객을 침묵 쪽 문으로 보내고 빈 감정을 장부에 적고 있었다. → `js/roomplay/data.js` 가 전부 0인 응답을 "측정 실패"로 다루게 고쳤다(화면에 "감정 측정에 실패했습니다"가 뜨고 직전 결로 이어진다). 함수 자체(오류를 200으로 감싸는 것)는 그대로다. 옛 지형 무대(play-test)는 손대지 않았다.

## 6. 충전한 뒤 할 일 (두 줄)

```bash
L="Tem - gwonyeok/backup/lines_1.json,Tem - gwonyeok/backup/lines_2.json,Tem - gwonyeok/backup/lines_3.json"
node tools/room-sim/walk.mjs --memory GWON-001 --runs 30 --lines "$L" --out "Tem - gwonyeok/backup/sim_runs.json"
node tools/room-sim/bake_stage.mjs --memory GWON-001 --out "Tem - gwonyeok/backup/bake.sql"   # 나온 SQL 을 저장소에서 실행
```

가짜 걸음 빼기: `plays`(persona_id = 'room-sim'), `run_journals`(run_traces->>'mode' = 'sim'), `ghost_variants`(extractor_version 에 'room-sim').

## 8. 결과 — 가짜 걸음 30번 (2026-11-20 밤) [예비]

| 본 것 | 값 |
|---|---|
| 걸음 / 장부 줄 | 30 / 132 (같은 말을 세 번 넘게 되풀이한 25줄은 시험 줄로 돌려 뺌) |
| 한 걸음에 지난 서로 다른 장면 수 가운데값 | 4 (전체 19) |
| 한 장면만 보고 끝난 걸음 | 30 중 7 (떠날 확률표 그대로) |
| 엔진이 읽은 결 | 따라감 63 · 옮겨감 33 · 맴돎 49 · 다리 11 · 거스름 1 |

- **굵은 길 하나로 쏠린다**: 외출(1) → 은수의 열쇠(9) → 마당(6) → 빈방(19). 1→9 가 30 중 17, 9→6 이 13, 6→19 가 8.
- **한 번도 안 닿은 장면**: 엎드림(5, 끝 장면) · 거짓말(16) · 사진과 칼(18, 잠금). **한 번만 닿은 장면**: 갈림길(2) · 공사장(8) · 현관(10) · 침묵(14).
- 읽기: 첫 장면의 감정(무감각·고립)에서 가까운 장면들이 한 무리를 이루고, 문은 늘 가장 가까운 장면 하나로만 나므로 그 무리 안에서 돈다. 척추(지금 걷는 이야기)의 뒤쪽과 죄책감 쪽 장면은 감정 자리가 멀다. **끝 장면에 닿는 걸음이 0**이라는 것이 가장 큰 문제다.
- 맴돎: 다시 온 방에서 같은 결의 말을 하면 엔진이 "여기 머묾"으로 읽어 같은 방 문을 낸다. 준비한 말이 장면당 두 줄뿐이라 세 번째부터는 같은 말이 되풀이되어 한 방에 10번 넘게 갇힌 걸음이 셋 나왔다 — 도구의 한계(사람은 같은 말을 열 번 치지 않는다).
- 가장 맞는 말로 뽑힌 것 중에 "그래서 그냥 나갔다"(0.66) 같은 대충 쓴 말이 있다. 정렬 숫자가 성의를 가리지 못한다는 기존 문제(§8.7-1)가 2겹 글에 그대로 들어간다.
- 구운 것: 걸음이 닿은 15장면의 2겹(관객 말 한두 줄을 마지막 문장 앞에 끼움)과 3겹(굳힘). 3겹은 사실을 바꾼다 — 예: 첫 장면의 끝 "잡혔는지 아닌지 알 길이 없다"가 "잡히지 않았다는 것을 지금도 알고 있다"로. 과완결의 뜻 그대로이나 **작가 감수 대상**.
- 떠도는 말 풀에 가짜 말 일부가 들어갔다(꼬리표 'room-sim').
