# 알파 1차 테스터 피드백 수리 — 260802

> 첫 알파 테스터(260802 오후) 참관 중 사용자가 지목한 5건. 전부 같은 날 수리.

## 1. 길게 누르기 호버 범위가 너무 작음
- 자리: play-test.html `_aimAssistPin` (신규) + `_getAimedPin`
- 원인: 조준 = 정밀 레이캐스트 단독 — 유령 몸을 픽셀 단위로 빗나가면 미조준.
- 수리: 레이캐스트 실패 시 **시선 원뿔 관용 판정** — 핀 중심 반경 ~1.4유닛 상당(최소 6.5도), 30유닛 이내, 가장 정면인 핀 1개. 사물이 정면을 막으면 정밀 히트가 먼저 잡으므로(관용 판정 미도달) 열람/대화 오발 불변.

## 2. 연결사 선택을 직관적으로 이해 못 함
- 자리: js/ui/lumen_dialog_phase1.js `_renderContInput`
- 수리 3종: ① 입력줄 위 안내 한 줄("문장이 끊겼습니다 — 연결사를 고르고, 뒤를 이어서 써 주세요"), ② 고르기 전 선택 상자 밑줄 강조(0.75)→고르면 평상(0.32), ③ 연결사 없이 제출 시 안내가 붉게 "연결사를 먼저 골라 주세요."로 1.4초 (기존: 말 없는 붉은 테두리 0.9초뿐).

## 3. 나가기/스킵하기 버튼 삭제 (사용자 결정)
- 자리: js/ui/lumen_dialog_phase1.js — 대화창 우상단 `.ldp-skip` 버튼(대사 중 'SKIP ▸' / 입력 차례 '나가기 ▸') 생성 블록 삭제.
- 대사 넘김은 오버레이 클릭(RPG식 수동 넘김) 그대로. 대화는 턴 소진 시 자연 종료.
- **트레이드오프**: 관객이 대화를 중간에 뜨는 길이 없어짐 — 이제 이어쓰기 제출이 유일한 진행. `.ldp-skip` 참조 자리들은 전부 null 가드라 무해. `_sub.skipMode/_sub.exit` 배선은 보존(롤백 = 버튼 블록 복원).
- ESC 메뉴 안의 '나가기'(세션 종료)는 **남김** — 설정 메뉴 안이라 상영 화면에 상시 노출 아님. 그것도 지울지는 작가 결정 대기.

## 4. 안개가 뚫려서 사용자가 들어가짐 (긴급)
- 자리: js/ui/lumen_spatial_fog.js `constrainMove`
- 관통 경로(2단): ① 벽면 슬라이드 허용선이 `BLOCK*0.75`(0.1125) — 벽 밑 반 발짝(걷힘 0.1125~0.15)에 설 수 있었고 → ② 거기서 **갇힘 면제(260728 A)가 전 방향 자유 이동**을 돌려줘 그 뒤로 안개 전체 무사통과.
- 수리: ① 슬라이드도 `BLOCK`(0.15) 이상인 자리만 착지, ② 갇힘 면제는 "같거나 맑아지는 걸음"만 허용(더 깊은 안개로 떨어지는 걸음은 정지). 균일 안개 탈출(면제의 원래 목적)은 유지.
- 실측(playwright, 대표 기억, DB 무접촉): 큰 걸음 5방향 전부 차단 + 벽면 지그재그 잔걸음 800보 시뮬에서 걷힘 최저 0.150 — 경계선에서 정확히 멈춤.
- 부작동 확인: 로드 직후 seed 전 1틱은 갇힘 면제 경고가 1회 뜨지만(기존과 동일 타이밍) 이동 잠김 없음.

## 6. 문(퇴장) 5회 관문 (추가 지시, 같은 날)
- 자리: play-test.html FP 어댑터 — `DOOR_MIN_VISITS`/`_doorGateOk`/`_doorBlockLine` (상수 자리) + 문 근접 속삭임 + 문 길게누르기.
- 규칙: **인터랙션 5회 미만이면 문이 안 열린다.** 인터랙션 = 방문한 씬(visitOrder 고유 수) + 열람한 사물(열람 장부 260731 고유 단어 수, 사용자 지시로 포함). 시스템 경고 대신 독백 두 개가 번갈아 뜸 — "… 더 둘러봐야 할 것 같아." / "아직… 충분히 보지 못했어." (en 병기). "길게 눌러 나가기" 안내도 숨김. 길게 눌러도 흔들림·타이머 없이 독백만.
- 씬이 5개 미만인 기억은 `min(5, 씬 수)` — 전부 보면 열림 (막다른 방지).
- 문 앞에 서 있는 동안 5회를 채우면 속삭임이 "......나가자."로 즉시 갱신.
- 관문 실패 + 유령 조준 중이면 씬 진입은 평소대로 (문이 씬 진입을 막지 않음).
- 모바일 2D 경로는 문이 없음 — sealBtn 자체 관문(coreVisitCount>=3)이 기존대로 담당.
