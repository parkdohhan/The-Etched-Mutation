# 로그인 — 아이디로 가입·들어가기, 기억 만들기는 로그인 필요 (2026-11-24)

> 사용자 결정(같은 날): "profile 에서 회원가입 만들어두자. 구글 로그인은 아마 안 될 거야, SNS 는 나중에. 로그인해야 기억 만들 수 있게. 아이디랑 이메일은 따로 받아서 아이디는 @gmail.com 안 붙여도 되게. 비밀번호는 특수문자·대문자 빼고 영어랑 숫자 7개만."

## 1. 무엇이 바뀌었나

| 자리 | 전 | 후 |
|---|---|---|
| 들어가기 창 (`index.html #loginModal`) | 이메일 + 비밀번호, 구글·페이스북 단추 | **아이디 또는 이메일** 한 칸 + 비밀번호. SNS 단추 숨김(`hidden style="display:none"`, 지우지 않음) |
| 가입 창 (`#signupModal`) | 이름·이메일·비밀번호(6자 이상)·확인 | **아이디**(영어·숫자·_ 3~20자, 대소문자 구별 없이 하나뿐) · **이메일** · **비밀번호**(영어·숫자만, 7자 이상) · 확인. 대문자·기호 요구 없음 |
| 창 글귀 | 영어 고정 | 한국어/영어 (`js/lib/i18n.js` `auth.title.*` `auth.btn.*` `auth.ph.*` `auth.msg.*`) |
| 기억 만들기 (`record-space.html`) | 로그인 없이 올릴 수 있음 | 로그인 안 했으면 **관문**: "기억을 만들려면 먼저 들어와야 해. 아이디 하나면 돼." + `들어가기 · 가입하기` → 첫 화면 들어가기 창 → 들어가면 **기억 만들기로 돌아옴**. 연습(`?test=1`)은 관문 없음(저장 안 함) |
| 올리기 서버 (`record-space-seal`) | 로그인 없어도 받음(`by: 'anon'`) | 로그인 없으면 **401 login required** — 돈 드는 호출(태그 뽑기) 전에 거절 |
| 첫 화면 `?action=login` | 들어가기 창만 열림 | `&next=record-space.html…` 를 받아 들어간 뒤 그리로 보냄(그 모양만 받음) |

들어가기: 칸에 `@` 가 있으면 이메일로 바로, 없으면 아이디 → 데이터베이스 함수 `login_email(아이디, 비밀번호)` 가 **비밀번호가 맞을 때만** 그 계정의 이메일을 돌려주고, 브라우저가 그 이메일로 들어간다. 모르는 아이디도 같은 비용이 들게 가짜 해시를 한 번 돌린다(시간을 재 보지는 않았다). 한 아이디에 15분 안 10번 틀리면 "너무 여러 번 틀렸어".

## 2. 서버 (2026-11-24 적용 — `supabase/migrations/`)

## 4. 못 한 것 · 남은 것

- **SNS 로그인**: 단추만 숨김. 서버(Supabase)에는 구글이 켜져 있다. 다시 열 때 되돌아오는 주소 설정부터 볼 것.
- **비밀번호 잊음**: 없다. 이메일을 따로 받아 두었으니 나중에 붙일 수 있다(인증 이메일 = 받은 이메일).
- **이메일 확인 메일**: 서버 설정이 "확인 없이 바로 가입"이다. 켜면 가입 뒤 "들어가기를 해 줘"로 넘어가게 해 두었다.
- **AI·소리 함수**(`claude-scene` `dialog-turn-record` `generate-scene-thing` `generate-scene-sound`)는 관객 무대에서도 쓰여 로그인을 걸지 않았다. 기억 만들기 화면을 거치지 않고 직접 부르면 여전히 돈이 든다 — 횟수 제한은 따로.
- 옛 RECORD(숨김)의 로그인 없는 저장은 이제 실패한다. 다시 메뉴에 올릴 일이 생기면 로그인 관문을 같이 달 것.

## 8. 기억 만들기 — 나가기 · 임시저장 · 오프닝 비침 (2026-11-24 밤)

**작가 지시:** "레코드 들어갈 때 오프닝 실 화면 잠깐씩 비추는 거랑, 기억 만들기 탭에 나가기 버튼이 없어. 그리고 임시저장 하시겠습니까? 물어봐 주고 실제로 임시저장 기능도 만들어 줘."

- **오프닝 비침**: 로그인 안 한 채 레코드 → 관문 "들어가기 · 가입하기" → 첫 화면(`?action=login&next=…`)이 오프닝(실 화면) 위에 들어가기 창을 띄우느라 실이 잠깐 보였다. 그 길에서는 오프닝을 건너뛰고 메뉴 위에 창을 띄운다(`sessionStorage tem_menu_after_ending` — 우주 무대 끝에서 메뉴로 갈 때 쓰는 표시와 같은 것, 한 번 읽고 지움). 관문 단추와 첫 화면의 `next` 받기 두 군데에서 세운다.
- **나가기**: 화면 왼쪽 위 "나가기". 쓴 게 없으면 곧바로, 있으면 "쓰던 걸 임시저장할까?" — 임시저장하고 나가기 / 그냥 나가기 / 계속 쓰기. 나가면 오프닝 없이 메인 메뉴.
- **임시저장**: 서버 표 `record_drafts`(계정마다 한 줄, 본인만 읽기·쓰기·지우기, 로그인 안 하면 읽기·쓰기 모두 401)와 이 브라우저(localStorage `tem_record_draft:<계정>`) 양쪽에. 들어올 때 둘 중 더 최근 것을 내민다. 서버에 닿지 않으면 "이 브라우저에만 임시저장했어". 연습 모드는 브라우저에만. 남기는 것: 제목·한 줄 설명·장면 카드 전부(네 칸, 감정 막대와 정한 방법, 대화 줄과 측정값 — 대화 창은 다시 열지 않음, 조형물 조리법, 소리 문장과 만든 소리 주소). 올리기 아래 "임시저장" 단추로 나가지 않고도 저장. 다시 들어오면 "임시저장한 기억이 있어 — 「제목」. ○○에 저장했어. 이어서 쓸까?" — 이어서 쓰기 / 새로 쓰기(새로 쓰면 그 임시저장은 지움). 올리기가 성공하면 지움. "그냥 나가기"는 이번에 쓴 것만 버리고 전에 저장한 것은 둔다.
- 한계: 창을 그냥 닫으면 묻지 않는다(브라우저 기본 "나가시겠습니까?"만). 한 계정에 임시저장은 하나 — 새로 저장하면 앞의 것을 덮는다.
- 서버 표: `supabase/migrations/20261124000200_record_drafts.sql`(적용됨). 시험(실제 계정 둘): 내 줄 저장·덮어쓰기·읽기 됨 / 남의 계정은 줄 0개로 보임 / 남의 줄 쓰기 거절(42501) / 남의 줄 지우기 0줄 / 내 줄 지우기 됨.
- 문구는 이 화면의 반말에 맞췄다("임시저장 하시겠습니까?" → "쓰던 걸 임시저장할까?").
