# 오프닝 테스터 모드 — 되돌리기 문서 (2026-08-02)

> 사용자 결정 2026-08-02. 데모 테스터에게 finder 인터뷰(닉네임 + 질문 3턴)를 묻는 것은
> 의미가 없으므로, 테스터에게만 인터뷰를 건너뛰고 대표 기억으로 직행시킨다.
> **풀버전 흐름은 한 줄도 지우지 않았다.** 본 문서는 (a) 스위치 사용법 (b) 원본 흐름 보존본
> (c) 테스터 모드를 통째로 걷어내는 절차를 담는다.

---

## 1. 스위치

| 하고 싶은 것 | 방법 |
|---|---|
| 테스터 모드 켜기 | 주소 끝에 `?tester=1` 붙여서 한 번 접속 |
| 끄기 (풀버전으로 복귀) | 주소 끝에 `?tester=0` 붙여서 한 번 접속 |
| 지금 켜져 있는지 확인 | 콘솔에 `localStorage.getItem('tem_tester_mode')` — `"1"` 이면 켜짐 |

한 번 켜면 **그 브라우저에 저장**되어 이후에는 주소를 붙이지 않아도 유지된다.
방문자마다 따로 저장되므로, 테스터 컴퓨터에서만 켜면 다른 사람에게는 영향이 없다.

켜진 상태로 진입하면 콘솔에 다음이 찍힌다:

```
[opening] 테스터 모드 — finder 인터뷰 생략, 대표 기억 직행
[opening] 테스터 모드 — 대표 기억 고정: UNDW-001
```

## 2. 화면이 어떻게 달라지나

| | 풀버전 (기본) | 테스터 모드 |
|---|---|---|
| 0 | 이름을 한 번 입력한 사람은 **오프닝 건너뛰고 메뉴로 직행** | **매번 오프닝부터** (아래 §2-1) |
| 1 | "너가 찾는 기억은 누구의 것이지?" + `...이름 하나` 입력칸 | **없음** |
| 2 | "어떤 기억을 찾고있어?" + 감정 단어 6개 + 입력칸 | **없음** |
| 3 | AI가 만든 추가 질문 2번 (총 3턴) | **없음** |
| 4 | — | **"지금부터 너는 한 기억을 떠올리게될거야"** (약 2.2초 머무름) |
| 5 | "...저기로 가봐." | 동일 |
| 6 | 대답으로 고른 기억으로 진입 | **UNDW-001 고정** |

영어(`en`) 대사는 `you are about to remember something`.

### 2-1. 재방문이어도 오프닝을 매번 보여준다 (2026-08-02 추가)

풀버전에는 **이름을 한 번이라도 입력한 사람은 오프닝을 영구히 건너뛴다**는 규칙이 있다
(`localStorage.tem_user_name` 존재 → [js/app/bindEvents.js](../js/app/bindEvents.js) `v213SkipOpening`).
테스터는 같은 컴퓨터로 여러 명이 돌아가며 하거나 같은 사람이 여러 번 하므로, 이 규칙이 걸리면
두 번째 사람부터 메뉴 화면만 보게 된다. 테스터 모드에서는 이 규칙을 무시한다.

- 무시 지점: `bindEvents.js` 의 `if (isTesterMode() && v213SkipOpening) { v213SkipOpening = false; }`
- 콘솔: `[opening] 테스터 모드 — 재방문 오프닝 skip 무시, 오프닝 강제 표시`
- **풀버전 규칙 자체는 그대로다** — 스위치가 꺼져 있으면 예전처럼 메뉴로 직행한다.

실측 검증 (2026-08-02, 로컬 서버 + 실제 브라우저):

| 상태 | openingScreen | introScreen | 결과 |
|---|---|---|---|
| `tem_user_name` 있음 + 테스터 OFF | `none` | `flex` | 메뉴만 (기존 증상 재현) |
| `tem_user_name` 있음 + 테스터 ON | **`flex`** | `flex` | **오프닝 표시** (파동 + 첫 대사 타이핑 확인) |

`introScreen` 이 `flex` 인 채로 남지만 오프닝(z-index 3000)이 메뉴(2000)를 덮으므로 화면에는
오프닝만 보인다 — 스크린샷으로 확인함.

## 3. 대표 기억 고정

- 코드: `UNDW-001`
- 못 찾을 때 폴백 id: `1835926d-5acc-4d43-afd7-273ed853bca4`
- 둘 다 못 찾으면 경고를 찍고 **기존 매칭 로직으로 자동 폴백** (화면이 멈추지 않는다)

다른 기억으로 바꾸려면 [js/app/opening.js](../js/app/opening.js) 상단의 `TESTER_MEMORY_CODE`
한 줄만 고치면 된다.

### 인터뷰를 건너뛰어도 안전한 이유

인터뷰 결과(감정 지문)가 비어 있어도 뒤쪽 사슬이 전부 안전하게 흘러간다 — 2026-08-02 실측:

```
decideBranch(빈 지문, [])        → speciation / empty_pool     (예외 없음)
decideBranch(빈 지문, 변주 2개)  → speciation / top_score_low  (예외 없음)
```

`speciation` 분기는 마지막 발화 원문을 유령 씨앗으로 저장하려 하는데, 테스터는 아무 말도
하지 않았으므로 원문이 없어 **저장이 자동으로 건너뛰어진다**
(`[opening:dialog] speciation 인데 마지막 turn raw_text 없음 — INSERT 스킵`).
즉 테스터 플레이가 유령 풀을 오염시키지 않는다.

## 4. 원본 흐름 보존본 (풀버전에서 쓰는 것)

아래 두 블록은 **지금도 코드에 그대로 살아 있다.** 테스터 스위치가 꺼져 있으면 이 경로를 탄다.
혹시 나중에 실수로 지웠을 때를 대비해 원문을 여기 남긴다.

### 4-1. `_runV2Sequence` — 닉네임 + intro 질문

```js
  // Returning user gets the same intro prompt as first-time — V2-13's separate
  // replayIntro branch retired (sound-first pivot, 2026-05-15). Nickname prompt
  // still gated on fresh users only.
  const isReturning = !!getUserName();
  if (isReturning) {
    await _typeLinesSequential(dialogue, D.intro);
    await new Promise(r => setTimeout(r, 1200));
  } else {
    await _promptNickname(dialogue, D);
    await new Promise(r => setTimeout(r, 600));
    await _typeLinesSequential(dialogue, D.intro);
    await new Promise(r => setTimeout(r, 1200));
  }
```

이어서 감정 칩 populate → `inputPhase.style.opacity = '1'` 로 입력 단계 표시.

### 4-2. `_handleOpeningSubmit` — 멀티턴 질문 루프

```js
  // 턴 2 + 3: NPC 질문 → 입력 → 분석. 빈 입력은 그 턴 skip.
  for (let turnNum = 2; turnNum <= TOTAL_TURNS; turnNum++) {
    await _fadeOutDialogue(dialogue, 600);
    const question = _pickNextQuestion(fp, _openingLang);
    await _showNpcQuestion(question);
    const turnText = await _waitForUserInput(60000);
    if (turnText) {
      const turnResult = await _analyzeTurnText(turnText, question);
      fp._turnsRaw.push({ turn: turnNum, raw_text: turnText, ts: new Date().toISOString() });
      _mergeTurn(fp, turnResult);
    }
  }
```

### 4-3. `_handleOpeningSubmit` — 기억 매칭 원문

```js
  const memMatch = pickTopMemory(fp, langFiltered);
  if (memMatch && memMatch.memory) {
```

(현재는 `const memMatch = memory ? null : pickTopMemory(fp, langFiltered);` —
테스터 모드에서 이미 기억이 정해졌으면 매칭을 건너뛰라는 뜻이다. 테스터 모드가 꺼져 있으면
`memory` 는 항상 `null` 이라 원본과 완전히 동일하게 동작한다.)

## 5. 테스터 모드를 통째로 걷어내는 절차

스위치를 끄는 것으로 충분하지만, 코드에서 완전히 지우려면 아래 세 파일만 손대면 된다.

**[js/app/testerMode.js](../js/app/testerMode.js)** — 파일째 삭제 (스위치 본체)

**[js/app/opening.js](../js/app/opening.js)**

3. `V2_DIALOGUES` 의 `testerIntro` 두 줄 삭제 (ko / en)
4. `_runV2Sequence` 의 `if (isTesterMode()) { … return; }` 블록 삭제
5. `_handleOpeningSubmit` 의 `const _testerSkipTurns = …` 한 줄 삭제 +
   for 조건을 `turnNum <= TOTAL_TURNS` 로 원복
6. `_handleOpeningSubmit` 의 `// ─── 테스터 모드 (260802): 대표 기억 고정 ───` 블록 삭제 +
   `const memMatch = memory ? null : pickTopMemory(…)` 를 `const memMatch = pickTopMemory(…)` 로 원복

**[js/app/bindEvents.js](../js/app/bindEvents.js)**

8. `if (isTesterMode() && v213SkipOpening) { … }` 블록 삭제 (§2-1)
