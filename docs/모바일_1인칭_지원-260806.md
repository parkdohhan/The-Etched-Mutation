# 모바일 1인칭 지원 (2026-08-06)

> 휴대폰·태블릿에서도 1인칭 지형을 걷게 한다. 여태 모바일은 1인칭을 통째로 건너뛰고
> 옛 2D 등고선 지도로 빠졌다.

---

## 1. 왜 막혀 있었나

`play-test.html` 의 `_temIsMobileDevice()` 가 터치 기기로 판정하면
`[FP Adapter] Mobile detected, skipping first-person mode` 로그를 남기고 폴링 자체를
시작하지 않았다(`var _startPoll = _isMobile ? null : setInterval(...)`).

막아둔 이유는 주석에 적혀 있었다 — **1인칭은 방향키 + 포인터 잠금 마우스에만 의존**하는데
휴대폰엔 둘 다 없다. 들어가봐야 못 움직이고 못 돌아본다.

## 2. 무엇으로 대체했나

| 데스크톱 | 모바일 | 구현 |
|---|---|---|
| W·A·S·D / 방향키 | 왼쪽 아래 십자 패드 (기울기 = 속도) | `rt.setTouchMove(x, y)` |
| 포인터 잠금 마우스 | 화면 쓸기 | `rt.addLook(dx, dy)` |
| Space | 점프 버튼 | `rt.touchJump()` |
| 화면 한가운데 조준 + 꾹 누르기 | **유령을 직접 손가락으로 꾹 누르기** | 탭 좌표 → NDC → `_getAimedPin(cam, ndc)` |

### 조준 방식 변경 (사용자 결정, 8-06)
> "조준점보다 그냥 직접 클릭하는게 낫지않냐?"

엄지로 화면을 쓸어 유령을 화면 한가운데에 맞추는 건 폰에서 너무 성가시다.
모바일은 **짚은 자리가 곧 조준**이다. 그래서:

- 모바일에서 크로스헤어(조준점)는 아예 만들지 않는다 — 남겨두면 "여기 맞춰야 하나" 하고 헛수고한다.
- 짚은 자리에 게이지 링이 차오른다(`TemMobileControls.showPressRing`). 데스크톱은 기존 화면 흔들림 그대로, 링 없음.
- 손가락이 유령을 정확히 짚었으면 **문(나가기)보다 유령이 이긴다** (`_tapHitPin`). 데스크톱은 기존 순서 불변.
- 손가락이 12px 넘게 움직이면 "둘러보기"로 보고 꾹 누르기를 취소한다.

## 3. 건드린 파일

| 파일 | 변경 |
|---|---|
| `js/ui/tem_mobile_controls.js` | **신규.** 십자 패드·화면 쓸기·점프·게이지 링·세로 안내 장막. `window._fpPlayActive` 폴링으로 스스로 붙고 뗀다(호출 배선 없음) |
| `js/shared/tem_af_strata_terrain.js` | 터치 입력 창구 3종 추가. 걷기 계산식은 불변 — `len > 1` 일 때만 정규화하도록 바꿔 스틱 미세 기울기(느린 걸음)가 살아남 |
| `play-test.html` | 모바일 1인칭 잠금 해제, 꾹 누르기를 pointer 이벤트로 통합, 포인터 잠금 요청 모바일 스킵, 조준 좌표화, UI 치수 분기 |
| `js/ui/lumen_dialog_phase1.js` | 좁은 화면(터치 + 높이 < 560) 대화창 축소 |

### 좁은 화면 치수 (가로로 눕힌 폰 = 세로 390~420px)

| 항목 | 데스크톱 | 모바일 |
|---|---|---|
| 하단 파동 `AW_HEIGHT` | 280 | 132 |
| 미니맵 `MINI_SIZE` | 325 | 148 |
| 대화 오버레이 하단 여백 | 300px | 148px |
| 대화 본문 | 1.3rem | 1.02rem |

**대화창 넘침이 이 작업의 실질 결함이었다.** 하단 여백 300px + 본문 1.3rem 을 그대로 두면
대화 박스가 화면 위로 밀려나 대사 첫 줄부터 잘렸다(실측 자막 y = **-127px**). 축소 후 111~172px 로 안착.

대화 중에는 미니맵과 조작 UI를 함께 접는다 — 좁은 화면에선 대화 박스가 미니맵 자리까지 올라온다.

## 4. 가로 모드

- 세로로 들면 "화면을 가로로 돌려주세요" 장막(z-index 99990)이 덮고, 가로로 돌리면 사라진다.
- 입장 문장(`landingEnterText`)을 누를 때 전체화면 + 가로 고정을 시도한다 — 그 클릭이 이 회차의
  유일한 확실한 손가락 제스처다. 지형에 들어간 뒤엔 브라우저가 거절한다.
- 안드로이드 크롬은 전체화면 상태에서만 회전 고정이 먹고, iOS 사파리는 둘 다 없다(장막이 대신 받는다).
- 두 손가락 확대 차단(`user-scalable=no` + `touch-action: none`) — 조준 중 확대되면 짚은 좌표가 어긋난다.

## 5. `?touch=1` 강제 스위치

노트북에서도 모바일 조작을 그대로 켠다. 검증용이자, 터치 노트북처럼 자동 판정이 애매한 기기의 수동 스위치.
`?touch=0` 이면 반대로 강제 해제.

```
http://localhost:8777/play-test.html?touch=1
```

`window.__temForceTouch` 를 가장 이른 시점에 세우고, 판정 함수 네 곳이 모두 이걸 먼저 본다
(module 스코프 `_temIsMobileDevice`, 일반 script `_isTouchDevice`, 조작기 `isMobile`, 대화 모듈 `_isTouchUI`).

> ⚠️ `play-test.html` 은 module 블록(677~6538)과 일반 `<script>` 블록(6540~)이 갈려 있다.
> 일반 블록에서 module 스코프 이름을 직접 부르면 ReferenceError 로 1인칭 전체가 죽는다(260708 검은 화면 사고).
> 그래서 일반 블록엔 `_isTouchDevice()` 를 따로 두고 전역 공유본을 통해서만 부른다.

## 6. 검증 (844×390 = 가로로 눕힌 아이폰 14)

| 항목 | 결과 |
|---|---|
| 십자 패드 걷기 | 정면 방향 정확, 3초에 12.5칸 |
| 화면 쓸기 시선 | 160px → 0.51 rad (29°) |
| 유령 직접 짚기 | 화면 중앙에서 88px 벗어난 유령을 짚어 대화 진입 성공 |
| 게이지 링 | 짚은 좌표(334, 313)에 정확히 표시 |
| 대화 박스 | 111~172px, 화면 안 완전 수납 |
| 이어쓰기 입력창 | 196~238px, 화면 안 |
| 세로 안내 장막 | 390×844 에서 표시 → 844×390 에서 해제 |

**데스크톱 회귀 (1440×900)**: 조작기 미부착, 십자 패드 없음, 크로스헤어(z 300) + 외곽 링(299) 존재,
키보드 걷기 정상, 마우스 시선 정상, 꾹 누르기 → 화면 흔들림 + 대화 진입 정상,
대화창 치수 원래값 유지(여백 300px / 본문 20.8px / 이름표 14.72px), 모바일 링 미표시.

## 7. 남은 것

- **실기기 확인 필요.** 브라우저 시뮬레이션은 터치 이벤트를 합성한 것이라, 실제 손가락의
  멀티터치(왼손 걷기 + 오른손 시선 동시)와 가상 키보드가 올라올 때의 대화창 가림은 폰에서 봐야 한다.
- 가상 키보드가 입력창을 가리면 `window.visualViewport` 로 대화창을 밀어올리는 처리 추가 검토.
- 이어쓰기 연결사 드롭다운은 폰 기본 선택 UI(휠)로 뜬다 — 미감 검토 대상.
