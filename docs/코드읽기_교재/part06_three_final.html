17장 · 검사하는 눈3D의 겉모양: Three.js

목표 지형 · 문 · 유령을 그리는 코드의 겉모양만 읽는다. 무대 · 카메라 · 그리는 장치 세 가지, 물체 = 모양 + 재질, 그리고 매 프레임 도는 루프. 삼각형을 어떻게 그리는지는 안 배운다.

것비유읽는 법
THREE.Scene무대물체를 올려놓는 곳. scene.add(물체)로 올림.
THREE.PerspectiveCamera카메라재료 넷: 시야각 50도 · 화면 비율 · 가장 가까운 거리 0.1 · 가장 먼 거리 500. 이 밖은 안 보임(지형 끝이 사라지면 여기 숫자).
THREE.WebGLRenderer그리는 장치무대를 카메라로 찍어 canvas(html 의 그림판 상자)에 냄. antialias: true = 테두리 부드럽게.

new THREE.X(…) = "X 를 하나 만든다". THREE. 뒤 이름만 읽으면 무엇을 만드는지 압니다. 이 프로젝트는 Three.js r128(2021년판)을 씁니다. 최신 예제 문법이 안 맞는 이유이고, 9월 23일 실험 기록에 "스플랫은 r128 위험"이라고 적힌 이유입니다.

읽는 법
  • THREE.Group(1번째 줄) = 물체 여러 개를 담는 묶음. 문 전체를 한 덩어리로 옮기려고. userData._exitDoor = true는 물체에 쪽지(html 의 data-, 13장의 dataset과 같은 발상). 나중에 "출구 문이냐?"를 이 쪽지로 묻습니다.
  • THREE.MeshStandardMaterial({ color, roughness, metalness })(5번째 줄) = 재질. 색 · 거칠기 · 금속성. 0x8a7a65는 색을 16진수로 적은 것 = css 의 #8a7a65와 같은 색(2장). 흙빛 나무색.
  • THREE.Mesh(모양, 재질)(6번째 줄) = 물체. 모양은 BoxGeometry(가로, 높이, 깊이): 가로 0.15 · 높이 3.2 · 깊이 0.15 = 가늘고 긴 기둥. PlaneGeometry(가로, 높이)는 판.
  • .position.set(x, y, z)(7번째 줄) = 어디에 놓나. y 가 위. 왼쪽 기둥 x=-0.7, 오른쪽 기둥 x=0.7, 높이 1.6 은 기둥 가운데(3.2 의 절반). 상인방(lintel)은 y=3.25 로 위에 얹힘.
  • .add(물체) = 묶음이나 무대에 올림.
  • THREE.PointLight(색, 세기, 거리, 감쇠)(20번째 줄) = 전구. 색 0xc4a882… 2장의 --accent-memory와 같은 금색입니다. 문 위 3.5 에 떠서 6 거리까지 은은하게.

이 스무 줄이 상영에서 보이는 그 문입니다. 기둥 둘, 상인방 하나, 어두운 판 하나, 금색 전구 하나. 3D 코드는 "무엇을 · 어떤 재질로 · 어디에" 세 가지의 반복입니다.

매 프레임 도는 루프

읽는 법
  • 애니메이션은 전부 이 모양입니다: 함수 하나(tick) 안에서 → 값을 조금 바꾸고(3번째 줄, 0.032 씩) → 그리고(7번째 줄) → 아직 덜 됐으면 다음 프레임에 자기를 다시 부른다(9~10번째 줄). 15번째 줄이 첫 시동.
  • requestAnimationFrame(tick)(11장) = "다음 그리기 직전에 tick 을 한 번". tick 안에서 또 부르니 초당 60번 돕니다. 다 되면(else) 안 부르니 멈춤. 12번째 줄 null은 "지금 도는 애니메이션 없음" 표시.
  • lerp(8장의 Lerp)는 "두 값 사이를 비율만큼 섞기", easeOutCubic은 "처음엔 빠르고 끝은 천천히". 연출 코드에 늘 나오는 두 단어. 속은 몰라도 됨.
  • 3D 무대라면 7번째 줄 자리에 renderer.render(scene, camera)("무대를 카메라로 찍어 내라")가 있습니다. strataView.js 717번째 줄의 animId = requestAnimationFrame(animateLoop)가 지형 뷰의 같은 자리.
이 프로젝트 기록(디버깅 지름길 메모): 카메라를 콘솔에서 옮겨도 _fpTick이 매 프레임 되돌립니다. 루프가 도는 동안은 루프 밖에서 바꾼 값이 다음 프레임에 덮입니다. "값을 바꿨는데 안 바뀌어요"의 3D 판 원인. 루프 안을 봐야 합니다.
3D 코드는 new THREE.이름의 이름만 읽는다. 물체는 "모양 + 재질 + 위치". 애니메이션은 "값 조금 바꿈 → 그림 → 자기 다시 부름". 0x 색은 css # 색과 같다.

grep: 폴더 전체에서 찾기

Ctrl+Shift+F. 파일 하나가 아니라 저장소 전체에서 글자를 찾습니다. 이 책에서 grep 이 필요한 자리 셋:

  • 진입점 세 곳(12장): 기능 이름이나 파일 이름 → 세 문 중 몇 곳에 있나.
  • 캐시버스터(12장): 파일 이름 → 각 줄의 ?v=가 같고 새로운가.
  • 죽은 레버(16장): 열 이름 → 읽는 자리(= 오른쪽)가 있나.

검색 결과 창에서 파일별로 몇 개인지 숫자가 나옵니다. 세는 것이 전부입니다.
