여기서부터는 속을 봅니다

앞의 18장에서 제가 계속 "속은 몰라도 된다"고 했죠. 경계만 보라고. 그건 지금도 맞아요. AI가 "고쳤어요" 할 때 진짜인지 확인하는 데는 경계만 보면 됩니다.

그런데 10월에 질문이 바뀌었어요. "내 엔진이 어떤 원리로 도는지 나도 모른다. 인정받으려면 내가 설명할 수 있어야 한다." 이건 경계를 보는 눈으로는 답이 안 나와요. 속을 봐야 해요. 그래서 이 부(部)를 붙였습니다.

미리 안심시켜 드릴게요. 속이라고 해 봐야 수학은 세 개예요. 평균, 코사인(두 화살표 사이 각도), 지수이동평균(새 값 10%, 옛 값 90%). 미적분 없어요. 행렬 없어요. 이 셋을 모르는 사람은 없어요. 다만 코드 안에서 그 셋이 어떤 옷을 입고 있는지를 모를 뿐이에요. 그 옷을 벗기는 게 이 부의 일입니다.

엔진은 질문 하나에 답합니다

별이엔진이 받는 질문은 딱 하나예요. 설계 문서 첫 줄에 그대로 적혀 있어요.

"A가 기억을 말했다. B가 그 기억을 읽고 반응했다. A와 B의 경험이 얼마나 비슷한가?"

답은 0에서 1 사이 숫자 하나. 1이면 똑같이 겪은 것, 0이면 전혀 다르게 겪은 것. 이 숫자 이름이 정렬도(alignment)예요. 엔진이 하는 일은 이 숫자를 내는 것뿐이고, "그러니까 당신은 이런 사람이다"라든가 "다음엔 이렇게 하라" 같은 말은 절대 안 합니다. 설계 원칙에 "엔진은 판단하지 않는다, 관찰하고 보고할 뿐"이라고 박아 뒀어요. 7월 16일에 "높은 정렬 = 승리"라는 말을 걷어내고 "접촉"이라는 말로 바꾼 것도 같은 맥락이에요. 숫자가 높은 건 잘한 게 아니라 일어난 거예요.

20장 · 엔진 읽기코사인: 두 화살표 사이 각도

목표 감정 하나가 코드 안에서 어떤 모양인지(17칸 묶음), "비슷하다"를 숫자로 바꾸는 코사인이 뭔지, 그리고 손으로 한 번 계산해 본다. 이 장을 넘기면 엔진의 수학 절반이 끝난다.

왜 "벡터"라고 부르나

문서에 자꾸 "감정 벡터"라는 말이 나오죠. 벡터는 그냥 칸마다 숫자가 든 묶음을 화살표로 보는 것이에요. 칸이 두 개면 종이 위에 그릴 수 있어요. 가로가 공포, 세로가 기쁨이라고 치면, { fear: 0.8, joy: 0.2 }는 원점에서 오른쪽으로 0.8, 위로 0.2 간 자리를 가리키는 화살표예요. 칸이 17개면 종이에 못 그리지만 수학은 똑같이 돌아가요. 그래서 저는 머릿속으로는 항상 두 칸짜리로 생각해요. 그걸로 충분해요.

"비슷하다"를 숫자로: 코사인

화살표 두 개가 있으면 "비슷하다"를 두 가지로 잴 수 있어요. 하나는 끝점 사이 거리. 다른 하나는 두 화살표 사이 각도. 엔진은 각도를 써요. 각도를 0~1 숫자로 바꾼 게 코사인이에요.

  • 두 화살표가 같은 쪽을 가리키면 코사인 = 1.
  • 직각이면 0.
  • 정반대면 -1. (엔진은 음수가 나오면 0으로 깎아요. 이유는 22장.)

왜 거리가 아니라 각도냐. 각도는 세기를 무시하거든요. { fear: 0.4, joy: 0.1 }과 { fear: 0.8, joy: 0.2 }는 길이는 두 배 차이지만 방향은 똑같아요. 코사인은 1. "덜 무서웠다"와 "많이 무서웠다"를 같은 결로 치는 거예요. 이건 설계 선택이에요. 결이 같으면 같은 경험으로 본다. 세기 차이는 안 본다. 좋다 나쁘다가 아니라, 이 엔진이 그렇게 정했다는 걸 아는 게 중요해요.

손으로 한 번

계산법은 세 줄이에요. 두 칸짜리로 해 볼게요.

  1. 칸끼리 곱해서 전부 더한다. (이걸 내적이라고 불러요. 이름은 몰라도 돼요.)

js/shared/math.js : 183~209 (cosineSimilarity) 
export function cosineSimilarity(vec1, vec2, anchorEmotions = null) {
  if (!vec1 || !vec2) return 0;

  let keys;
  if (anchorEmotions && Array.isArray(anchorEmotions) && anchorEmotions.length > 0) {
    keys = anchorEmotions.map(anchor => normalizeAnchor(String(anchor)));
  } else {
    keys = DEFAULT_EMOTION_ANCHORS;
  }

  let dotProduct = 0;
  let mag1 = 0;
  let mag2 = 0;

  keys.forEach(key => {
    const v1 = vec1[key] || 0;
    const v2 = vec2[key] || 0;
    dotProduct += v1 * v2;
    mag1 += v1 * v1;
    mag2 += v2 * v2;
  });

  mag1 = Math.sqrt(mag1);
  mag2 = Math.sqrt(mag2);

  if (mag1 === 0 || mag2 === 0) return 0;
  return dotProduct / (mag1 * mag2);
}
읽는 법
  • 4~9번째 줄: 어느 칸들로 잴지 정해요. 셋째 재료(anchorEmotions)로 칸 목록이 들어오면 그걸 쓰고, 안 들어오면 기본 17칸. 이게 7월 27일에 정한 "기억별 좌표계"가 들어오는 자리예요. 기억마다 실제로 쓰는 감정 어휘만으로 재겠다는 결정. 그 결정이 코드 한 줄짜리 갈림길(4장)로 들어와 있는 거예요.
  • 10~13번째 줄: 빈 통 세 개. 곱해서 더할 통, A 길이 통, B 길이 통.

  • 22~23번째 줄: 길이 = 제곱근. 위 표의 ②.
  • 25번째 줄: 둘 중 하나라도 길이가 0이면(아무 감정도 없으면) 0을 답으로. 0으로 나누면 터지니까요.
  • 26번째 줄: 표의 ③. 끝.

27줄이 전부 위의 세 줄짜리 계산이에요. 코드가 길어 보이는 건 "없을 때" 대비(2 · 25번째 줄)와 "어느 칸으로" 고르기(4~9번째 줄)가 붙어서예요. 계산 자체는 15~26번째 줄, 열두 줄.

"비슷하다"는 말이 코드에선 항상 코사인이에요. 장면 하나의 점수도 코사인, 궤적 모양 비교도 코사인(다음 장), 고착 감지도 코사인(최근 셋이 서로 얼마나 같은 결이냐). 그러니까 어떤 문서가 "유사도"라고 쓰면 "코사인이겠구나, 세기는 무시하겠구나"라고 읽으면 거의 맞아요. 안 맞는 자리가 하나 있는데, 지형 배치용 VAD 거리(calculateVADSimilarity)예요. 그건 판단에 안 쓰고 그림 그릴 때만 써요. 7월에 "VAD 안 쓰기로"라고 한 건 정렬도 점수에 안 쓴다는 뜻이었어요.
감정 = 17칸 묶음. 비슷함 = 코사인 = 각도. 세기는 무시, 결만 본다. 계산은 "곱해서 더하고, 길이로 나눈다" 세 줄.
