목표 js/core/ByeoriEngine.js의 중심 함수 calculateStep을 재료 받기부터 답 내보내기까지 아홉 덩어리로 끊어서 읽는다. 다 읽으면 "L × S × V"가 어디서 어떻게 나오는지 손가락으로 짚을 수 있다.

식부터 외워 두세요

파일 맨 위 주석에 식이 통째로 적혀 있어요. 이걸 먼저 외우고 코드를 읽으면, 코드는 이 식의 재료를 준비하는 과정일 뿐이라는 게 보여요.

js/core/ByeoriEngine.js : 4~7 
// 공식: alignment = level × shape × void_mod
// level = 장면별 감정 유사도 평균
// shape = 감정 변화 궤적의 형태 유사도 (3장면 미만이면 1.0)
// void_mod = 회피 보정 (기본 1.0, 회피 시 0.7)

한국어로 다시 쓰면 이래요.

정렬도 = 수준 × 형태 × 회피

  • 수준(level): 장면마다 "작가와 얼마나 같은 결이었나"를 코사인으로 재고, 지금까지 본 장면 전부의 평균.
  • 형태(shape): 장면에서 다음 장면으로 감정이 어느 쪽으로 움직였나를 작가의 움직임과 비교한 코사인. 장면이 셋 미만이면 비교할 게 없어서 1.
  • 회피(void_mod): 관객은 감정을 안 내놨는데 작가는 내놨으면 0.7을 곱해서 깎음. 아니면 1(그대로).

셋을 곱해요. 더하는 게 아니라. 왜 곱이냐는 22장에서 말할게요. 지금은 "하나라도 0이면 전체가 0"이라는 성질만 기억하세요.

js/shared/math.js : 302~305 
export function calculateLevelSimilarity(sceneScores) {
  if (!sceneScores || sceneScores.length === 0) return 0;
  return sceneScores.reduce((a, b) => a + b, 0) / sceneScores.length;
}

reduce((a, b) => a + b, 0)는 "0에서 시작해 전부 더해라"(7장의 반복 한 종류), 그걸 개수로 나누면 평균. 끝이에요. 장면 네 개 점수가 0.9 · 0.8 · 0.6 · 0.7이면 수준은 0.75.

1~6번째 줄은 덩어리 ③의 5번째 줄과 같은 모양이에요. 지금까지 궤적 끝에 이번 감정을 붙여서 두 목록을 만들어요. 관객 목록과 원본 목록. userVector.base || userVector는 "묶음 안에 base 칸이 있으면 그걸, 없으면 묶음 자체를"(8장). 이 파일은 감정이 { base: {...}, reason_analysis: {...} }로 포장돼 들어올 때도 있고 맨 묶음으로 들어올 때도 있어서 둘 다 받아요.

8번째 줄에서 형태를 계산해요. 속을 보죠.

export function calculateShapeSimilarity(userTrajectory, originalTrajectory, emotionKeys = null) {
  // emotionKeys (260727 기억별 좌표계): level 과 같은 자로 재도록 호출자가 축 목록을
  // 넘길 수 있다. 생략 시 판단 기본 17축 — V4 §9.1 (level·shape 동일 좌표계) 유지.

    return { raw: 1.0, clamped: 1.0, active: false };
  }
  const deltaUser = [];
  const deltaOrig = [];
  for (let i = 1; i < userTrajectory.length; i++) {
    deltaUser.push(subtractVectors(userTrajectory[i], userTrajectory[i - 1]));

읽는 법
  • 4~6번째 줄: 장면이 셋 미만이면 형태 = 1, 그리고 active: false("형태는 아직 안 쟀음" 표시). 왜 셋이냐. 움직임을 하나 재려면 장면 둘이 필요하고, 움직임 둘을 비교하려면 장면 셋이 필요해요. 움직임이 하나뿐이면 "방향이 비슷한가"를 물을 수 없어요. 그래서 1을 돌려주면 정렬도 = 수준 × 1 × 회피가 되어 초반엔 수준만 반영돼요. 이게 19장 시험 1번의 답이에요.
  • 9~12번째 줄: 움직임(delta) 만들기. 둘째 장면부터 "이번 감정 빼기 직전 감정"을 구해 목록에 넣어요. subtractVectors는 칸마다 빼는 것. 관객 것 한 목록, 원본 것 한 목록.
  • 13번째 줄: 움직임 목록을 한 줄로 펴서(flattenDeltas) 코사인(cosineFlat). 펴는 건 그냥 "움직임1의 17칸, 움직임2의 17칸, …"을 쭉 이어 붙이는 거예요. 그러면 긴 화살표 하나가 되고, 관객 것과 원본 것 두 화살표의 각도를 재요. 20장과 완전히 같은 계산.
  • 14번째 줄: 날것(raw, -1~1)과 깎은 것(clamped, 음수면 0) 둘 다 돌려줘요. 엔진은 깎은 걸 식에 넣고 날것은 debug에만 남겨요.

손으로 한 번: 장면 셋

두 칸짜리로 해 볼게요. 관객이 장면 셋을 봤고, 갈수록 무서워졌어요. 작가도 그랬어요.

장면 1장면 2장면 3
관객{ fear 0.2, joy 0.8 }{ fear 0.6, joy 0.4 }{ fear 0.9, joy 0.1 }
작가 원본{ fear 0.3, joy 0.7 }{ fear 0.7, joy 0.3 }{ fear 0.8, joy 0.2 }
장면 점수(코사인)0.990.980.99

수준 = (0.99 + 0.98 + 0.99) ÷ 3 = 0.99. 장면마다 거의 같은 결이었어요.

이제 움직임. 둘째 빼기 첫째, 셋째 빼기 둘째.

움직임 1 (장면2 − 장면1)움직임 2 (장면3 − 장면2)한 줄로 편 것
관객{ fear +0.4, joy −0.4 }{ fear +0.3, joy −0.3 }[0.4, −0.4, 0.3, −0.3]
작가{ fear +0.4, joy −0.4 }{ fear +0.1, joy −0.1 }[0.4, −0.4, 0.1, −0.1]

편 두 줄의 코사인: 곱해서 더하면 0.16 + 0.16 + 0.03 + 0.03 = 0.38. 길이는 √0.50 = 0.707과 √0.34 = 0.583. 나누면 0.38 ÷ 0.412 = 0.92. 둘 다 공포 쪽으로 움직였고, 폭만 조금 달랐으니 높게 나와요.

정렬도 = 0.99 × 0.92 × 1 = 0.91. 등급은 HIGH, 패턴은 echo_follow가 될 거예요(덩어리 ⑦, ⑧에서 확인).

왜 "순서"가 아니라 "움직임"인가

자주 헷갈리는 데라서 짚고 갈게요. 관객이 장면을 어떤 순서로 보든, 원본 목록도 같은 순서로 재배열해서 비교해요. 그러니까 순서 자체는 점수를 떨어뜨리지 않아요. 떨어뜨리는 건 "그 순서로 봤을 때 감정이 어느 쪽으로 움직였나"가 작가와 다른 경우예요. 장면마다 감정은 비슷한데 움직인 방향이 반대면, 수준은 높고 형태는 0이 돼요. 24장 두 번째 문제가 정확히 이거예요.

const alignment = calculateTrajectoryAlignment(level, shapeResult.clamped, voidMod);

export function calculateTrajectoryAlignment(level, shape, voidMod = 1.0) {
  return Math.max(0, Math.min(1, level * shape * voidMod));
}

식 그대로예요. 셋을 곱하고, 0 아래면 0, 1 위면 1로 잘라요. 이 줄이 이 파일의 심장인데 한 줄이에요. 나머지 189줄은 이 한 줄의 재료를 만들고, 결과에 이름표를 붙이는 일이에요.

덩어리 ⑧ 어긋남 종류, 전이 패턴 (87~91, 121~171)

js/core/ByeoriEngine.js : 121~150 (_getMismatchType) 
_getMismatchType(userVector, originalVector, frameKeys = null) {
  if (!userVector || !originalVector) return null;

  const userReason = userVector.reason_analysis || {};
  const origReason = originalVector.reason_analysis || {};

  if (!!userReason.is_void !== !!origReason.is_void) return 'void_mismatch';

  if (userReason.attribution && origReason.attribution &&
      userReason.attribution !== origReason.attribution) return 'attribution_mismatch';

  if (userReason.target && origReason.target &&
      userReason.target !== origReason.target) {
    const emotionSim = cosineSimilarity(
      userVector.base || userVector,
      originalVector.base || originalVector,
      frameKeys
    );
    if (emotionSim >= 0.5) return 'target_displacement';
  }

  const emotionSimilarity = cosineSimilarity(
    userVector.base || userVector,
    originalVector.base || originalVector,
    frameKeys
  );
  if (emotionSimilarity < 0.5) return 'emotion_mismatch';

  return null;
}

위에서 아래로 먼저 걸리는 게 답이에요. 4장의 "문지기 줄서기". 순서가 곧 우선순위예요.

  1. 한쪽만 회피했으면 → 회피 어긋남.
  2. 둘 다 "탓"(attribution)을 적었는데 다르면 → 탓 어긋남.
  3. 둘 다 "대상"(target)을 적었는데 다르고, 감정은 비슷하면(코사인 0.5 이상) → 대상 옮김. "같은 감정인데 향한 데가 다르다."
  4. 감정 코사인이 0.5 미만이면 → 감정 어긋남.

목표 식의 모양(왜 곱인가, 왜 움직임인가)이 어디서 왔는지, 식 안의 숫자(0.7 · 0.85 · 0.50 · 셋 규칙)가 어디서 왔는지를 둘로 나눠서 말할 수 있게 된다. 이 둘을 섞어 말하면 심사위원이 바로 찌른다.

코드엔 "왜"가 없어요

21장을 다 읽으면 식은 읽혀요. 그런데 "왜 더하지 않고 곱하냐", "왜 0.7이냐"는 코드 어디에도 없어요. 그건 설계 문서 docs/별이엔진_V4-궤적기반_정렬도-260327.md에 있어요. §3이 "왜 이 공식이어야 했는가", §4가 "이론적 기반", §9가 "설계 결정 기록". 이 세 절이 이 장의 재료예요. 제가 여기서 하는 일은 그걸 "이론에서 온 것"과 "직접 정한 것"으로 가르는 거예요.

먼저 실패 이야기: V1에서 V4까지

이 식은 처음부터 이랬던 게 아니에요. 세 번 실패하고 네 번째예요. 실패 기록이 식의 모양을 설명해요.

판식뭐가 안 됐나
V1감정 코사인 하나"같은 감정이라도 이유가 다르면 다른 경험"을 못 담음. 둘 다 슬펐으면 끝.
V2글 임베딩 코사인 + VAD 거리"엄마한테 미안해서 울었다"와 "친구한테 미안해서 울었다"가 임베딩 공간에서 거의 같은 자리. 이유를 못 가름.
V3감정 0.4 + 이유 0.4 + 태도 0.2세 가지가 터짐. ① AI가 뽑는 이유 꼬리표가 같은 글에서도 흔들려 점수가 최대 0.14 널뜀. ② 이유 축이 15단계 꼬리표 맞추기라 해상도가 너무 낮음. ③ 더하기라서 한 축이 0이어도 다른 축이 메움. 감정이 정반대(0)여도 이유 꼬리표가 우연히 같으면 0.54까지 올라감. 그리고 0.4/0.4/0.2라는 비율에 근거가 없었음.
V4수준 × 형태 × 회피이유를 재지 않기로 함. 대신 이유의 결과를 봄. 같은 감정이라도 이유가 다르면 다음 장면에서 다르게 움직일 테니, 움직임(형태)을 비교하면 이유 차이가 간접으로 드러남.

여기서 V4의 핵심 전환을 한 문장으로 하면 이래요. "이유를 직접 재는 대신 이유의 결과를 관찰한다." 장면 1에서 둘 다 슬펐어도, "내 탓"이라 느낀 사람은 장면 2에서 죄책감 쪽으로, "그 사람 탓"이라 느낀 사람은 분노 쪽으로 움직여요. 궤적이 갈라지면 이유가 달랐다는 게 드러나요. AI가 이유를 뽑을 필요가 없어져요. 이게 V3의 세 문제를 한 번에 없앤 수였어요.

이론에서 온 것: 식의 모양

식의 모양을 정한 외부 이론은 사실상 하나예요. 나머지는 그 모양이 말이 된다는 뒷받침이에요.

① 왜 두 항인가, 왜 곱인가 → Butler의 TIES

Butler(2011, 2017)가 "감정은 시간에 걸쳐 펼쳐지는 대인 시스템"이라며 한 주장이 이거예요. 감정의 수준(level)과 감정의 움직임(dynamics)은 서로 독립이고, 둘 다 따로 관계의 질을 예측한다. 별이엔진은 이 구분을 그대로 가져왔어요. 수준 따로, 형태 따로. 그리고 독립인 두 것을 결합할 때 더하면 V3의 ③ 문제(한쪽이 메움)가 다시 생기니까 곱했어요. 곱이면 한쪽이 0일 때 전체가 0. "감정이 비슷해도 궤적이 반대면 낮고, 궤적이 비슷해도 감정이 다르면 낮다"가 구조로 보장돼요. §9.1이 이 결정이에요.

딱 하나만 읽으시겠다면 Butler 2017이에요. 여섯 쪽이에요. 이 식의 뼈대가 거기서 왔어요.

② 왜 감정을 코사인으로 재도 되나 → 정서 유사도 연구

"같은 상황에서 같은 감정을 느끼는 것"이 공감 · 조율 · 관계 만족과 연결된다는 연구 묶음(Locke & Horowitz 1990, Preston & de Waal 2002, Anderson 외 2003 등). 이건 "감정이 비슷하다는 게 의미 있는 양이다"라는 뒷받침이지, 코사인이라는 계산법을 준 건 아니에요. 코사인은 그냥 벡터 비슷함의 표준 도구예요.

③ 왜 움직임의 궤적을 비교하나 → 감정 궤적 그래프

서사 분석에서 이야기를 "시간순 감정 곡선"으로 만들어 비교하는 건 이미 있는 방법이에요(Reagan 외 2016, "이야기의 감정 곡선은 여섯 모양으로 수렴한다"). 별이엔진은 그 방법을 빌리되 감정 값이 아니라 감정의 변화량을 비교해요. 그래서 "얼마나 슬펐나"가 아니라 "어느 쪽으로 움직였나"가 잡혀요. 이건 빌린 방법 위에 얹은 TEM의 변형이에요.

④ 왜 이유를 안 재나 → 인지적 평가 이론의 측정 도구

Lazarus의 평가 이론은 "같은 사건도 사람마다 다르게 평가한다"고 해요. V3는 그 평가를 AI로 뽑으려 했죠. 그런데 심리학에서 평가를 재는 검증된 도구는 전부 자기보고 설문이에요. AI가 글에서 꼬리표를 뽑는 건 검증된 측정이 아니고 재현성도 확인 안 됐어요. 그래서 V4는 이 이론을 버린 게 아니라, 그 이론이 말하는 차이가 궤적에 나타날 거라 보고 간접으로 가요. §4.4가 이 얘기예요.
