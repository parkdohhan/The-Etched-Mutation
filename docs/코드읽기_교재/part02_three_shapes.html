4장 · 코드의 세 가지 모양갈림길: if

목표 코드가 "판단하고 나뉘는" 자리를 읽는다. if를 보면 두 가지만 묻는다. 무슨 질문인가(괄호 안), 맞으면 뭘 하나(뒤). (7월 2교시 확장)

실제 코드: "예전에" 인가 "지금" 인가

안전 필터는 "예전에 죽고 싶었다"(과거 이야기)와 "지금 죽고 싶다"(현재 의도)를 구분합니다. 그 판단이 이 세 줄입니다.

js/safety.js : 78~80 (detectTense 안) 
if (hasIntent && !hasPast) return 'present';
if (hasPast && !hasIntent) return 'past';
return 'ambiguous';
읽는 법
  • if ( … ) = "괄호 안이 맞으면 뒤엣것을 해라". 괄호 안은 항상 예/아니오로 답할 수 있는 질문입니다.
  • hasIntent, hasPast는 안에 예/아니오만 든 상자("의도가 있나?", "과거 얘긴가?"). 영어로 has 가 앞에 붙은 이름은 대개 예/아니오 상자입니다(is, has, can, should 로 시작하면 의심하세요).
  • && = 그리고(둘 다 맞아야). ! = 아니다(뒤집기). 그래서 1번째 줄은 "의도가 있고 그리고 과거 얘기가 아니면 → 답을 '현재'로 정하고 끝".
  • return = 답을 정해 돌려주고 그 자리에서 함수를 끝냄. 1번째 줄에서 return 했으면 2, 3번째 줄은 안 봅니다. 그래서 3번째 줄은 "앞의 두 질문에 다 안 걸리면 → 애매함".

5장 · 코드의 세 가지 모양함수: 기능 한 덩어리

목표 "기능 하나"의 이름 · 재료 · 몸통 · 답을 본다. 검증의 단위가 함수다. AI가 "X 함수 고쳤어요" 하면 그 {부터 }까지만 보면 된다. (7월 3교시 확장)

실제 코드: 가장 작은 함수

index.html : 32 (마스터 음량 안) 
function clamp01(x) { return Math.max(0, Math.min(1, x)); }
읽는 법: 네 부분
부분여기서는뜻
이름clamp01이 기능을 부를 때 쓰는 이름. clamp = 죄다, 01 = 0과 1 사이로.
재료(x)이 기능이 받는 것. 하나.
몸통{ … }여는 중괄호부터 닫는 중괄호까지가 이 기능의 전부. 그 밖은 남의 일.
답return …돌려주는 값. 여기서는 "x를 0~1 사이로 가둔 값".

속(Math.max, Math.min)은 몰라도 됩니다. 이름과 메모가 "0~1로 가둔다"고 말해 주니까요. Math. 뒤에 붙는 것들은 전부 수학 도구(최대 · 최소 · 반올림 · 제곱근)입니다.

실제 코드: 재료가 둘, 답이 셋 중 하나

js/safety.js : 68~81 
function detectTense(originalText, keywordIndex) {
  const before = originalText.substring(Math.max(0, keywordIndex - 40), keywordIndex).toLowerCase();
  const after = originalText.substring(keywordIndex, Math.min(originalText.length, keywordIndex + 60)).toLowerCase();
  const window = before + ' ' + after;

  const hasPast = KO_PAST.test(window) || EN_PAST.test(window);
  const hasIntent = KO_INTENT.test(window) || EN_INTENT.test(window);

  if (hasIntent && !hasPast) return 'present';
  if (hasPast && !hasIntent) return 'past';
  return 'ambiguous';
}
읽는 법
  • 이름 detectTense(시제 감지), 재료 둘(originalText 원문, keywordIndex 위험 단어가 있던 위치), 몸통은 1번째 줄 {부터 12번째 줄 }까지.
  • 2~7번째 줄은 재료를 손질하는 자리(위험 단어 앞 40글자와 뒤 60글자를 잘라 창을 만들고, 그 창에 과거 표현과 의도 표현이 있는지 봄). 속은 지금 몰라도 됩니다.
  • 9~11번째 줄이 4장에서 본 갈림길. 답은 세 글자 중 하나: 'present', 'past', 'ambiguous'. 함수를 읽을 때 "답이 될 수 있는 값이 뭐뭐인가"를 세면 그 함수를 다 읽은 겁니다.

읽는 법
  • { } 안에 또 { }. 안에 든 것일수록 오른쪽으로 밀려 적힙니다. 그게 들여쓰기입니다.
  • 왼쪽 끝만 보면 목차가 보입니다: "바깥 조건 하나(1번째 줄) 안에, 갈림길 세 개(2 · 4 · 6번째 줄)가 나란히."
  • 바깥 if 는 문지기. 궤적이 충분히 깊지 않으면(1번째 줄 질문이 틀리면) 안쪽 세 갈래는 구경도 못 합니다. 그래서 "수렴 오염이 안 올라가요"의 첫 용의자는 안쪽 계산이 아니라 바깥 문지기입니다.
  • 속(delta_conv = ...)은 몰라도 됩니다. 목표는 어디부터 어디까지가 한 덩어리인가뿐.

try { … } catch (_) {}는 "해 보고, 안 되면 조용히 넘어가라"는 안전망(14장). 여기서는 오래된 브라우저에서 부드러운 스크롤이 안 되어도 멈추지 않게 한 것.

짝 찾기

여는 {의 짝은 같은 계단에 있는 }입니다. 편집기에서 여는 괄호에 커서를 두면 짝이 밝게 표시됩니다. VS Code 에서는 Ctrl+Shift+\ 로 짝으로 점프합니다. 괄호 짝이 어긋나면 파일 전체가 죽습니다(14장의 SyntaxError).

큰 파일은 처음부터 읽지 말고, 왼쪽 끝을 훑어 0계단 줄(function, const, if 가 맨 왼쪽에 있는 줄)만 세어 지도를 그린다. 바깥 if 가 틀리면 안쪽은 실행 안 된다는 것을 잊지 않는다.

for · forEach 와 map · filter 의 차이

앞의 둘은 일을 하고 끝(화면에 카드를 붙이거나 저장). 뒤의 둘은 새 목록을 답으로 돌려줌. 그래서 map과 filter는 거의 항상 const 새이름 = 목록.map(…) 처럼 왼쪽에 상자가 있고, 뒤에 점을 더 찍어 이어 붙이기도 합니다: 목록.filter(…).map(…) = "골라낸 다음 바꿔라".

실제 코드: 반복 속 반복

js/shared/tem_variant_strata.js : 136~144 (붓 모양 만들기) 
var BRUSH = (function () {
  var r = PHYS.radius, arr = [], tw = 0, dx, dz, d, w;
  for (dz = -r; dz <= r; dz++) for (dx = -r; dx <= r; dx++) {
    d = Math.sqrt(dx * dx + dz * dz);
    if (d > r) continue;
    w = 1 - d / r;
    arr.push({ dx: dx, dz: dz, w: w });
    tw += w;
  }

3번째 줄에 for 가 두 개 붙어 있습니다. 바깥이 세로(dz), 안이 가로(dx). 격자를 한 칸씩 전부 훑는 모양이고, 지형 코드에 아주 많습니다. continue는 "이번 항목은 건너뛰고 다음으로", arr.push(…)는 "목록 끝에 하나 추가". 원 밖 칸은 버리고, 원 안 칸만 무게를 매겨 목록에 담는 붓입니다.

반복을 보면 세 가지만 적는다. ① 어떤 목록을 ② 하나씩 뭐라 부르며 ③ 뭘 하나. map이면 "새 목록으로 무엇을 만드나", filter면 "무엇을 남기나"를 추가로.
