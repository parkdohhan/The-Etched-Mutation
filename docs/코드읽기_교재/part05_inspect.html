try { 해 봐 } catch (오류) { 실패하면 이거 }. catch (_) {}처럼 비어 있으면 오류를 조용히 삼킵니다. 멈추지는 않지만 콘솔에도 안 남습니다. 편리하지만 함정: "왜 안 되지?"의 원인이 빈 catch 안에 숨을 수 있습니다. AI 에게 "이 catch 가 삼키는 오류가 뭐냐"고 물을 수 있는 자리입니다. 반대로 catch (e) { console.error('…', e) }는 기록을 남기니 콘솔에서 보입니다.

빨간 줄은 종류 · 내용 · 첫 at 줄 세 조각으로 자른다. null/undefined 면 "못 찾았는데 점 찍음", not defined 면 "이름 없음", SyntaxError 면 "파일 통째로 죽음". Network 는 404 = 없음, 403 = 권한, 409 = 충돌.

목표 데이터베이스가 표라는 것, 표를 만들고 고치는 글(SQL)을 읽는 법, 코드가 표를 읽고 쓰는 한 문장, 403 의 근원인 권한 규칙(RLS), 그리고 "저장돼 있다 ≠ 쓰인다"를 안다.

표 · 행 · 열

Supabase 의 데이터베이스는 엑셀과 같습니다. 표(memories, scenes, plays …)가 있고, 행 하나가 기억 하나 · 씬 하나 · 회차 하나, 열이 칸(title, scene_order, alignment …). 행마다 id라는 주민번호가 있고 모양은 8fe034ef-6db0-4ba1-b291-66954fea2e08 같은 36글자(UUID). 코드에서 memory_id, scene_id는 전부 이 번호로 다른 표의 행을 가리키는 것.

실제 SQL: 표 만들기

supabase/migrations/20250107000000_create_notes_table.sql : 4~14 
CREATE TABLE IF NOT EXISTS notes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  memory_id UUID REFERENCES memories(id) ON DELETE CASCADE,
  sender_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  recipient_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  message TEXT NOT NULL,
  note_type TEXT DEFAULT 'player_to_author',
  is_read BOOLEAN DEFAULT false,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT now(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT now()
);
읽는 법
  • SQL 은 영어 문장에 가깝습니다. CREATE TABLE IF NOT EXISTS notes ( … ) = "notes 표를 만들어라, 이미 있으면 말고". 괄호 안이 열 목록, 한 줄에 열 하나: 이름 · 종류 · 규칙.
  • 종류: UUID(주민번호), TEXT(글), BOOLEAN(참/거짓), TIMESTAMP WITH TIME ZONE(시각), INT(정수), JSONB(묶음을 통째로).
  • PRIMARY KEY = 이 열이 주민번호. DEFAULT … = 안 주면 이 값(gen_random_uuid() 새 번호 자동, now() 지금 시각, false).
  • REFERENCES memories(id) ON DELETE CASCADE = "이 칸은 memories 표의 id 를 가리킨다. 그 기억이 지워지면 이 쪽지도 같이 지워라". 표 사이의 끈. (2026-07-14 에 씬 삭제 때 이 끈이 회차까지 지우던 것을 끊는 마이그레이션이 있었습니다. 끈은 편리하지만 위험.)
  • NOT NULL = 비워 둘 수 없음.

실제 SQL: 표 고치기와 권한

supabase/migrations/20260716000000_terrain_layers_and_contact_cols.sql : 11~17, 24~31, 34~36 
create table if not exists public.terrain_layers (
  memory_id    uuid primary key references public.memories(id) on delete cascade,
  height_delta jsonb       not null default '{}'::jsonb,
  foot_map     jsonb       not null default '{}'::jsonb,
  generation   int         not null default 0,
  updated_at   timestamptz not null default now()
);

alter table public.terrain_layers enable row level security;

-- SELECT 공개(anon/authenticated). INSERT/UPDATE/DELETE 정책은 두지 않는다.
-- = 관객(anon)의 쓰기는 매칭 행 0개로 조용히 통과. Edge service_role 만 RLS 우회.
create policy "terrain_layers public read"
on public.terrain_layers for select
to anon, authenticated
using (true);

alter table public.trajectory_bridges
  add column if not exists contact_utterance text,
  add column if not exists contact_turn      int;
읽는 법
  • 대소문자는 상관없습니다(위 파일은 소문자, 앞 파일은 대문자). -- 뒤는 메모(자바스크립트의 //).
  • 9번째 줄 RLS(행 단위 권한) 켜기. 켜면 정책이 허락한 것만 됩니다. 13~16번째 줄 정책: "읽기(select)는 익명(anon)이든 로그인(authenticated)이든 누구나(using true)". 쓰기 정책이 없으니 관객은 못 씁니다. 쓰려면 서버 함수(supabase/functions/record-erosion)가 관리자 열쇠(service_role)로 대신 씁니다. 메모(11~12번째 줄)가 그 설계를 적어 뒀습니다.
  • 14장의 403 이 태어나는 자리가 바로 이 정책입니다. 정책이 "아니오" 하면 403. notes 표의 정책은 auth.uid() = recipient_id("지금 로그인한 사람이 받는 사람일 때만 읽기") 같은 모양.
  • 18~20번째 줄 alter table … add column if not exists = "표에 열을 더해라, 이미 있으면 말고". 표 모양이 바뀌었다는 말은 반드시 이런 파일이 migrations 폴더에 새로 생겨야 합니다(1장 시험 3번). 파일 이름 앞 숫자가 날짜시각이고 그 순서로 적용됩니다.

코드에서 표를 읽고 쓰는 한 문장

js/shared/api.js : 36~40, 59~63 
const { data, error } = await supabaseClient
  .from('scenes')
  .select('*, choices(*)')
  .eq('memory_id', memoryId)
  .order('scene_order');

const { data, error } = await supabaseClient
  .from('plays')
  .insert(playData)
  .select()
  .single();
조각뜻
.from('scenes')scenes 표에서
.select('*, choices(*)')모든 열을, 그리고 끈으로 이어진 choices 표의 행들도 같이
.eq('memory_id', memoryId)memory_id 가 이 값인 행만 (eq = equal). 비슷한 것: .neq 아닌, .gt 보다 큰, .in 목록 안
.order('scene_order')scene_order 순으로 정렬
.insert(playData)이 묶음을 새 행으로 넣어라
.select().single()넣은 행을 돌려받되, 하나만
.update({…}).eq(…)조건에 맞는 행의 칸을 고쳐라 (이 파일 다른 곳)

답은 항상 { data, error }(10장). error가 차 있으면 콘솔 빨간 줄(14장), 그 안의 code: '42501'은 "권한 거부"입니다.

jsonb: 열 안의 묶음

meta, emotion_dist, height_delta처럼 종류가 jsonb인 열은 안에 묶음을 통째로 담습니다. 코드에서는 scene.meta.stage_position처럼 점 두 번. 장점은 열을 안 늘리고 칸을 더할 수 있다는 것. 단점은 넣기만 하고 아무도 안 읽는 칸이 생겨도 표에는 안 보인다는 것.

CLAUDE.md 4절, 죽은 레버 pin_override: 편집기에서 핀을 끌면 meta.pin_override에 저장은 됩니다. 그런데 상영 쪽에 그 칸을 읽는 코드가 없습니다. 진짜 핀 위치는 meta.stage_position. "데이터베이스에 저장된다"와 "쓰인다"는 다른 말입니다. 검사법: 칸 이름(pin_override)으로 grep 해서 읽는 자리(meta.pin_override가 = 오른쪽에 있는 줄)가 있는지 셉니다. 저장하는 자리(= 왼쪽)만 있으면 죽은 레버.

서버 함수(Edge Function)의 머리

supabase/functions/record-erosion/index.ts : 1~6, 33~41 
// record-erosion — 이본 지층 W2-2 (2026-07-16): 봉인 시 변형층 저장 + 스냅샷 로깅.
//
// 배경: 회차 봉인 시 그 관객 몫의 침식(누적 변형층)을 굽고 저장한다.
//   memories/terrain_layers RLS = 익명 관객 직접 쓰기 불가 → service_role Edge 경유가 유일한 길

const MAX_BODY_BYTES = 512 * 1024;    // 스냅샷 포함분
const HEIGHT_SCALE = 20;              // |height_delta 잎| ≤ 이 값

interface RequestBody {
  memoryId: string;
  height_delta: unknown;
  generation: number;
}

파일 끝이 .ts(TypeScript) = 자바스크립트에 종류 표시를 더한 것. memoryId: string은 "memoryId 는 글자여야 한다". 읽는 법은 자바스크립트와 같고, 쌍점 뒤 종류만 덤으로 읽으면 됩니다. 머리 메모가 왜 이 함수가 존재하는지(관객은 못 쓰니 서버가 대신)를 적어 둔 좋은 예. 이 프로젝트 서버 함수 19개는 거의 다 이 이유로 존재합니다.

표 모양이 바뀌었다 → migrations에 새 파일이 있나. 403 → 그 표의 create policy를 읽어 누가 무엇을 할 수 있는지 본다. 저장했다 → 그 칸을 읽는 코드가 있는지 grep.
