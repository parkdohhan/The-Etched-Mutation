11장 · 움직이는 것들기다림: async · await · setTimeout

목표 코드에서 시간이 걸리는 자리를 알아본다. 서버에 물어보는 일, 몇 초 뒤에 하는 일, 매 프레임 하는 일. "저장이 안 됐어요"의 원인 절반이 여기 있다.

왜 기다림이 따로 있나

코드는 위에서 아래로 한 줄씩 돕니다. 그런데 어떤 줄은 답이 바로 안 옵니다. 데이터베이스에 "기억 목록 줘"라고 하면 인터넷 건너 서버가 답할 때까지 0.1초든 2초든 걸립니다. 그동안 화면이 멈추면 안 되니까, 자바스크립트는 "답 오면 이어서 해"라고 표시하고 다른 일을 합니다. 그 표시가 await입니다.

실제 코드: 서버에 물어보기

js/shared/api.js : 8~26 
export async function fetchMemories() {
  const supabaseClient = getSupabaseClient();
  if (!supabaseClient) {
    console.error('fetchMemories: Supabase client not initialized');
    return [];
  }

  const { data, error } = await supabaseClient
    .from('memories')
    .select('*')
    .eq('is_public', true)
    .order('created_at', { ascending: false });

  if (error) {
    console.error('fetchMemories error:', error);
    return [];
  }

  return data || [];
}
읽는 법
  • 1번째 줄 async function = "이 함수 안에는 기다리는 줄이 있다"는 선언. await는 async 붙은 함수 안에서만 쓸 수 있습니다.
  • 8번째 줄 await = "오른쪽 일이 끝날 때까지 여기서 기다렸다가, 답을 왼쪽에 담아라". 8~12번째 줄은 점으로 이어진 한 문장: "memories 표에서 · 모든 열을 · is_public 이 참인 것만 · 만든 시각 내림차순으로" (16장에서 자세히).
  • 답이 { data, error } 묶음으로 오고(10장의 "한꺼번에 풀기"), 오류면 빈 목록, 아니면 data.
await 가 빠지면 답 대신 "약속 상자"(Promise)라는 빈 껍데기가 옵니다. 오류도 안 나고 저장도 안 됩니다. "저장했다는데 데이터베이스에 없어요"를 들으면 첫 용의자는 await 빠진 줄입니다. AI에게 "그 호출 앞에 await 있어?"라고 물으세요. 반대로 await 없이 부르는 게 의도인 경우도 있습니다(기다리지 않고 뒤에서 저장). 그땐 보통 // 비동기, _background… 같은 표시가 있습니다.

옛 모양: then 과 catch

js/app/opening.js : 92 (fadeInSound 안, 줄 나눔) 
const playPromise = audio.play();
playPromise.then(() => {
    console.log('opening 사운드 재생 시작');
    ...
}).catch(e => {
    console.error('opening 사운드 재생 Failed:', e);

await가 생기기 전 방식. .then(함수) = "성공하면 이걸 해", .catch(함수) = "실패하면 이걸 해". 뜻은 await + try/catch 와 같습니다. 브라우저가 소리 재생을 거부하면(사용자가 아직 화면을 안 눌렀을 때) catch 로 갑니다. 오프닝 소리가 안 나는 문제는 이 catch 의 콘솔 메모에서 시작됩니다.

async는 "안에 기다림 있음", await는 "여기서 답 올 때까지". await new Promise(r => setTimeout(r, N))는 통째로 "N 밀리초 쉬기". 저장이 안 됐다는 말을 들으면 await 부터 의심.

사건 붙이기

window.addEventListener('keydown', function (e) {
  if (!(e.ctrlKey && e.shiftKey) || e.altKey || e.metaKey) return;
  if ((e.code || '') !== 'KeyB' && String(e.key || '').toLowerCase() !== 'b') return;
  e.preventDefault();

읽는 법
  • 대상.addEventListener('사건이름', function (e) { … }) = "대상에서 그 사건이 일어나면 이 함수를 돌려라". 대상은 window(창 전체), 사건은 keydown(키 누름). 사건 이름은 click, keydown, mousemove, timeupdate(소리 재생 위치), ended, DOMContentLoaded(html 다 읽음) 등.
  • e = 그 사건의 정보 묶음. e.ctrlKey(Ctrl 눌렸나), e.key(어떤 키), e.target(어디서 일어났나).
  • 2~3번째 줄: 문지기 둘. "Ctrl+Shift 가 아니거나 Alt/Meta 가 섞였으면 나가", "B 키가 아니면 나가". 통과하면 Ctrl+Shift+B.
  • e.preventDefault() = 브라우저가 원래 하려던 일(이 키 조합의 기본 동작) 막기. e.stopImmediatePropagation() = 같은 사건을 기다리는 다른 함수들에게 안 넘기기.
  • 6번째 줄: 페이지 이동(8장). 마지막 true는 "남들보다 먼저 받겠다"는 옵션.

이 일곱 줄이 세 문에 똑같이 있습니다(1장 · 12장). grep "KeyB" 로 셀 수 있습니다.

DOM 동사는 여섯 개(찾기 · 만들기 · 붙이기 · 바꾸기 · 없애기 · 사건 붙이기). addEventListener('X', function (e) {…})를 보면 "X 가 일어나면 → 문지기 → 하는 일" 순으로 읽는다.
