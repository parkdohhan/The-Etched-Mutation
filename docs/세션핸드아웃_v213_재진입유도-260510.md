## 4. 만약 막히면 — fallback 자리

### 4-1. handoff probe filteredScenesLength === 0

`game.traces`에 데이터 안 박힘 → 다른 자리 시도:
1. **`game.plays`** — `_collectPlays` 또는 비슷한 자리에서 박을 가능성. `play-test.html:2240` 부근 확인.
2. **`window._temGame.contState`** — contamination state. 사용자 emotion 자리 박혀있을 수 있음.
3. **수동 한 줄** — fallback으로 평균 user emotion vector 한 줄만 박아 단일 씬으로 표시. firstPlayScenification에 한 줄 파동만 떠도 데모 의미.

코드 자리: `play-test.html:4454` continueBtn click handler 안의 데이터 모으는 자리 (현재 traces → trajectory fallback 박힘). 추가 fallback 박음.

### 4-2. 동적 import 실패

`await import('./js/app/firstPlayScenification.js')` — vite dev 서버에서 OK, file:// 환경에선 CORS. 사용자가 `npm run dev`로 띄워야 함. 만약 정적 서빙(file://)이면 import 실패 → 로그에 "lumen handoff failed:" 박힘. 그 경우 dev 서버 사용 강제.

### 4-3. 두 번째 플레이가 같은 메모리 보장 안 됨

`selectMemory:1190`에서 `replay=1` query param 박지만, lumen 흐름 자리에서 그 param 안 읽음. 두 번째 플레이는 단순히 같은 메모리 다시 진행. 만약 사용자가 다른 메모리 클릭하면 그 메모리의 첫 플레이가 됨. **이건 정상** — 메모리별 첫 플레이 데이터가 따로 박힘.
