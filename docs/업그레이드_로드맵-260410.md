# Web 스택 업그레이드 로드맵

> 작성: 2026-04-10
> 맥락: Unity 갈아타기 vs Web 강화 논의 결론. **Web 유지 + 핵심 카드 3장 도입**으로 정리.
> 전제: 데모 영상 → 첫 전시 제안서 → 첫 피드백 사이클을 web으로 끝내고, 그 이후에 v2/Unity 분리 여부 재검토.

---

## 0. 결론 한 줄

**Tone.js + Three.js 셰이더 + GSAP 세 카드만 6주에 걸쳐 도입한다.** 나머지(WebGPU, Rapier, Lottie)는 미래 카드.
Unity는 지금 단계에서 함정이다 — 작품의 80%가 web에 더 적합하고, 갈아타면 데모가 영원히 안 나옴.

## 1. 작품 정체성과 도구의 매칭

너 작품의 핵심 무기:

| 요소 | Web 적합도 | Unity 적합도 | 비고 |
|---|---|---|---|
| 텍스트 오염 / 글리치 | ✅ 자연스러움 | ⚠️ 어렵게 가능 | HTML/CSS가 텍스트에 압도적 |
| 잔상 시스템 (DB 매칭) | ✅ Supabase 그대로 | ❌ 다 다시 짜야 | |
| 감정 벡터 → 색/파동 | ✅ 충분 | ✅ 더 화려함 | 차이는 양적 |
| Strata 3D 지층 | ⚠️ Three.js 한계 있음 | ✅ 풍부 | **셰이더로 메꿀 수 있음** |
| Floating anchor | ✅ DOM | ✅ | |
| AI 대화 (Claude) | ✅ Edge Function | ⚠️ HTTP 직접 | |
| 사운드스케이프 | ⚠️ 약함 | ✅ FMOD | **Tone.js로 메꿀 수 있음** |

## 3. 6주 도입 플랜

### Week 1 — GSAP (가장 빠른 ROI)

**왜 먼저**: 학습 1-3일, 즉각 시각적 효과, 데모 영상 직전 작업으로 최적.

**대상 파일 3개**:
1. [js/ui/afterimage.js](js/ui/afterimage.js) — 잔상 등장/사라짐
2. [js/app/endScreen.js](js/app/endScreen.js) — 엔드 스크린 시퀀스
3. live.js — 씬 전환

**핵심 기법**:
- `gsap.timeline()` — 시퀀스 전체를 한 객체로
- `'-=1.2'` — 이전 애니 끝나기 전에 다음 시작 (겹침)
- `stagger: { each: 0.06, from: 'random' }` — 글자별 시간차
- `ease: 'expo.out' / 'power3.out'` — 영화적 곡선
- `yoyo: true, repeat: -1` — 미세 떨림 영구
- `onUpdate` 콜백 — 정렬도 카운트업
- `gsap.utils.random()` — 흩어지는 사라짐

**구체적 효과**:
- 잔상: 멀리서 안개 뚫고 다가옴 + 글자 무작위 등장 + 떨림 + 클릭 시 사방으로 흩어짐
- 엔드 스크린: 카운트업 정렬도 + 영화 엔드 크레딧 식 stagger
- 씬 전환: 디졸브 + 휘장 + 줌 (3-step)

**비용**: npm install gsap 한 줄. 30KB. 무료.
**참고**: gsap.com/docs/v3/GSAP/Timeline + codrops.com 데모

### Week 2-3 — Tone.js (작품의 약한 고리 보강)

**왜 두 번째**: 너 작품의 시각이 9점이면 사운드는 5점. 균형 회복 필요.

**대상 파일**: [js/audio/SoundscapeBeta.js](js/audio/SoundscapeBeta.js) 전면 재설계

**현재 상태**: mp3 5개(amb_window_rain, amb_silence, amb_crowd, amb_wind, amb_base) 음량 조절만.

**도입 후 능력**:
1. **오염 단계 → 사운드 변환** — biased_inclination → hypercompletion 단계마다 필터/리버브/디스토션이 자동 변화
   ```
   Stage 0: 원음
   Stage 1: lowpass 2000Hz, reverb wet 0.4
   Stage 2: lowpass 1400Hz, reverb wet 0.7, distortion 0.1
   Stage 3: lowpass 800Hz, reverb wet 0.9, distortion 0.4
   ```
2. **감정 벡터 → 신디사이저 음색** — fear는 harmonicity 3.5, longing은 1.5 등
3. **잔상 등장 시 한 음** — FMSynth로 잔상 떠오를 때 톤 한 번
4. **씬 전환 사운드** — 페이드 + 공간감(reverb) 자동 처리

**핵심 개념**:
- `Tone.Player` — 기존 mp3 재생
- `Tone.Filter / Reverb / Distortion` — 이펙트 체인
- `Tone.FMSynth / AMSynth` — 신디사이저
- `rampTo()` — 파라미터 부드러운 전환
- `Tone.Transport` — 타임라인/시퀀서

**비용**: 약 100KB. 무료.
**참고**: tonejs.github.io/examples

### Week 4-6 — Three.js + GLSL 셰이더 (Strata 작품화)

**왜 마지막**: 학습 곡선 가장 가파름. 그리고 결과가 가장 폭발적.

**대상 파일**: [js/shared/tem_af_strata_terrain.js](js/shared/tem_af_strata_terrain.js)

**현재 상태**: `MeshStandardMaterial` 기본 셰이더. 평평한 컬러 + 라이팅.

**도입 후**: 커스텀 ShaderMaterial로 교체

**셰이더에 넣을 효과**:
1. **종이 결 텍스처** — `noise(uv * 80.0)`로 fragment마다 미세한 결
2. **깊이 그라디언트** — 위로 갈수록 색이 마름, 아래로 갈수록 가라앉음 (퇴적층)
3. **Fresnel 안개** — 가장자리가 시야와 만나면 안개로 흐려짐
4. **시간 기반 마모** — `uniform float u_time` 으로 색이 천천히 마모
5. **감정별 컬러 매핑** — vertex color로 17감정 × RGB 매핑 (이미 `EC` 테이블 있음 → 그대로 활용)

**의사 코드**:
```glsl
uniform float u_time;
uniform vec3 u_emotionColor;
varying vec2 vUv;
varying vec3 vNormal;

void main() {
  float grain = noise(vUv * 80.0);
  vec3 color = mix(u_emotionColor, sedimentColor, vUv.y);
  float fog = pow(1.0 - dot(vNormal, viewDir), 3.0);
  color *= 1.0 - 0.2 * sin(u_time * 0.05 + vUv.y * 10.0);
  gl_FragColor = vec4(color + fog * 0.3, 1.0);
}
```

**효과**: Strata가 "3D 모델"에서 "살아있는 퇴적층"으로 변함. teamLab/Refik Anadol 결의 90%가 이거.

**비용**: Three.js 이미 있음. 셰이더 코드만 추가. 0KB.
**참고**:
- thebookofshaders.com (한국어 번역 있음)
- iquilezles.org (셰이더의 신)

## 4. 도입 후 작품 변화 예상

| 영역 | 지금 | 도입 후 |
|---|---|---|
| 잔상 등장 | fade + 타이프라이터 | 안개 뚫고 다가옴 + 무작위 글자 + 떨림 |
| 잔상 사라짐 | 그냥 fade | 글자가 사방으로 흩어지며 안개 |
| 씬 전환 | 즉시 다음 텍스트 | 디졸브 + 휘장 + 줌 |
| 엔드 스크린 | 동시 표시 | 시간차 + 카운트업 + 엔드 크레딧 |
| 사운드 | mp3 5개 음량 | 오염 단계 자동 필터/리버브/디스토션 + 감정별 신디 |
| Strata | 평평한 컬러 | 종이 결 + 퇴적 그라디언트 + 안개 + 마모 |

**시각 9 / 청각 5 → 시각 9.5 / 청각 8.5 / 분위기 9.5**.
영상 데모에서 바이럴 가능한 모먼트 3개 추가 확보 (잔상 흩어짐 / Strata 셰이더 / 카운트업 엔드).

## 5. 미루는 카드 (지금 안 함)

### WebGPU
- 호환성 90% (Firefox만 nightly). 학습 곡선 높음.
- **Three.js r170+ 부터 백엔드 자동 지원** → 너가 직접 안 짜도 따라옴.
- **6개월 뒤 v2 작품 만들 때 진지하게 고민**.
- 가능성: GPU 파티클 잔상, 컴퓨트 셰이더 오염 시뮬레이션, 유체 감정 벡터.

### Rapier.js / Cannon.js
- 너 작품에 물리가 핵심이 아님. 학습 비용 대비 임팩트 작음.
- **거의 안 쓸 가능성 높음**. 시간 남으면.

### Lottie
- AE 능력에 의존. 너가 AE 안 다루면 1/10.
- **모션 디자이너랑 협업 생기면 그때 검토**.
- 가능 활용처: 로딩 시퀀스, 엔드 크레딧, 씬 전환 마스크.

### Howler.js
- Tone.js로 가면 자동 흡수됨. 별도 도입 불필요.

## 6. Unity는 언제 검토하는가

**조건부 트리거 — 다음 중 하나가 명확해질 때**:

1. **전시/페스티벌 큐레이터 피드백**에서 "공간 설치 작품"으로 강하게 권유받음
2. **VR/XR 컨셉**이 떠오르고 그게 작품의 메시지를 강화함
3. **오프라인 키오스크 작품**이 본격 의뢰됨
4. **Steam/itch.io 출시** 의향이 명확해짐 (지금 없음)

**대원칙**: web 작품과 Unity 작품은 **다른 작품**으로 분리한다. 한 작품 안에서 갈아타지 않는다.
- web 버전 = "온라인 작품"
- Unity 버전 = "공간 작품"
- 둘은 같은 컨셉의 두 작품.

**최소 6개월 web 버전을 운영한 뒤** 결정. 그 전에 Unity 시작은 회피 신호.

## 7. 함정 경고 (작가 본인용)

이번 도구 도입 논의가 **데모 끝내야 하는 압박을 회피하는 신호**일 가능성을 항상 점검할 것.

### 회피 신호 체크리스트
- [ ] 새 도구 학습이 데모 일정을 1주 이상 미루고 있는가?
- [ ] 도구를 도입한 작업이 **이미 작동하는 코드**를 다시 쓰고 있는가?
- [ ] "이거 하나만 더…" 패턴이 반복되는가?
- [ ] 데모 영상 촬영 일정이 2주째 안 잡히고 있는가?

위 중 2개 이상 ✓면 → **도구 도입을 멈추고 데모를 끝낸다.**

### 안전 신호
- 도입이 **하나의 새 효과를 만드는 것**으로 끝남
- 기존 코드에 **추가**되고 **재작성**되지 않음
- **데모 영상에 그 효과가 직접 들어감** (즉 작업이 곧 영상 결과물)

## 8. 다음 액션 (단기)

1. **데모 영상 시퀀스를 먼저 정의**한다 — 어떤 장면이 영상에 들어갈지 (15-30초씩 4-5컷)

3. 영상 1차본 촬영 → 부족한 부분 진단

6. 둘 다 아니면 → **이미 충분하다는 뜻**. 도구 더 안 도입하고 영상 마무리.
