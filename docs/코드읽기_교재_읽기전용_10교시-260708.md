# 1교시 — 상자 · 목록 · 메모 · 글자

**목표:** 가만히 있는 데이터를 읽는다.

**실제 코드** — 당신이 설계한 안전 필터 [js/safety.js](../js/safety.js):
```javascript
// Safety system — crisis keyword detection and response
export const SAFETY_KEYWORDS = {
  block_high: [
    "suicide", "kill myself", "want to die", "self-harm", "overdose"
  ],
  monitor_only: [
    "depressed", "want to disappear", "feel empty"
  ]
};
```

**읽는 법**
- `//` = 사람 메모. 막히면 여기부터 찾아라(제일 쉬움).
- `const SAFETY_KEYWORDS =` = "안전 키워드들"이라는 상자를 만든다. `=` 는 "오른쪽 걸 이 상자에 담는다".
- `[ ... ]` = 목록. `"suicide"` 같은 `" "` 는 "글자 그대로의 단어".
- 그래서: **block_high(고위험) 목록 = 즉시 위기 대응할 말들, monitor_only = 안 막고 기록만 할 말들.** (당신 설계 그대로)

**미니 시험** — 아래 상자의 이름은? 목록인가? 어떤 성격의 문장인가?
```javascript
export const CRISIS_DIALOGUES = [
  "......No. This is too sharp.",
  "If I dig any deeper, I'll get hurt."
];
```
> **정답:** ① 이름 = `CRISIS_DIALOGUES` ② 목록 맞음(`[ ]` 때문) ③ 위기 감지 시 속 목소리("Another Me")가 대신 내뱉는 대사들.

# 2교시 — 갈림길 `if`

**목표:** 코드가 "판단하고 나뉘는" 곳을 읽는다.

**실제 코드** — safety.js의 시제 판별("예전에 죽고 싶었다"=과거 vs "지금 죽고 싶다"=현재):
```javascript
if (hasIntent && !hasPast) return 'present';
```

**읽는 법**
- `if (...)` = 만약 괄호 안이 맞으면 뒤엣걸 한다. 괄호 안은 **예/아니오 질문**.
- `hasIntent` / `hasPast` = 안에 **예/아니오만** 든 상자. ("의도 있나?" / "과거 얘긴가?")
- `&&` = 그리고(둘 다 맞아야). `!` = ~가 아니다(뒤집기).
- 통째로: **"지금 하려는 의도가 있고 && 과거 얘기가 아니면 → 답을 '현재(present)'로 정한다."**
- 즉 "지금 죽고 싶다"는 잡고 "예전에 죽고 싶었다"는 놔주는 당신 설계.

**읽는 요령:** `if` 보면 두 개만 물어라 — ① 무슨 질문?(괄호 안) ② 맞으면 뭘 함?(뒤).

**미니 시험** — 별이엔진 [js/core/ByeoriEngine.js:138](../js/core/ByeoriEngine.js#L138). `<` 는 감으로:
```javascript
if (emotionSimilarity < 0.5) return 'emotion_mismatch';
```
> **정답:** `emotionSimilarity`(감정 유사도)가 `< 0.5`(0.5보다 작으면) → `'emotion_mismatch'`(감정 어긋남)라고 판정. 별이엔진이 벌주지 않고 **이름표만 붙이는**(관찰·보고) 자리.

# 3교시 — 함수 = 기능 한 덩어리

**목표:** "기능 하나"의 이름·재료·경계를 본다. (← 검증의 핵심 단위)

**설명용 예시** (모양을 보기 위한 것):
```javascript
function classifyMismatch(emotionSimilarity) {
  if (emotionSimilarity < 0.5) return 'emotion_mismatch';
  return 'aligned';
}
```

**읽는 법 — 세 부분만**
- `function classifyMismatch(...)` = 여기서부터 `classifyMismatch`라는 **기능 덩어리 시작**.
- `(emotionSimilarity)` = 이 기능이 받는 **재료**. "감정 유사도 하나 주면 처리할게."
- `{ ... }` = 이 덩어리의 **몸통(경계)**. 여는 `{` 부터 닫는 `}` 까지가 이 기능의 전부. `}` 넘어가면 남의 일.
- 통째로: **"감정 유사도를 받아 → 0.5 미만이면 '어긋남', 아니면 '정렬됨'이라 답하는 기능."**

**당신 목표와 연결:** AI가 *"classifyMismatch 고쳤어요"* 하면 → `function classifyMismatch` 찾아서 `{` 부터 `}` 까지만 보면 됨. **그 밖은 안 봐도 된다.** 이게 "검증"의 실체 — 파일 전체가 아니라 한 덩어리만 확인.

**미니 시험** — 아래 기능의 ① 이름 ② 재료 몇 개 ③ 몸통은 어디부터 어디까지?
```javascript
function clamp01(x) {
  if (x < 0) return 0;
  if (x > 1) return 1;
  return x;
}
```
> **정답:** ① `clamp01` ② 재료 1개(`x`) ③ 몸통 = 첫 `{` 부터 마지막 `}` 까지. (하는 일: 0보다 작으면 0, 1보다 크면 1, 아니면 그대로 → "0~1 범위로 가둔다".)

# 4교시 — 들여쓰기 = 목차 (덩어리 속 덩어리)

**목표:** 큰 파일을 목차처럼 훑는다.

**실제 코드** — 당신 오염 벡터 계산 [js/core/ContaminationTracker.js:236](../js/core/ContaminationTracker.js#L236):
```javascript
if (depth >= MIN_DEPTH_FOR_CONVERGENCE) {
  if (fixation_level >= FIXATION_THRESHOLD) {
    delta_conv = ...
  } else if (effectiveShape >= 0.7 && level >= 0.7) {
    delta_conv = ...
  } else if (alignment >= 0.5) {
    delta_conv = ...
  }
}
```

**읽는 법**
- `{ }` 안에 또 `{ }` 가 들어감(덩어리 속 덩어리). **안에 든 것일수록 오른쪽으로 밀려 적힌다** = 들여쓰기.
- 왼쪽 끝만 보면 목차가 보임: "바깥 조건 하나 안에, 갈림길 3개가 나란히."
- **바깥 `if` = 문지기.** 여기 통과 못 하면 안쪽 3개는 **구경도 못 함.**
- **속(계산)은 지금 몰라도 된다.** 목표는 "어디부터 어디까지 한 덩어리인가"만.

**읽는 요령:** 큰 파일은 처음부터 읽지 말고 **들여쓰기만 훑어** "여기 한 뭉치, 저기 다음 뭉치" 지도부터 그려라.

**미니 시험** — 위 코드 그대로. 계산 무시하고 모양만: ① 제일 바깥 조건은? ② 그 안에 나란한 갈림길 몇 개? ③ 바깥 조건이 틀리면 안쪽 3개 중 하나라도 실행되나?
> **정답:** ① `depth >= MIN_DEPTH_FOR_CONVERGENCE` ② 3개 ③ 하나도 실행 안 됨(바깥 `{ }` 에 갇힘). — 뜻: 궤적이 충분히 깊어진 뒤에만 수렴 오염을 계산하는 당신 설계.

# 5교시 — 반복 `for ... of` (3대 모양 완성)

**목표:** "목록 전체에 같은 일 다 하기"를 읽는다.

**실제 코드** — safety.js가 위험 단어를 **하나하나 검사**하는 곳 [js/safety.js:93](../js/safety.js#L93):
```javascript
for (const keyword of SAFETY_KEYWORDS.block_high) {
  if (텍스트에 keyword 있으면) {
    ... 위험 처리 ...
  }
}
```

**읽는 법**
- `for (const keyword of 목록)` = "목록에서 하나씩 꺼내 `keyword`라 부르며 `{ }` 를 반복".
- 단어가 20개면 `{ }` 안이 **20번** 돈다. (한 번 쓰고 20번 재생)
- 반복 `{ }` **안에** 갈림길 `if` 가 들어있음 → **"각 위험 단어마다 → 있으면 → 처리".** (4교시+5교시 합체)

**미니 시험** — 처음 보는 [js/core/DriftPicker.js:47](../js/core/DriftPicker.js#L47):
```javascript
for (const w of motifWords) { ... }
```
① 어떤 목록을 도나? ② 하나씩 꺼낸 걸 뭐라 부르나? ③ `{ }` 는 한 번? 목록 개수만큼?
> **정답:** ① `motifWords`(모티프 단어들) ② `w` ③ 목록 개수만큼.

# 6교시 — 이름 읽는 법 (`.` 점 · 낙타 이름 · `let`)

**목표:** 영어투성이 이름에서 뜻을 뽑아내고, `.` 을 읽는다.

**실제 코드**:
```javascript
next.cont_divergence = clamp01(next.cont_divergence + delta_div);
let delta_conv = 0;
```

**읽는 법 — 세 가지**
1. **낙타 이름(붙여쓰기):** `emotionSimilarity` 처럼 대문자에서 단어가 끊긴다 → `emotion` + `Similarity` = "감정 유사도". `cont_divergence` 처럼 `_`(밑줄)로 끊기도 함 → `cont`(contamination, 오염) + `divergence`(발산). **대문자·밑줄에서 잘라서 영어 뜻으로 읽어라.**
2. **`.` 점 = "~의":** `SAFETY_KEYWORDS.block_high` = "SAFETY_KEYWORDS **의** block_high". `next.cont_divergence` = "next(다음 상태) **의** 오염-발산 값". 점은 **큰 상자 안에서 한 칸 꺼내는 것**.
3. **`let` vs `const`:** `const` = 한번 담으면 안 바뀌는 상자. `let` = **나중에 값이 바뀔** 상자. `let delta_conv = 0` 은 "일단 0으로 시작, 뒤에서 바꿀 예정"이라는 신호.

**읽는 요령:** 모르는 이름 만나면 겁먹지 말고 ① 대문자/밑줄에서 자르고 ② 영어 뜻으로 옮기고 ③ `.` 은 "의"로.

**미니 시험**
① `next.cont_convergence` 를 우리말로.
② `emotionVectorToWaveStyle` 를 단어별로 끊어 뜻을 추측.
③ `let uV = 0` 과 `const PI = 3.14` 중 나중에 값이 바뀔 수 있는 건?
> **정답:** ① "next(다음 상태)의 오염-수렴 값" ② emotion Vector To Wave Style = "감정 벡터를 → 파동 스타일로 (바꾸는 것)" ③ `let uV`.

# 7교시 — 만들기(정의) vs 부르기(호출) · `import`/`export`

**목표:** 같은 기능이 "만들어진 곳"과 "쓰이는 곳"을 구별한다. (← 추적의 핵심)

**실제 코드**:
```javascript
// 만든 곳(정의) — safety.js
function detectTense(originalText, keywordIndex) { ... }

// 쓴 곳(호출) — safety.js:97
const tense = detectTense(originalLower, matchIdx);

// 다른 파일 기능 꺼내오기 — recordChat.js:9
import { getAccessToken, getSupabaseClient } from '../lib/supabaseClient.js';
```

**읽는 법**
- **정의(만들기):** 앞에 `function` 이 붙음 → "이 기계를 여기서 **만든다**". 보통 **딱 한 곳**.
- **호출(부르기):** 이름 뒤에 바로 `( )` 가 붙음 → "그 기계를 **지금 돌린다**". **여러 곳**에서 부를 수 있음. `detectTense(originalLower, matchIdx)` = "detectTense 기계에 재료 2개 넣고 돌려".
- **`import` / `export` = 파일 사이 문:** `export` = "이 기능을 남이 쓰게 내놓는다"(1교시의 `export const` 이것). `import { X } from '경로'` = "저 파일에서 X를 **꺼내 온다**". 둘은 짝.

**왜 중요한가:** AI가 *"이거 어디서 일어나요?"* 물으면, **정의는 하나·호출은 여럿**이라는 걸 알아야 "진짜 도는 자리"를 짚는다. `import` 줄만 읽어도 **이 파일이 누구한테 의존하는지** 지도가 나온다.

**읽는 요령:** 이름 뒤에 `( )` 붙어있으면 "지금 돌리는 중". `function` 뒤에 붙어있으면 "만드는 중".

**미니 시험** — 처음 보는 [js/core/SceneNavigator.js:8](../js/core/SceneNavigator.js#L8):
```javascript
import { cosineSimilarity, DEFAULT_EMOTION_ANCHORS } from '../shared/math.js';
```
① 이 줄은 뭘 하나? ② `cosineSimilarity` 는 어디서 만들어졌나? ③ `getAccessToken()` — 정의? 호출?
> **정답:** ① `math.js` 파일에서 `cosineSimilarity` 와 `DEFAULT_EMOTION_ANCHORS` 두 개를 꺼내온다. ② `../shared/math.js` 안. ③ 호출(이름 뒤 `()` 있음).

# 8교시 — 두 번째 `{ }`: 데이터 묶음(객체)

**목표:** `{ }` 의 두 가지 뜻을 구별한다. (TEM DB 한 줄이 다 이 모양)

**실제 코드** — 별이엔진이 돌려주는 결과 [js/core/ByeoriEngine.js:167](../js/core/ByeoriEngine.js#L167):
```javascript
{
  alignment_score: 0,
  current_scene_score: 0
}
```

**읽는 법**
- `{ }` 가 **두 가지** 뜻:
  - (4교시) **코드 덩어리** — 안에 명령이 줄줄이.
  - (8교시) **데이터 묶음(객체)** — 안에 `이름: 값` 짝이 쉼표로.
- **구별법:** 안에 `이름: 값` 이 보이면 **데이터 묶음**. `{ alignment_score: 0 }` = "alignment_score라는 이름표에 값 0을 붙여 묶음".
- **목록 `[ ]` 과 차이:** 목록은 **순서**로 꺼냄, 객체는 **이름표**로 꺼냄. 객체에서 꺼낼 땐 6교시의 `.` — `result.alignment_score`.
- **왜 중요:** TEM의 memory·scene 한 줄이 전부 이런 객체다. `emotion_dist`, `meta` 같은 것도 안이 `{ 이름: 값 }`.

**읽는 요령:** `{ 이름: 값, 이름: 값 }` = "이름표 붙은 값 묶음". `.이름` 으로 한 칸 꺼낸다.

**미니 시험** — 처음 보는 [js/shared/math.js:518](../js/shared/math.js#L518):
```javascript
{
  speed: 0.3 + intensity * 0.9,
  amplitude: 30 + intensity * 50
}
```
① 이건 코드 덩어리인가 데이터 묶음인가? 어떻게 알았나? ② 이름표 몇 개? ③ 이 묶음에서 speed를 꺼내려면 어떻게 쓸까? (묶음이 `wave`라는 상자에 담겼다 치고)
> **정답:** ① 데이터 묶음(`이름: 값` 짝이 있음) ② 2개(speed, amplitude) ③ `wave.speed`.

# 9교시 — 실전 ①: 바뀐 것 읽기 (검증의 진짜 기술)

**목표:** AI가 "고쳤다"고 할 때 눈으로 확인한다.

**개념 — diff(전후 비교):** 코드를 고치면 "전 vs 후"를 나란히 보여줄 수 있다. 관례:
```
- if (score < 0.5) return 'mismatch';      ← 빨강(-): 지운 줄
+ if (score < 0.4) return 'mismatch';      ← 초록(+): 새로 넣은 줄
```
위 예는 "기준을 0.5에서 0.4로 낮췄다"는 뜻. **초록 줄(`+`)만 읽으면 "새로 뭘 하기로 했나"** 가 나온다.

**AI한테 쓸 요청 문구 (그대로 복사해서 써라):**
- "요약 말고 **바뀐 코드 전후로** 보여줘."
- "고친 함수를 `{` 부터 `}` 까지 **그대로 붙여줘**."
- "이 파일 **몇 줄에서 몇 줄로** 바뀌었어?"

**검증 3질문 (매번 물어라):**
1. **바꾼 함수 이름이 뭐야?** (3교시: 한 덩어리만 보면 됨)
2. **그 `{ }` 경계 안만 바뀌었어, 딴 데도 건드렸어?** (딴 데 건드렸으면 왜인지 물어라)
3. **파일이 비정상적으로 커졌어?** (play-test.html이 6,965줄 된 게 이걸 안 물어서 생긴 일)

**읽는 요령:** 초록 줄에서 3대 모양(`if`/`for`/이름)만 봐도 성격은 잡힌다. 계산 세부는 몰라도 된다.

**미니 시험** — 이 diff는 뭘 바꿨나?
```
- for (const keyword of SAFETY_KEYWORDS.block_high) {
+ for (const keyword of SAFETY_KEYWORDS.block_mid) {
```
> **정답:** 검사 대상 목록을 "고위험(block_high)"에서 "중위험(block_mid)"으로 바꿨다. (이러면 고위험 단어를 안 걸러서 위험할 수 있으니, 실제라면 "왜 바꿨어?"를 물어야 하는 신호다.)

# 10교시 — 실전 ②: 큰 파일 지도 그리기 + 졸업

**목표:** 6,965줄짜리 괴물도 안 무섭게.

**큰 파일 읽는 3단계 (처음부터 읽지 마라):**
1. **이름으로 검색(Ctrl+F):** AI가 말한 함수 이름을 파일에서 찾아 그 자리로 점프. **함수 이름 = 이정표.**
2. **들여쓰기로 목차 훑기(4교시):** 왼쪽 끝만 보며 "여기 한 뭉치, 저기 다음 뭉치".
3. **`function` 줄만 세기:** `function` 이 나오는 줄만 훑으면 **이 파일이 가진 기능 목록**이 나온다. (Ctrl+F로 "function" 검색)

**최종 검증 체크리스트 — AI가 "다 됐어요" 할 때:**
- [ ] 어떤 **함수/파일**을 바꿨는지 이름을 말하게 했다 (7교시)
- [ ] 바뀐 코드를 **전후(diff)로** 봤다, 요약만 믿지 않았다 (9교시)
- [ ] 초록 줄을 읽고 **새로 하는 일**을 내 말로 설명할 수 있다 (2·5교시)
- [ ] `{ }` **경계 밖**을 건드렸는지 확인했다 (4교시)
- [ ] 파일이 **얼마나 커졌는지** 숫자로 물었다 (9교시)
- [ ] 정말 도는지 **실행/화면으로** 확인했다 (읽기의 마지막 짝: 눈으로 봄)

**미니 시험(최종):** AI가 *"오염 계산 로직 좀 고쳤어요, 잘 돼요"* 라고만 했다. 위 체크리스트로 **되물을 질문 3개**를 직접 만들어보라.
> **정답 예:** ① "어떤 함수 안을 고쳤어? 이름 알려줘." ② "그 함수 `{` 부터 `}` 까지 전후로 붙여줘." ③ "ContaminationTracker.js가 몇 줄에서 몇 줄로 바뀌었어? 다른 함수도 건드렸어?"
