### terrain_layers 침묵 통과 실측 (핸드아웃 요구 — R6 scenes 패턴 재확인)

익명(anon) 키로 REST PATCH:

```
PATCH /rest/v1/terrain_layers?memory_id=eq.<mem>   body {"generation":999,"height_delta":{"hacked":[99]}}
→ HTTP 200, 응답 본문 []   (0행 영향 — 에러 없이 조용히 무시)

이후 익명 SELECT → generation=2 (Edge가 저장한 값 그대로, 999로 안 바뀜)
```

**확정**: RLS ON + write 정책 부재 → 익명 UPDATE는 매칭 행 0개로 필터되어 **200-0행으로 침묵 통과**한다(400/403이 아님). R6 때 scenes에서 발견된 패턴과 동일. 관객이 terrain_layers를 직접 조작하려 해도 조용히 씹히며, 실제 데이터는 Edge service_role 경로로만 바뀐다. 익명 SELECT(읽기)는 공개 정책으로 정상 허용.

### 2.1 record-erosion (봉인 시 변형층 저장 + 스냅샷)

입력 `{ memoryId, height_delta, foot_map, generation, snapshot? }`. service_role로 terrain_layers upsert + snapshot 있으면 Storage `terrain_snapshots/{memoryId}/{generation}.json`.

방어 상수:
- `MAX_BODY_BYTES = 512KB`(스냅샷 포함분) · `HEIGHT_SCALE = 20`(|델타 잎| 상한) · `PER_CELL_STEP = 10`(변화 예산 단위) · `MAX_LEAVES = 200000` · `MAX_SNAPSHOT_BYTES = 400KB`.
- height_delta/foot_map 은 **구조 불문 숫자 잎 전수 순회**로 검증(W1 serializeLayer가 어떤 격자 형태로 보내든 안전).

**익명 REST 공격/정상 6종 (mem_a=최근 play 있음, mem_b=play 없음):**

| # | 케이스 | 입력 요지 | 기대 | 실측 |
|---|---|---|---|---|
| E1 | 무플레이 | mem_b(play 없음), gen=1, 유효 델타 | 403 | **403** `no recent play for this memory` |
| E2 | generation 점프 | mem_a, gen=5 (서버 0) | 409 | **409** `generation must be 1 (server has 0)` |
| E3 | 범위 밖 | mem_a, height_delta 잎=25 (>20) | 400 | **400** `height_delta value out of range (\|v\| <= 20)` |
| E4 | 정상 | mem_a, gen=1, 델타 2셀 + snapshot | 200 | **200** gen1, cells 2, change 0.8/budget 20, **snapshot_saved:true** |
| E5 | 역행 | mem_a, gen=1 재시도 (서버 1) | 409 | **409** `generation must be 2 (server has 1)` |
| E6 | 예산 초과 | mem_a, gen=2, 델타 [20,20] (범위 내지만 Σ\|Δ\| 큼) | 400 | **400** `change budget exceeded (sum\|delta\| 39.2 > 20)` |
| E7 | 모르는 키 | mem_a, gen=2, 정상 델타 + `foo:"bar"` | 200 (무시) | **200** gen2 (foo 무시, 거부 아님) |

- E3(범위 검사)이 generation 검사보다 먼저 걸리는 것 정상(파싱 직후 잎 검증). E4에서 스냅샷 Storage 업로드까지 성공 확인.
- E7이 R3-2 판례("모르는 키는 거부가 아니라 무시") 준수 확인.

### 2.2 record-contact (유령 접촉 기록)

입력 `{ memoryId, sceneId, utterance, turn }`. service_role로 trajectory_bridges INSERT.

**trajectory_bridges NOT NULL·default 없음 컬럼 실측** = `memory_id`, `entry_emotion`. entry_emotion 은 접촉엔 감정 라벨이 없어 `'contact'` 로 채움(정본화 아님을 표식). key_passed_scenes default '{}', status default 'live' → **status='contact' 명시**(admin의 'live' 필터와 충돌 없음).

방어: 본문 4KB · UUID 2종 · scene 이 그 memory 소속 · 최근 180분 plays 존재 · utterance 500자 · 30분 내 중복 접촉 차단(회차당 1회 서버 보강).

**익명 REST 정상 1 + 공격 3종:**

| # | 케이스 | 입력 요지 | 기대 | 실측 |
|---|---|---|---|---|
| C1 | scene 불일치 | mem_a + scene_b(다른 memory 소속) | 403 | **403** `scene does not belong to this memory` |
| C2 | 무플레이 | mem_b + scene_b | 403 | **403** `no recent play for this memory` |
| C3 | 정상 | mem_a + scene_a + 발화 + turn | 200 | **200** `{ok:true, id:...}` (contact 행 생성) |
| C4 | 중복 | mem_a + scene_a 재시도 | 409 | **409** `contact already recorded for this session` |

### 2.3 generate-reveal 확장 (이본 명명 + 접촉 언어)

- 선택 입력 추가(하위호환): `variant_summary{alignment_avg, dominant_mismatch, fixation_level}`, `contact{occurred, scene_text?, utterance?}`. 없으면 기존 출력 그대로.
- variant_summary 가 오면 서사 끝에 **"이본(異本) 초상화" 한 단락** 지시 부착. **서열·평가·성공/실패 언어 금지**('잘했다/아쉽다/거의 도달/성공/실패/높은 정렬' 명시 금지). 우열이 아니라 성격만.
- contact.occurred=true 면 접촉을 **'성취'가 아니라 '일어난 사건'**으로 한 문장(utterance 인용 허용). ko/en 양쪽.
- R3가 넣은 입력 상한(MAX_BODY_BYTES 32KB, MAX_VISITS, MAX_TITLE) 보존. 신규 필드에도 타입·범위·상한(MAX_MISMATCH_CHARS 40, MAX_CONTACT_CHARS 300) 추가.
- 기존 규칙 4번의 서열 뉘앙스("정렬도 높으면 공명, 낮으면 균열")를 "공명과 균열은 점수·서열이 아니라 결(texture)로 표현"으로 순화.
- **"트루엔딩/true ending" 어휘: 프롬프트·예시에 부재 확인**(제거할 것 없음).

**실호출 3종 인용 (서열 언어 부재 눈 확인):**

- **R1 (구형 입력, visits만)** — 초상화 단락 없이 기존 서사만 출력(하위호환). 발췌: "…다리를 건너던 두려움의 감촉만을 손에 쥐고, 그 자리에 낯선 그리움의 흔적을 남겨둔 채 당신은 그 기억을 떠났습니다."

- **R2 (variant_summary)** — `---` 뒤 초상화 단락 등장. 발췌: "이 여정은 온전히 이어지기보다 군데군데 실이 풀린 이본으로 남았다. … 정렬의 결은 짙지도 옅지도 않은 흐린 안개처럼 걸쳐 있었으며 … 이 이본은 다리 하나를 사이에 두고 두 개의 얼굴을 가진 초상으로 … 남는다." → **서열/성공·실패 어휘 없음**, 성격 묘사로만.

- **R3 (variant_summary + contact.occurred)** — 접촉을 사건으로 언급. UTF-8 파일 전달분 발췌: "그 틈에서 누군가의 목소리가 들려왔습니다, \"우리 같은 걸 봤어\" — 그 말은 당신이 찾던 것과 비슷한 결을 가지고 있었지만, 완전히 같은 무늬는 아니었습니다." + 초상화: "이 여정은 하나의 이본으로 접혔습니다 — 깊이 파고들기보다 표면을 오래 매만진 판본 …" → **'거의 도달/마침내/해냈다' 없음**, '일어난 사건'으로 처리.

> 검증 하네스 주의: 첫 R3 호출에서 utterance 인용이 `�츮…`로 깨졌으나, 원인은 **Windows Git Bash가 커맨드라인 인수의 한글을 콘솔 코드페이지로 처리한 검증 하네스 아티팩트**였음. body를 UTF-8 파일(`--data-binary @file`)로 전달하면 완벽 인용됨(위 R3 발췌). 함수 자체는 문자열을 그대로 슬라이스해 프롬프트에 넣을 뿐, 인코딩 변환 없음. memory_title(한글)이 R1~R3 내내 안 깨진 이유는 LLM이 직접 인용 대신 재서술했기 때문.

## 5. 못 한 것 / 후속 필요

1. **W1 실측 재보정 대기 (구조적)** — 핸드아웃은 본문 상한·변화 예산을 "W1 시뮬 실측치×3"에서 정하라 지시했으나, 집필 시점 **W1(tem_variant_strata.js)이 아직 없음**(W1 보고서도 부재). 그래서:
   - `MAX_BODY_BYTES=512KB`: W1 스냅샷 목표 <150KB(설계 §4)의 ~3.4배 여유로 잠정.
   - `PER_CELL_STEP=10`(변화 예산 단위): HEIGHT_SCALE(20)의 절반으로 잠정. 정상 봉인(관객 1명 얕은 경로)은 이 상한 훨씬 아래이므로 "전 격자 대량 조작" 공격만 차단하는 넉넉한 값.
   - **W1 시뮬 500명 실측 완료 후 두 상수를 "실측치×3"으로 재보정 필요.** W1·W2는 원래 동시 진행 레인이라 예견된 상태.
2. **generation 규약 문서화 필요** — record-erosion은 "요청 generation === (기존행 있으면 stored+1, 없으면 1)"을 강제. 첫 봉인은 반드시 generation=1을 보내야 함. W4가 W1 `applyVisitorErosion().generation`을 이 규약에 맞춰 배선해야 함(0-기반이면 조정 필요).
3. **orphan 테스트 스냅샷 1개** — `terrain_snapshots/fb7742f1…/1.json`. storage.objects는 `protect_delete` 트리거로 SQL 직접 삭제 불가, service_role 키 부재로 Storage API 삭제도 보류(임시 anon delete 정책 시도했으나 anon에 테이블 GRANT 없어 403 → 정책은 즉시 제거함). 무해(삭제된 테스트 기억 참조, 비공개 버킷). 후속으로 service_role로 정리 권고.
4. **배선·목격 연출·접촉 게이트·옛 플래그 청소·e2e = W4 몫** (본 레인 범위 밖).
5. 변화 예산의 "직전 저장분과 Σ|Δ|"는 델타 잎 배열 길이가 같을 때만 element-wise 비교, 다르면 이번 델타 절대값 합으로 보수적 계산(격자 재정의 대비). W1 델타 직렬화가 세대 간 격자 크기를 고정하면 항상 정확 비교됨.
