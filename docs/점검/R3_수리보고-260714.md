### [R3-N1] `plays` 에 DELETE 정책이 없다 — admin 의 plays 삭제가 **조용히 0행 처리**된다

- **발견 경위**: R3-5 검증용 임시 행을 익명 REST 로 DELETE → **HTTP 204 인데 행이 그대로 남아 있었다.** RLS 가 DELETE 정책 부재를 에러 없이 "0행 삭제"로 통과시킨 것 — 7-13 봉인 도장 증발과 **완전히 같은 침묵 실패 패턴**.
- **파급**: `repo.js deleteMemoryGraph`(L407-433)와 `admin.js:4941`(nukeThenReseed 계열)이 plays 를 지우려 하지만 **실제로는 아무것도 안 지워진다.**
  → **L3-10 의 "고아 plays 24행 (삭제된 기억 10종의 잔재)"의 원인이 이것이다.** 기억은 지워지고 plays 는 남았다.
- **그런데 지금 고치면 안 된다**: 이 침묵이 현재 **우연한 안전망**으로 작동 중이다. DELETE 정책을 추가하는 순간 `nukeThenReseed()` 와 `deleteMemoryGraph` 가 **진짜로** plays 를 지우기 시작한다 — 마스터 취합의 ⚠️ 운영 경고가 경계하는 바로 그 파괴 경로다.
- **권고**: **R1 이 저작 파괴 연산을 고친 뒤**에 admin 전용 DELETE 정책을 별도 라운드로. 그 전까지는 고아 plays 24행을 SQL 로 직접 정리(service_role)하는 편이 안전.

수리 중 이 함수 응답에 깨진 글자(`U+FFFD`)가 섞여 나와 잠깐 버그로 의심했으나, **Git Bash 에서 curl 로 한글을 넘길 때 발생한 제 테스트 하네스의 인코딩 문제**였다. 본문을 UTF-8 파일로 넘기니 정상 한국어가 나온다. 앞으로 이 함수를 CLI 로 시험할 사람은 `--data-binary @file.json` 을 쓸 것.
