## 못 고친 것 + 이유

1. **`recoverScenesFromBackup`(repo.js)도 여전히 DELETE+INSERT** — 같은 CASCADE 위험이 있으나 백업 복구 도구(파괴가 목적에 가까움)라 diff 로 바꾸면 의미가 달라짐. 핸드아웃 수리 항목에도 없어 보존. 지휘 판정 요망: 이 함수도 diff 화할지, 경고 confirm 만 달지.
2. **plays.scene_id FK 의 ON DELETE CASCADE 자체** — R3 소유 (작업 트리에 `20260714000000_fk_no_cascade_on_scene_delete.sql` 초안이 이미 있음). diff 저장은 FK 와 무관하게 삭제 자체를 안 하므로 R3 적용 전에도 안전.
3. **기존 DB 에 문자열로 저장된 `original_emotion` 행 정규화** — DB 쓰기 금지 규칙. SELECT 로 스키마만 확인(emotion_dist/emotion_vector/scene_role 모두 nullable). 일괄 정규화는 R3 또는 Phase D 에서.
4. **is_seed "기억당 1개" 강제** — UI 안내 + 기본값까지만. DB 제약/저장 검증은 스코프 밖.
5. **브라우저 실검증** — R2 가 브라우저 단독 점유 중이라 규칙상 금지. admin 편집 → 저장 → plays 잔존 확인은 Phase D 에서 지휘 세션이.
6. **새로 발견한 것 (수리 안 함, 보고만)**:
   - `admin.js` 저장 후 로컬 `memoryData` 갱신 블록이 `interpretationLayers: 0` 으로 리셋함 — DB 는 이제 안 덮지만 화면 목록 표시값은 저장 직후 일시적으로 0 으로 보일 수 있음 (새로고침하면 정상). 🟢 수준.
   - `scenes.scene_role` DB 기본값이 `'anchor'` — 신규 씬을 "역할 없음"으로 저장하면 명시적 null 이 들어가 기본값과 다른 상태가 됨. 의도 확인 필요(🟢).
