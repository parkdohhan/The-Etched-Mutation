## 수리 항목 (순서대로)

### R1-1 (F1 🔴 최우선) saveMemoryGraph 파괴 저장 → id 보존 갱신
- 현재: `repo.js:163-185` 기존 choices·scenes 전부 DELETE 후 새 UUID 로 INSERT. `plays.scene_id` FK 가 ON DELETE CASCADE 라 **저장할 때마다 그 기억의 플레이 기록이 통째로 삭제돼 왔다** (지휘 실측 확정).
- 수리: diff 방식으로 교체 — ① 로드 매핑(`repo.js:43-68`)이 scene `id` 를 보존하는지 확인, 안 하면 추가. admin 쪽(`admin.js` currentScenes)이 그 id 를 저장까지 들고 오는지 사슬 전체 확인. ② 저장 시: id 있는 씬 = UPDATE, id 없는 씬 = INSERT, 목록에서 사라진 씬만 DELETE. choices 는 씬별 교체 유지해도 됨(choices CASCADE 는 선택지 데이터라 수용).
- 완료 기준: 모킹 단위 테스트 — 기존 id 가진 씬 3개를 저장하면 delete 가 호출되지 않고 update 3회가 호출됨을 assert. 실기억 검증은 지휘 세션이 Phase D 에서.
