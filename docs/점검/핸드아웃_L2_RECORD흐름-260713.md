## 이 코드베이스의 알려진 부패 패턴 (오늘 실제로 잡힌 것들)

1. **표기·키 불일치**: 감정 키셋(6축/12축/17축 혼재 — 특히 Record 산출물 vs 엔진 기대), stage 명,
   ko/en 분기 누락.
2. **빈 배열/null 의미 오판** (`[]` 를 미지정으로 폴백).
3. **진입점 누락 배선**: index.html 메뉴 → 실제 핸들러가 살아있는지 (RECORD 메뉴는 7-13 응급
   복구됨 — 같은 유형이 PLAY/ARCHIVE/PROFILE/PORTFOLIO 에 없는지).
4. **저장 경로 이중화**: Record 저장이 두 벌이다 — ritual 경로(saveConfessionToDB→repo.saveMemoryGraph)
   vs conversation 경로(saveRecordMemory→직접 insert). **두 경로의 필드 집합을 표로 대조**하라
   (meta/motif·object_tags, echo_words, void_info, text_stage_*, anchor_emotions, vector_weight…).
   한쪽에만 저장되는 필드 = 전부 보고.
5. **비로그인/로그인 분기**: 익명 저장(curator_id null), _pendingSave 보류 저장 흐름, 로그인 후
   복구가 실제로 이어지는지.
6. **하드코딩 플레이스홀더**, **죽은 코드**(live 계열이 메뉴에 없는데 로드·초기화되는 비용/부작용),
   **회차 경계에서 안 닦이는 상태**(record 세션 잔존물).
7. **prompt()/alert() 같은 원시 UI** 가 작품 톤을 깨는 자리 (saveConfessionToDB 의 prompt 등 — 존재 자체 보고).

## L2 전용 점검 항목

- [ ] **Record 파이프라인 전체 사슬**: 대화(recordChat) → [SCENE_COMPLETE] 추출 → 씬 생성 호출
      → 검토(showSceneReview) → 제목/동의 → 저장 → first play 자동 생성(_autoCreateFirstPlay)
      → 잔상 후보 수확. 각 고리의 실패 처리(LLM 실패, 네트워크, 401)와 유실 필드.
- [ ] **알려진 이슈 확인**: 씬 생성이 입력 내용(예: "자전거")을 무시하고 일반 묘사를 쓰는 문제 —
      conversationData 가 함수로 넘어가기 전에 이미 빈약한가(추출 단계 문제)  vs 프롬프트 문제인가
      경계를 코드로 판정하라.
- [ ] **safety.js**: 3계층 필터·시제 감지·에스컬레이션이 recordChat 와 dialog(phase1) 양쪽에
      실제로 물려 있는지. 한쪽만 물린 경우 보고.
- [ ] **archive**: 목록/검색(제목 기준)/맞춤 기억 찾기(motif 매칭) — Record 로 만든 meta 없는
      기억이 목록·매칭에서 어떻게 처리되는지.
- [ ] **endScreen/reveal**: generate-reveal 입력(visits/traces) 계약과 scene_link 폐기(7-09) 이후
      빈 문자열 흐름이 안 깨지는지.
- [ ] **profile**: 세션 기록·받은 메시지 — plays 봉인 도장 UPDATE 정책 수정(7-13)과 표시 정합.
- [ ] **i18n**: getCurrentLanguage 사용처 전수 — 한쪽 언어에서만 죽는 문자열 접근.
- [ ] **opening/진입 의례(7-13 신규 랜딩)**: 서가+암전 전환이 기존 흐름과 충돌하는 지점.
