## 🔴 핸드아웃 전제 정정 2건 (읽지 않고 넘기면 안 되는 자리)

### 정정 1 — depth 단조 가드를 "403 거부"로 하면 상영작 2/3 이 영구 차단된다

핸드아웃 R6-1 ④: *"요청 depth < 기존 depth 면 403 (오염 리셋 공격 차단)"*.

**실측:**

| 기억 | `memories.cont_depth` (DB) | play-test 가 보내는 depth | 403 되나? |
|---|---|---|---|
| 당신에게 | **30** | **4** (관객 판 3 + 이번 1) | **영구 차단** |
| 엘리베이터에서 | **8** | **1** (관객 판 0 + 이번 1) | **영구 차단** |
| 발자국 | 0 | 9 | 통과 |

두 수가 다른 건 버그가 아니라 **2026-07-09 결정**이다. play-test 는 상영작의 깊이를 "전시장에서 실제로 지나간 관객"(`persona_id` 없음 + `DEMO_EPOCH` 이후)만으로 센다(`play-test.html:4617-4632`·`4789-4803`). DB 의 30/8 에는 **AI 페르소나 193판**이 섞여 있고, 그걸 "앞사람의 흔적"으로 내보이면 작품이 주장하는 변형이 실재가 아니라 연출이 된다 — 그래서 세지 않기로 했다. 즉 **두 값은 서로 다른 좌표계**다.

**조치 — 거부도 덮어쓰기도 아닌 `max(기존, 요청)`:**
- depth 는 **절대 내려가지 않는다** → 핸드아웃이 막으려던 리셋 공격은 그대로 차단된다(실측: 9 → 1 요청 시 **9 유지**).
- 정상 관객이 막히지 않는다.
- 레거시 30/8 을 **파괴하지 않는다** (규칙 7 "직접 SQL 쓰기 금지"와도 정합 — 값을 정규화하려면 SQL 쓰기가 필요했다).
- 인플레이션은 따로 막는다: 요청 depth ≤ 그 기억의 plays 행 수 + 1 (실측: 999999 → **403**).

### 정정 2 — archive.js 생성 게이트를 그대로 이식하면 **한 글자도 생성되지 않는다**

핸드아웃 R6-2 ①: *"트리거 조건…그대로 이식 (재발명 금지)"*.

원본 게이트: `if (pres.stage === 'stable' || pres.intensity < 0.01) return;`

**실측 (브라우저, 발자국 진입 직후):**
```
cont_depth: 8      ← 관객이 8번 지나갔다
cont_stage: 'stable'
intensity : 0
```
→ **원본 게이트는 여기서 즉시 return.** 발자국은 영원히 판본을 못 갖는다.

원인은 **두 세계가 판본을 고르는 축이 다르다**는 것이다.

| | 판본 선택 축 | 생성 게이트 |
|---|---|---|
| index 셸 (archive.js + contaminationPresenter) | `stage` + `band` | `stage`/`intensity` — **자기 독자와 일치** |
| play-test (상영 경로) | **`depth`** (≥1 오염, ≥5 파편화, ≥15 키워드 붕괴) | 없었음 |

`applyStageText`(play-test.html:2324) 주석이 이미 이유를 적어뒀다 — *"drift 는 약 0.48 에 평평해지고 band 는 'strong'(0.67)에 끝내 닿지 않아, 관객이 120명 와도 text_stage_2·3 이 한 번도 표시되지 않았다"*. EMA 축은 "몇 사람을 거쳤는가"를 재는 양이 아니다.

**조치 — 게이트만 독자의 조건(`depth ≥ 1`)으로 바꾸고 나머지는 원본 그대로.** 프롬프트 인자, 덮어쓰기 금지, 백그라운드 실행, 씬 순회는 한 줄도 안 바꿨다.

### R6-2 🔴 오염 텍스트 자동 생성 — play-test 이식 — **완료**

| | |
|---|---|
| 전 | 유일한 생성기가 `archive.js` 죽은 구역의 고아(R5 "삭제 보류 1"). play-test 에는 생성 경로가 **아예 없어서** 5개 기억의 `text_stage_*` 가 영원히 빈 채였다 (L3-11 의 원인 규명). |
| 후 | `_generateStageTextsInBackground` 를 play-test 봉인 블록으로 이식. 회차당 **3씬 상한**. |

**RLS 실측 (핸드아웃이 요구한 기록):**

| 대상 | 익명 UPDATE 결과 |
|---|---|
| `memories` | **HTTP 401** — `new row violates row-level security policy` |
| `scenes` | **HTTP 200 인데 0행** ← 에러조차 안 난다. **조용한 차단** |

> `scenes` 쪽이 더 위험하다. 정책은 admin/curator 만 UPDATE 를 허용하는데(`pg_policy` 확인), 익명 요청은 **에러 없이 0행으로 통과**한다 — R3-N1 이 지적한 `plays` DELETE 침묵과 **완전히 같은 패턴**이다. 클라이언트가 직접 썼다면 "저장했다"고 믿으며 아무것도 안 남았을 것이다.

→ 핸드아웃 지시대로 `contaminate-text` 에 **선택적 `persist: { sceneId, memoryId }`** 를 추가해 서버가 생성 직후 직접 쓴다. **방어 4겹**: sceneId/memoryId UUID · **scene 이 그 memory 소속인지** · 최근 플레이 존재 · **이미 값이 있으면 덮어쓰기 금지**. R3 의 입력 상한·화이트리스트(v18)는 그대로 보존.

**실증 — 브라우저 2회차 (발자국, `text_stage` 전부 null 이던 기억):**

| 회차 | 콘솔 | 결과 |

| 2회차 봉인 | 같은 로그 | 씬 **3·4·5** 집필 — **0·1·2 는 건드리지 않음** |

`stage=stable` 인데도 생성이 돌았다는 것이 **정정 2의 실증**이다(원본 게이트였다면 로그 자체가 안 찍힌다).

## 🔴 수리 중 발견 (이번 범위 밖 — 지휘 판단 필요)

### [R6-N1] `contaminate-text` 의 juxtaposition 모드가 `text_stage_2` 에 **JSON 덩어리**를 넣는다

```ts
const parsed = match ? JSON.parse(match[0]) : null;
return { text_stage_1: parsed?.variant_biased || raw,
         text_stage_2: raw,                              // ← 모델의 원 출력 = JSON 문자열 통째
         text_stage_3: parsed?.variant_hyper || raw };
```
프롬프트가 `{"variant_biased": …, "variant_hyper": …}` JSON 을 요구하므로, `text_stage_2` 에는 **중괄호가 그대로** 들어간다. 독자 화면에 JSON 이 찍힌다.

- **누가 타나**: admin 레거시 호출(`stage: 2` → `legacyToV2` → `juxtaposition`). `ContaminationTracker` 는 이 stage 를 만들지 않으므로 관객 경로는 안 탄다.
- **현재 피해 0** — 당신에게의 `text_stage_2` 7개는 작가가 쓴 정상 산문이다(확인함).
- **이번 조치**: 고치지 않았다(사용자 지시 "핸드아웃 지시만"). 대신 **persist 를 이 경로에서 거부**해 서버가 DB 에 JSON 쓰레기를 굽는 일만 막았고, 코드에 `KNOWN BUG` 주석을 남겼다.

### [R6-N2] 자동 생성 판본의 결이 작가 판본과 다르다 — **작가 판단 필요**

DB 의 작가 판본은 **붕괴 사다리**다: `stage_1` 단어 빠짐 → `stage_2` 문장 파편화 → `stage_3` 키워드만 (`"죽었습니다."`). play-test 의 depth 사다리와 정확히 맞물린다.

그런데 `contaminate-text` 의 프롬프트는 **기울임/과잉완결**(20~40% 변형, 확신↔불확실)이다 — 붕괴가 아니다. 이식한 생성기가 만드는 판본은 작가의 결과 다르다(위 발자국 예시).

프롬프트를 고치는 것은 **연출 결정**이라 손대지 않았다. 선택지: ① 현행 유지(AI 판본 = 작가 판본보다 약한 폴백) ② 붕괴 사다리용 프롬프트 신설 ③ 자동 생성은 초안으로 두고 작가가 덮어쓰기. **②를 고르면 `depth` 별 프롬프트 3종이 필요하다.**
