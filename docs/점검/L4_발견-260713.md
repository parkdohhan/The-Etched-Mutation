## 심각순 발견

### [L4-01] 🔴 편집화면 [저장] = 씬 전멸 후 재삽입 → 씬 ID 전면 교체 → 참조 연쇄 붕괴

- 파일: `js/admin.js:2263` (saveMemory → saveMemoryGraph) → `js/lib/repo.js:163-185`, `js/lib/repo.js:266-292`
- 증상: 기존 기억을 저장하면 `UPDATE` 가 아니라 **그 기억의 choices 전부 DELETE → scenes 전부 DELETE → 새로 INSERT** 한다. 새 씬은 **새 UUID** 를 받는다.

```js
// repo.js:170-185 — 기존 씬을 통째로 지운다
if (existingScenes && existingScenes.length > 0) {
    await client.from('choices').delete().in('scene_id', sceneIds);
    await client.from('scenes').delete().eq('memory_id', finalMemoryId);   // ← 전멸
}
// repo.js:288 — 그리고 새 id 로 다시 만든다
const { data: sceneData } = await client.from('scenes').insert(insertData).select().single();
```

- 영향 (작가가 겪는 일): 제목 오타 하나 고치고 [저장] → 겉보기엔 정상. 그런데 그 순간
  1. **`utterances.scene_id` → NULL** (`supabase/migrations/20260409000000_create_utterances.sql:28` 이 `ON DELETE SET NULL`). 그 씬에 달렸던 잔상 발화가 씬과의 연결을 잃음.
  2. **`meta.trajectory_targets` 가 죽은 ID를 가리킴.** 핀 모드 분기는 **씬 UUID 목록**으로 저장되는데(`admin-trajectory.js:2569`), 저장 후 그 UUID들은 존재하지 않는 씬이다. `SceneNavigator.js:56` 이 이 목록을 후보로 쓰므로 → **후보 0 → fallback 경로로 전락**. 작가가 Canvas에서 공들여 그린 분기 구조가 편집화면 저장 한 번에 무효가 된다.
  3. `trajectory_bridges.scene_id`(공명 브릿지), 페르소나 `plays.scene_id` 도 같은 씬을 못 찾음.
- **plays 연쇄 삭제 의혹 (Phase B 확인 요청)**: `plays.scene_id` 의 FK 삭제 규칙이 저장소 마이그레이션에 없다(CLI 추적 이전 생성). L3 보고서 [L3-10]이 센 **`plays.scene_id IS NULL` 34행**은 `ON DELETE SET NULL` 로 잘려나간 흔적과 정확히 일치한다. **`information_schema` 한 줄 SELECT 로 확정 필요** — 만약 `CASCADE` 라면 편집 저장이 그 기억의 플레이 기록을 통째로 지워온 것이고, "플레이 기록 6개월 증발"의 진범이 된다.
- 확신: 씬 DELETE+INSERT 와 targets 무효화는 **확실**(코드 직접 확인). plays 연쇄는 **유력**(FK 규칙 미확인).

// repo.js:242-254 — choices 가 없으면 전부 0 인 8축 벡터가 만들어지고
const emotionDist = { fear:0, sadness:0, guilt:0, anger:0, longing:0, isolation:0, numbness:0, moralPain:0 };
if (scene.choices && scene.choices.length > 0) { /* ... */ }
// repo.js:318-333 — 그 0벡터로 emotion_vector 까지 덮어쓴다

### [L4-04] 🔴 Canvas 씬 저장이 17축을 8축으로 잘라냄 + `original_emotion` 을 문자열로 이중 저장

- 파일: `js/admin-trajectory.js:2054` (EMO_KEYS 8개), `js/admin-trajectory.js:1962-1968`
- 증상: Canvas 우측 "씬 편집" 패널의 감정 입력은 8축(`fear, sadness, anger, guilt, shame, longing, numbness, isolation`)뿐이다. 저장 시 그 8축 객체로 `original_emotion` 을 **통째 교체**한다.

```js
const EMO_KEYS = ['fear','sadness','anger','guilt','shame','longing','numbness','isolation']; // 8
await sb.from('scenes').update({
  emotion_dist: emo, emotion_vector: emo,
  original_emotion: JSON.stringify(emo),   // ← 17축이 8축으로 잘림 + jsonb 에 문자열로 박힘
})
```

- 영향: 엔진 판단축은 17축(`js/shared/math.js:20` DEFAULT_EMOTION_ANCHORS)인데 Canvas 로 씬을 한 번 저장하면 **`moral_pain, helplessness, despair, joy, hope, relief, gratitude, love, peace, comfort` 10축이 소멸**한다. 편집화면(17축 picker)과 Canvas(8축)가 같은 컬럼을 서로 다른 스키마로 덮어쓰는 **이중 편집 충돌**. 게다가 `JSON.stringify` 로 넣어 jsonb 안에 문자열이 들어간다(L3 [L3-10]이 센 "문자열 original_emotion 26행"의 생산자 중 하나).
- 확신: 확실.
