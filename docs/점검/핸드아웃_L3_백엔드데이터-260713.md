## 알려진 부패 패턴 (오늘 실제로 잡힌 것들)

1. **은퇴/구식 모델명**: 7-13에 sonnet-4 계열 전면 교체됨 — 잔재가 남았는지 12개 함수 전수
   grep (`claude-3`, `claude-sonnet-4`, `claude-opus-4` 등 하드코딩 전부 목록화 + 현재 유효 여부).
2. **배포본-저장소 드리프트**: `get_edge_function` 으로 배포 소스를 받아 repo 파일과 대조.
   12개 전부. 다르면 어느 쪽이 최신인지 판정 근거와 함께 보고. **(7-13 사후 확인: 배포는
   L3 단독 권한인데 다른 세션이 배포한 이력 있음 — 드리프트 가능성 높음)**
3. **조용한 실패**: RLS/정책 때문에 insert/update 가 0행으로 조용히 끝나는 자리 (plays 봉인
   도장이 6개월 증발한 그 패턴). 프론트가 쓰는 모든 쓰기 경로(테이블별)와 RLS 정책을 대조표로.
4. **응답 계약 불일치**: 함수가 반환하는 JSON 필드 vs 프론트가 읽는 필드 (`resp.data.ok`,
   `analysis.base` 12축 vs 17축 등). 함수별로 "반환 스키마 / 소비자 기대" 표.
5. **키셋 혼재**: claude-scene emotion_extract 는 12축? 엔진은 17축? 어디서 변환되는지 추적.
6. **CORS/인증 비대칭**: verifyAuth 필수인 함수 vs 익명 허용 함수 — 프론트 호출부와 일치하는지.
7. **마이그레이션 정합**: `list_migrations`(적용됨) vs `supabase/migrations/`(저장소) 대조.
   저장소에만 있고 미적용, 또는 적용됐는데 저장소에 없는 것.
