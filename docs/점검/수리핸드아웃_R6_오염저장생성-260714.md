# 수리 핸드아웃 R6 — 오염 사슬 마지막 두 마디 (저장 영속화 + 텍스트 자동 생성)

> Phase C 후속 단독 레인. 판정 근거: docs/점검/PhaseB_마스터취합-260714.md v1.1 "남은 🔴 2건"
> + R2_수리보고(R2-3b RLS 차단 실측) + R3_수리보고(방어 패턴 원본) + R5_수리보고(보류 1번 = 생성기 참조 구현).
> 미션: R2가 복원한 오염 사슬(입력→계산→표출)에 빠져 있는 **저장**과 **연료 생산**을 잇는다.
> 이 레인이 끝나면: 봉인한 오염이 DB에 남아 다음 관객에게 누적되고, 오염 텍스트가 플레이 중 자동으로 집필된다.

## 절대 규칙

1. **내 구역**: `supabase/functions/**`(배포 권한 포함), `play-test.html`. 참조 읽기: `js/app/archive.js`(고아 생성기), `js/app/contaminationPresenter.js`, `js/core/ContaminationTracker.js` — **읽기만, 수정 금지**.
2. 배포 전 현 배포본 백업(`get_edge_function` → scratchpad). verify_jwt 는 R3 판례를 따른다: 익명 관객 경로면 false 유지 + **함수 내부 방어**가 실질 (R3-2 참조. MCP 배포가 verify_jwt 를 true 로 켜버리면 CLI `--no-verify-jwt` 로 복원할 것).
3. 마이그레이션 불요 예상 — 필요해지면 저장소 파일과 함께 (R3 규칙 2).
4. **브라우저(MCP playwright) 허용** (현재 단독). 실증 없이 "완료" 선언 금지.
5. 커밋 접두어 `fix(R6):`. PowerShell 커밋 메시지 큰따옴표 금지. `npm test` 회귀 확인 (현재 기준 22파일 564개).
6. 보고서: **`docs/점검/R6_수리보고-260714.md`**.
7. DB 쓰기는 Edge Function 경유 검증만. 직접 SQL 은 SELECT 만.

## 수리 항목

### R6-1 🔴 오염 cont_* 저장 — Edge Function 경유

- 현재: 봉인 시 `game.contState` 갱신은 되는데(R2-3a) `memories` UPDATE 가 anon RLS 401 (R2-3b 실측). play-test 에 R2 가 남긴 `console.error('[contamination] memories UPDATE 실패 …')` 지점이 배선 자리다.
- 수리: **신규 함수 `record-contamination`** (record-drift-cumulative v5 를 골격으로 복제 — 방어 패턴 재사용):
  1. 본문 8KB 상한, `memoryId` UUID 검증
  2. **그 기억에 최근 180분 내 plays 행 존재** (플레이 없이 오염만 밀어넣는 호출 차단)
  3. 허용 컬럼 화이트리스트만 통과: `cont_depth`(정수), 3축·drift·fixation·stage_weights·last_alignment 등 [0,1] 유한수, Welford `_cont_align_mean/m2` 유한수, `cont_last_mismatch` 어휘 화이트리스트(emotion_mismatch/attribution_mismatch/target_displacement/void_mismatch/vague/none), `drift_dir_v/a` [-1,1]
  4. **`cont_depth` 단조 증가 가드**: 요청 depth < 기존 depth 면 403 (오염 리셋 공격 차단)
  5. service role 로 `memories` UPDATE — **화이트리스트 컬럼만** 조립 (본문의 다른 키 무시)
- play-test 봉인 블록: R2 의 실패 지점을 이 함수 호출로 교체. 실패 시 여전히 `console.error` 크게 (조용한 실패 금지).
- 보낼 필드 목록은 `ContaminationTracker.js` 의 상태 스키마를 읽고 확정할 것 (16개 안팎 — 추측 금지, 실제 키 확인).
- 완료 기준(실증): 브라우저에서 회차 봉인 → SELECT 로 `cont_depth` 증가·`cont_last_mismatch` 반영 확인. 익명 REST 로 공격 4종(무플레이/depth 감소/범위 밖/모르는 컬럼) 전부 거부 확인.

### R6-2 🔴 오염 텍스트 자동 생성 — play-test 이식

- 현재: 유일한 생성기 `archive.js` 의 `_applyContaminationAtEnd` + `_generateStageTextsInBackground` 가 죽은 구역의 고아 (R5 보고서 "삭제 보류 1" — 역사적으로는 MM23L 10/11 씬을 채운 실적 있는 코드). play-test 에는 생성 경로가 아예 없어서 **5개 기억의 text_stage 가 영원히 빈 채**로 남는다 (L3-11).
- 수리:
  1. archive.js 원본을 **읽고** 트리거 조건(어느 depth/stage 에서 어느 판본을 만드는지)·프롬프트 인자·캐시 규칙을 그대로 이식 (재발명 금지 — 검증된 규칙이다).
  2. play-test 쪽 트리거 자리: 대화 씬 종료(`onSceneEnd` 이후) 또는 봉인 시, **text_stage 가 비어 있고 오염 단계가 요구하는 씬**에 한해 백그라운드 생성. 회차당 생성 수 상한(예: 3씬)으로 크레딧 폭주 방지.
  3. 쓰기 경로: scenes UPDATE 도 curator 있는 기억은 anon RLS 에 막힐 것 — **먼저 실측**하고, 막히면 `contaminate-text` 에 선택적 `persist: {sceneId}` 를 추가해 서버가 생성 직후 직접 쓴다 (방어: sceneId 가 그 memoryId 소속인지 + 최근 플레이 존재 + **이미 값이 있으면 덮어쓰기 금지**). R3 가 넣은 입력 상한·화이트리스트(v18)는 보존.
  4. 생성 완료가 현재 회차 화면에 즉시 반영될 필요는 없음 (다음 방문자용 연료 — 원본 설계와 동일).
- 완료 기준(실증): text_stage 전부 null 인 기억(발자국 등, L3-10 표 참조)을 브라우저로 플레이·봉인 → SELECT 로 해당 씬 text_stage_N 채워짐 확인 + 이미 값 있는 씬은 불변 확인.
