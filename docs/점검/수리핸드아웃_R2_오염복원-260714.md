# 수리 핸드아웃 R2 — 오염 사슬 복원 (play-test 런타임)

> Phase C 수리 5레인 중 R2. 판정 근거: docs/점검/PhaseB_마스터취합-260714.md (줄기 A + E 일부) + L1_발견-260713.md.
> 미션: **오염 시스템의 끊긴 네 마디(입력→계산→저장→표출)를 다시 잇는다.** 이 레인이 끝나면 관객이 원본과 다른 감정으로 플레이할 때 오염이 실제로 쌓이고, 오염된 기억의 텍스트가 화면에서 붕괴한다.

## 절대 규칙

1. **내 파일만 수정**: `play-test.html`, `js/core/ContaminationTracker.js`, `js/ui/**`. 그 외(js/shared, js/app, admin, supabase)는 읽기만 — 문제는 보고서에.
2. **배포·마이그레이션 금지.** DB는 SELECT + **R2-3 검증에 한해 memories cont_* UPDATE 시도 1회 허용** (실패해도 롤백 불요 — 0행이면 그 자체가 발견).
3. **브라우저(MCP playwright)는 5레인 중 R2만 허용** (단독). 단 브라우저가 좀비 되면: mcp-chrome 프로세스 kill + SingletonLock 삭제. 캐시 착시 주의 — 하드 리프레시.
4. 커밋 접두어 `fix(R2):`. PowerShell 커밋 메시지에 큰따옴표 금지.
5. `npm test` 회귀 확인. vite.config 수정 금지(R4).
6. 보고서: **`docs/점검/R2_수리보고-260714.md`**.
7. 스코프 밖 리팩터링 금지.

## 수리 항목 (반드시 이 순서 — 순서 자체가 안전장치다)

### R2-1 (A6 🔴 제일 먼저) band 지뢰 제거
- `play-test.html:2345-2360`: `const { stage, intensity } = pres;` 인데 아래에서 미선언 `band` 참조 → strict mode ReferenceError. `getPresentationState` 출력에 band 가 있으면 구조분해에 추가, 없으면 intensity 로 band 도출(`>=0.66 strong / >=0.33 medium / weak` 식 명시적 규칙). **이걸 먼저 안 고치면 R2-5 가 켜지는 순간 씬 진입이 터진다.**

### R2-2 (A2 🔴) mismatch 어휘 매핑
- 대화 경로는 `mismatch_type` 자리에 `resonance|vague|dissonance` 를 기록(play-test.html:3338)하는데 `ContaminationTracker.MISMATCH_BONUS`(41행)엔 그 단어가 없어 항상 0.
- 수리: Tracker 에 `normalizeMismatch()` 추가 (normalizeStage 전례를 따를 것 — f2bce54): `dissonance→emotion_mismatch(1.0)`, `vague→0.5(신규 키 vague 로 표에 추가)`, `resonance→none(0.0)`. updateContamination 과 replayFromPlays 양쪽 입구에서 통과시키기.
- 단위 테스트 추가: 'vague' 입력 시 mismatchBonus > 0.

### R2-3 (A4 🔴) 봉인 시 오염 갱신 + 저장
- (a) 필수: 대화 경로(onSceneEnd)가 `game.lastResult` 를 채우지 않아 봉인 블록(play-test.html:4977)이 통째로 스킵됨. 대화 씬 종료마다 세션 집계를 쌓아 봉인 시 `updateContamination` 이 실제로 돌게 배선.
- (b) 시도: 갱신된 `game.contState` 의 cont_* 컬럼(3축 + depth + Welford `_cont_align_mean/m2` + stage_weights 관련)을 `memories` 에 UPDATE. **주의: RLS 상 anon 이 curator 있는 기억을 UPDATE 못 할 가능성이 높다.** UPDATE 후 반환 행 수를 확인해서 0행이면 — 고치려 들지 말고 **보고서에 "RLS 차단 확인, R3/지휘 협의 필요"로 기록**. (조용한 실패를 만들지 말 것 — 이번 점검의 주제가 그것이다.)

### R2-4 (A5 🔴) replayFromPlays 의 fixation_level=0 고정
- `ContaminationTracker.js:374`: plays 의 `user_emotion` 궤적으로 `calculateFixationLevel`(js/shared/math.js — **호출만, 수정 금지**)을 계산해 넣기. 이러면 Stage 3 도달 불가(상한 0.45<0.65) 산술이 풀린다.
- 단위 테스트: 동일 감정 반복 plays 를 넣으면 fixation 이 임계 초과 가능함을 assert.

### R2-5 (A1 🔴) 오염 텍스트를 대화 경로에 표출
- 설계(확정, 최소 수정): `play-test.html:3378` 분기에서 `_enterLumenDialogPhase1(pin, scene)` 호출 **직전에** `applyStageText(scene.text, scene, game.contPresentation)` 로 오염 판본을 계산하고, `{...scene, text: 오염판본}` 사본을 넘긴다. **lumen_dialog_phase1.js 내부는 최대한 무수정** (본문 소스가 sceneData.text 하나라 사본 전달로 충분).
- `getMonologue`(혼잣말)는 이번에 이식하지 말 것 — 대화 UI 에 자리 설계가 필요. 보고서에 후속 항목으로만.
- 검증(브라우저): "당신에게"(MM23L, text_stage 10/11 채워짐)로 진입해 stage 텍스트가 실제로 뜨는지. 오염 낮은 기억은 원문 그대로인지.
