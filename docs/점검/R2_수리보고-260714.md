## 한 줄 결론

**작가가 쓴 오염 판본이 처음으로 독자에게 도달했다.** 그리고 대화로 플레이해도 오염이 실제로 쌓인다.
다만 **저장은 RLS 에 막혔다** — 고치지 않고 기록한다(R2-3b, 아래 참조).

### R2-3 🔴 봉인 시 오염 갱신 + 저장

#### (a) 갱신 배선 — 완료

| | |
|---|---|
| 전 | 봉인 블록의 진입 조건이 `if (game.lastResult && game.contState)`. 그런데 `game.lastResult` 는 **고전 감정 제출 경로에서만** 채워진다(play-test.html:4143). 상영 경로인 **대화 플레이는 엔진을 안 거치므로 끝내 `null`** → **봉인 블록이 통째로 스킵** → 오염이 한 번도 갱신되지 않았다. |
| 후 | 회차 시작 시 `game.dialogSession = { alignments, mismatches, emotions }` 를 비우고, 대화 씬이 끝날 때마다 쌓는다. 봉인 시 `buildSessionEngineOutput()` 이 **두 경로를 모두** V4 형태로 환산한다. |

환산 규칙 (정직하게):
- `level` = 씬별 정합도의 **평균** — V4 §2 정의 그대로.
- `shape` = **미측정.** 대화 경로는 궤적 델타를 산출하지 않는다. `0` 으로 채우면 *"궤적이 정반대"* 라는 거짓말이 되므로 **`shape_active: false`** 로 미측정임을 선언한다 (Tracker 가 `effectiveShape=1.0` 으로 중립화 → shape 항이 오염을 밀지 않는다).
- `fixation_level` = 세션 감정 이력으로 **실측** (`calculateFixationLevel`).
- `mismatch_type` = 세션의 지배적 어긋남 (`getDominantMismatch` 재사용 → R2-2 가 접어준다).
- 드리프트 방향 = 대화 경로는 `emotionCursor` 를 안 굴리므로 마지막 감정벡터를 `projectEmotionToVAD` 로 투영 (`replayFromPlays` 가 과거 판에 쓰는 **같은 함수 = 같은 좌표계**).
- `transition_pattern` = `'bridge'` 고정 — **이번 라운드 범위 밖** (후속 항목 참조).

**검증 (브라우저, 실기):** "당신에게" 회차에 대화 3씬 분량을 넣고 봉인 —

| `cont_drift` | 0.0092 | **0.0526** |
| `cont_fixation` | 0.0797 | **0.1305** |
| `cont_last_alignment` | — | **0.46** (= (0.62+0.41+0.35)/3, 정확) |
| `cont_last_mismatch` | — | **`emotion_mismatch`** (대화 어휘가 접힘) |
| `drift_dir_v` | — | **−0.042** (슬픔 방향) |

#### (b) DB 저장 — **RLS 차단 확인. 고치지 않음.**

`game.contState` 의 cont_* 16개 컬럼(3축 + depth + Welford `_cont_align_mean/m2` + stage 혼합 + last_*)을 `memories` 에 UPDATE 시도.

**결과: 401 / RLS 정책 위반.**
```
Failed to load resource: 401
  https://…supabase.co/rest/v1/memories?id=eq.c291e1aa…&select=id
[contamination] memories UPDATE 실패 —
  new row violates row-level security policy for table "memories"
  | 오염이 저장되지 않았다. RLS 확인 필요 (R3/지휘).
```

핸드아웃 지시대로 **고치려 들지 않았다.** 다만 **조용한 실패를 만들지 않았다** — 실패·0행·예외 세 경우 모두 `console.error` 로 크게 남긴다. (이번 점검의 주제가 조용한 실패였다.)

> **지휘/R3 협의 필요:** anon 키로는 `memories` UPDATE 가 불가능하다. 선택지는
> ① cont_* 컬럼에 한정한 RLS UPDATE 정책 추가, 또는 ② service role 로 쓰는 Edge Function 경유.
> **이 결정이 나기 전까지 오염은 여전히 회차마다 소멸한다** (명세 `contamination_mvp_spec_v3` §14-7 이
> 4개월째 미완료로 남겨둔 바로 그 자리).

### R2-4 🔴 replayFromPlays 의 fixation 실측 — 완료

| | |
|---|---|
| 전 | `fixation_level: 0` **하드코딩** (`// not available in play records`). 그 탓에 `fixSignal` 상한이 `0.55×0 + 0.25 + 0.20 = 0.45` 로 묶여 **hypercompletion 문턱 0.65 에 산술적으로 닿을 수 없었다** (L5-05). 실제 플레이가 타는 유일한 경로가 이것이므로, **Stage 3(과잉완결)이 관객 플레이로는 절대 발생하지 않았다.** |
| 후 | 판 기록에 `user_emotion` 이 **있다**. fixation 은 정의상 "같은 감정, 또"(V4 §5)이므로 **근사가 아니라 실측**이다. 재생하며 감정 이력 창을 굴려 `calculateFixationLevel` 을 호출한다. |
| 검증 | 단위 테스트 4개 신규 — 같은 감정 60판 → `cont_fixation > 0.65` **및 `cont_stage === 'hypercompletion'`** (옛 동작으로는 통과 불가능한 단언). 감정이 매번 다르면 낮게 남고, `user_emotion` 없는 판이 섞여도 안 터진다. |

### R2-5 🔴 오염 텍스트를 대화 경로에 표출 — 완료 (이번 수리의 본체)

| | |
|---|---|
| 전 | 고전 씬 UI 는 `applyStageText` 를 거치는데(renderScene), **상영 경로인 대화 UI 는 `scene` 을 날것 그대로 넘겼다.** 그래서 작가가 집필한 `text_stage_1/2/3` 이 DB 에 있어도 **단 한 번도 독자에게 도달한 적이 없다.** |
| 후 | 대화 진입 직전 `applyStageText(scene.text, scene, pres, { plain: true })` 로 오염 판본을 계산하고 `{...scene, text: 오염판본}` **사본**을 넘긴다. `lumen_dialog_phase1.js` **무수정**. |

**설계 판정 하나 — 핸드아웃이 놓친 함정:**
`applyStageText` 는 두 종류를 반환한다. 작가 판본은 **평문**이지만, 판본이 없을 때의 클라이언트 폴백은 **`<span class="cont-word">` 가 섞인 HTML** 이다. 그런데 대화 UI 는 본문을 **`textContent` 로 한 글자씩 타이핑**한다(`lumen_dialog_phase1.js:332`) → HTML 을 그대로 넣으면 **화면에 `<span class=…>` 가 날것으로 찍힌다.**

그래서 `applyStageText` 에 **평문 모드(`opts.plain`)** 를 추가했다. 침식 문자(`·`)·글리치·에코는 원래 평문이라 껍데기만 벗기면 그대로 쓸 수 있고, **RNG 호출 순서가 같아 두 모드의 오염 자리는 동일**하다. **고전 경로 출력은 한 글자도 안 바뀐다**(`opts` 없으면 `plain=false`).

**검증 (브라우저, 실기 — "당신에게" / `depth=3`):**

대화 UI 가 실제로 받은 본문을 가로채 비교:
```
matchesStage1 : true      ← 작가 판본과 일치
matchesOriginal: false    ← 원문이 아님
isCopy        : true      ← 사본 전달 (scene 원본 불변)
hasHtmlTag    : false     ← 태그 안 샘
```
| | |
|---|---|
| 원문 | 엄마에게 투정을 부리**거나 매달리는** 엄마의 모습이… 그런 식으로 **엄마에게** 달라붙어본 적이 없었는데… 하는 **쓸모**… |
| 화면(판본) | 엄마에게 투정을 부리는 엄마의 모습이… 그런 식으로 달라붙어본 적이 없었는데… 하는 **결론에 미끄러지곤 했습니**… |

**단어가 빠지고 뜻이 밀렸다.** 스크린샷으로 유령이 이 문장을 말하는 것까지 확인.

오염 낮은 기억(원문 유지) 확인: `depth <= 0` 이면 `applyStageText` 가 원문을 그대로 돌려준다(최초 목격자 규칙, 기존 로직). 이번 회차의 세 기억 중 depth 0 인 것이 없어 **실기로는 미확인** — 로직상으로만 확인.

## 못 고친 것 · 후속 필요

1. **🔴 오염 저장 (R2-3b) — RLS 차단.** 지휘/R3 결정 필요. 이게 풀리기 전까지 **오염은 여전히 회차마다 소멸**하고, 다음 관객은 `plays` 행에서 근사 재계산(`replayFromPlays`)만 받는다. R2-4 로 Stage 3 도달 산술은 풀렸지만, **저장이 안 되면 EMA·Welford 내부 상태는 계속 유실**된다.
2. **🔴 `transition_pattern` 궤적 산출** — 이번 라운드 제외(핸드아웃 명시). 대화 경로는 여전히 `'bridge'` 고정. 다만 L5 감사에서 밝혀진 더 깊은 문제가 있다: **엔진 자체가 패턴을 궤적이 아니라 bucket 에서 파생**시키고 있어(L5-06), 배선을 이어도 대부분 `bridge` 가 나온다. **배선 문제가 아니라 엔진 설계 문제** — R4/지휘 판단 필요.
3. **🟡 혼잣말(`getMonologue`) 이식** — 대화 UI 에 자리 설계가 필요해 이번에 안 넣음(핸드아웃 지시).
4. **🟡 `applyStageText` 폴백의 medium 이 사실상 안 보인다** — L5-16 에서 지적한 확률 문제(짧은 문장에서 medium 10% 는 거의 안 걸림). 이번엔 안 건드림. 작가 판단 필요(폴백은 어차피 "초라한" 임시물이고, 정공법은 모든 씬에 `text_stage_*` 를 채우는 것).
5. **🟡 `play-test.html` 의 인라인 사본** — `calculateFixationLevel`(2202줄)·`cosineSimilarity`(1161줄)가 `js/shared/math.js` 와 **중복 존재**한다. 실제로 이번에 `math.js` 에서 import 하려다 **이름 충돌로 모듈 전체가 SyntaxError** 나는 것을 잡았다(node --check 로 발견 — **vitest 는 이걸 못 잡는다**). 내용은 현재 동일하나 갈라지면 조용히 어긋난다. `별이엔진_단일화_베이스라인-260518` §후속이 예고한 바로 그 자리. **R4 정리 대상으로 넘긴다.**
6. **원문 유지(depth 0) 실기 미확인** — 세 기억 모두 depth > 0 이라 확인 못 함. 로직상으로만 확인.
