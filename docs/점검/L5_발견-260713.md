## 발견 (심각순)

### [L5-01] 🔴 감정이 그대로인 플레이는 정렬도가 **0점**이 된다 — 영벡터 코사인

- 파일: `js/shared/math.js:270~282` (`cosineFlat`) → `:287~299` (`calculateShapeSimilarity`)
- 증거: `test/unit/__snapshots__/pipeline.regression.test.js.snap:862~877`

**증상:** 체험자가 장면마다 **같은 감정을 유지**하면 감정 변화량(delta)이 전부 0이 된다. 원본도 같은 감정이면 원본 delta 역시 0. 두 궤적은 **완벽히 일치**하는데, 코사인 유사도 함수가 영벡터를 만나 **0을 반환**한다. `alignment = level × shape` 이므로 **최종 점수가 0점**이 된다.

**근거:**
```js
// math.js:279~281 — 크기가 0이면 무조건 0
mA = Math.sqrt(mA);  mB = Math.sqrt(mB);
if (mA === 0 || mB === 0) return 0;      // ← 영벡터끼리 = "완전 불일치" 취급
return dot / (mA * mB);
```
골든 스냅샷이 이 결과를 **정답으로 박제**하고 있다:
```
// pipeline.regression.snap:862~877 — "fixation: repeated identical emotions"
{ "alignment": 0, "bucket": "LOW", "level": 0.333333,
  "pattern": "bridge", "shape": 0, "shape_active": true }
```
`level` 은 0.333인데 `shape` 가 0이라 곱해서 0. 등급이 **LOW** 로 떨어지고 패턴은 **bridge**.

**영향:** 별이엔진 V4 문서 §9.3 은 "장면이 부족할 때 shape=1.0" 이라는 안전장치를 뒀지만, **delta 가 0인 경우**에 대한 안전장치는 없다. 감정이 흔들리지 않고 원본을 그대로 따라간 체험 — 해석상 **가장 공명에 가까운 플레이**일 수 있는 것 — 이 0점을 받고 LOW 로 분류된다. 이 0점은 그대로 오염 계산에 들어가 divergence 를 밀어올린다(`delta_div = (1-shape)×(1-level)` 에서 shape=0 이므로 최대 기여).

**확신: 확실** (코드 + 스냅샷 증거)

### [L5-02] 🔴 VOID(감정 회피) 보정이 작동하지 않는다 — 골든 픽스처가 실패를 정답으로 박제

- 파일: `js/core/ByeoriEngine.js:70~74`, `:114~141`
- 증거: `test/unit/__snapshots__/pipeline.regression.test.js.snap:563~582`

**증상:** 픽스처의 **이름**은 "체험자가 VOID, 원본은 비VOID → void_mod 0.7" 인데, **저장된 결과는 void_mod 가 1** 이다. 패턴도 `avoidance` 가 아니라 `contradiction`, mismatch 도 `void_mismatch` 가 아니라 `emotion_mismatch` 다. **셋 다 어긋났다.**

**근거:**
```
// pipeline.regression.snap:563~582
exports[`... > avoidance: user void on non-void original → void_mod 0.7 1`] = `
[ { "engine": {
      "alignment": 0, "bucket": "LOW",
      "mismatch": "emotion_mismatch",   // ← void_mismatch 여야 함
      "pattern": "contradiction",       // ← avoidance 여야 함
      "void_mod": 1,                    // ← 0.7 이어야 함
    }, ... } ]
```
엔진은 `userVector.reason_analysis.is_void` 를 본다(`ByeoriEngine.js:70~74`). 결과가 전부 비VOID 로 나왔다는 것은 **VOID 표시가 그 자리까지 도달하지 못한다**는 뜻이다.

**영향:** 별이엔진 V4 의 3개 항 중 하나(`void_mod`)가 **죽어 있다.** "말하고 싶지 않다"를 고른 체험자에게 걸려야 할 ×0.7 페널티가 안 걸리고, `avoidance` 패턴도 발생하지 않는다. SceneNavigator 의 avoidance 분기(빈 벡터 중심)도 사실상 도달 불가. 그리고 이 실패가 **골든 스냅샷에 "정답"으로 고정**돼 있어서, 누가 VOID 를 고쳐도 **테스트가 오히려 실패로 잡는다.**

**확신: 확실** (스냅샷의 이름 ↔ 값 불일치)

### [L5-03] 🔴 오염 2축(화면이 쓰는 것)과 3축(문서가 쓰는 것)이 정면으로 모순된 답을 낸다

**증상:** 한 파일 안에서 두 오염 모델이 동시에 돌면서 **서로 반대되는 결론**을 낸다. 3축 쪽은 "과잉완결 100%"라 하고, 2축 쪽은 같은 순간에 "안정(stable)"이라 한다.

**근거:**

{ "stage": "stable",        // ← 2축 EMA 판정 (화면이 쓰는 값)
  "stage_1": 0,
  "stage_2": 0,

### [L5-05] 🔴 실제 런타임 경로에서는 hypercompletion(과잉완결)에 도달할 수 없다

- 파일: `js/core/ContaminationTracker.js:375` (replayFromPlays) + `:36~40`, `:59`

**증상:** 오염 3단계의 종착점이 **실제 플레이 경로에서는 산술적으로 불가능**하다.

**근거:**
```js
// :375 — 근사 재계산은 집착도를 0으로 못박는다
fixation_level: 0,   // (not available in play records)

// :185 — 그러면 fixSignal 의 상한은
0.55 × 0        (집착도)     = 0
+ 0.25 × 최대 1 (정렬 보너스) = 0.25
+ 0.20 × 최대 1 (패턴 보너스) = 0.20
                              ─────
                       상한 = 0.45   <   임계값 0.65 (:59)
```
`cont_fixation` 은 이 신호의 EMA 이므로 **0.45 를 넘을 수 없다.**

**대조:** `updateContamination()` 에 진짜 `fixation_level` 을 직접 넣으면 도달한다 — 스냅샷(`:262~273`)이 depth 12에서 `hypercompletion` 을 보여준다. **즉 계산 모듈 자체는 정상이고, 문제는 실제 플레이가 타는 경로가 `replayFromPlays` 라는 것이다.** [L5-04](저장 안 됨) 때문에 정밀 경로의 결과가 살아남지 못하므로 구제되지 않는다.

**영향:** "가짜 원본이 굳는" 3단계 연출 — 작품 주제의 종착점 — 이 관객의 플레이로는 절대 발생하지 않는다. 작가가 admin 에서 `cont_stage` 를 손으로 넣을 때만 나타난다(`play-test.html:4785` override 분기).

**확신: 확실** (산술 + 스냅샷 대조)

### [L5-06] 🔴 transition_pattern 이 궤적이 아니라 bucket 에서 파생된다 — 문서 §5 판정 기준 미구현

- 파일: `js/core/ByeoriEngine.js:143~162`
- 어긋난 문서: 별이엔진 V4 §5

**증상:** 문서는 6패턴을 **delta 방향**에서 도출하라고 명시한다. 코드는 `userTraj`/`origTraj` 를 인자로 받지만 **길이 검사에만 쓰고 방향을 한 번도 비교하지 않는다.** 패턴은 등급의 별명이다.

**근거:**
```js
_getTransitionPattern(bucket, mismatchType, level, shape, userTraj, origTraj) {
    if (bucket === 'FIXATED') return 'fixation';
    if (level >= 0.5 && shape < 0.3 && userTraj.length >= 3 && origTraj.length >= 3) return 'displacement';
    if (bucket === 'HIGH') return 'echo_follow';   // 문서: "직전 2개 delta 방향 일치"
    if (bucket === 'MID')  return 'bridge';        // 문서: "나머지"
```

**영향 (두 겹):**
1. 문서가 약속한 "궤적의 형태에서 서사적 전이를 읽는다"가 사라졌다. CLAUDE.md 가 경고한 *"패턴이 lookup table 로 격하"* 가 실현돼 있다.
2. **`bridge` 가 구조적으로 지배한다.** MID 구간(0.10~0.50)이 가장 넓고 MID → 무조건 bridge. **골든 스냅샷이 이를 실증한다** — echo_follow 픽스처(`:759~825`)의 4스텝 중 3스텝이 `bridge`, displacement 픽스처(`:706~756`)의 3스텝 중 2스텝이 `bridge`. **원본과 거의 똑같이 따라간 체험조차 2번째 장면부터 bridge 로 떨어진다.** `level` 이 누적 평균이라 계속 내려가기 때문.

핸드아웃이 지목한 *"phase1 대화가 pattern 미산출, 'bridge' 고정 저장"* 제보 — **배선 단절이 아니라 엔진이 원래 대부분 bridge 를 뱉는 것**일 가능성이 매우 높다. 지휘 세션의 브라우저 재현 1순위.

**확신: 확실** (코드 + 스냅샷)

### [L5-08] 🟡 divergence 가 **두 판 만에** 1.0 으로 포화해 변별력을 잃는다

- 파일: `js/core/ContaminationTracker.js:230~231`
- 증거: `pipeline.regression.snap:3~40`

```
depth 1 → divergence 0.685714
depth 2 → divergence 1          ← 벌써 최대치
depth 3~10 → divergence 1 (고정)
```
명세 v2 §13.3 은 이 감쇠(`1/(1+depth×0.05)`)를 **"분자시계 포화 모델 — 초기엔 크고 점차 둔화"** 라고 정당화했지만, 실제로는 **둔화가 시작되기도 전에 천장을 친다.** DECAY_RATE 0.05 는 depth 20에서야 감쇠가 절반이 되는데, 그 전에 누적합이 1.0 을 넘는다. 열 판을 굴려도 여덟 판은 같은 값이다.

**영향:** 3축 중 divergence 는 사실상 **이진 신호**(0판=0, 2판 이상=1)다. `stage_1 = divergence × (1-convergence)` 이므로 stage 혼합도 함께 뭉개진다. (다만 [L5-03] 때문에 3축은 화면에 도달하지 않으므로 현재 체감 피해는 없다.)

**확신: 확실** (스냅샷)

## 지휘 세션에 넘기는 우선순위 제안

1. **[L5-02] VOID 죽음 + [L5-01] 영벡터 0점** — 둘 다 **골든 스냅샷이 오답을 정답으로 고정**하고 있다. 고치려면 스냅샷을 함께 갱신해야 하므로, **수정 전에 "무엇이 정답인지" 판정이 선행**되어야 한다. 이건 코드 판단이 아니라 **작가 판단**이다. (감정이 안 변한 체험은 공명인가 고착인가?)
2. **[L5-06] bridge 지배** — L1 의 "phase1 대화 bridge 고정" 제보와 **같은 뿌리일 가능성.** 브라우저 재현 1순위. 두 레인이 각각 다른 원인을 보고할 위험이 있으니 지휘 세션이 합쳐서 판정할 것.
3. **[L5-04] + [L5-05] + [L5-03] 은 한 덩어리.** 저장이 안 돼서(04) 근사 경로가 유일해지고, 그 경로가 집착도를 0으로 못박아(05) 3단계가 죽고, 그 와중에 2축과 3축이 서로 다른 답을 낸다(03). **04 를 먼저 고치면 05 가 절반 풀린다.**
4. **[L5-07] 축 3종** — L3(Edge Function)·L4(admin) 와 교차. 혼자 판정 불가.
5. **[L5-14] 지형 v2 미가동** — 이건 버그가 아니라 **미착수**다. 수리 목록이 아니라 **로드맵**으로 넘길 것.
