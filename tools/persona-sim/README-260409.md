# TEM Persona Simulation

Empirically-grounded reader simulation for TEM memory contamination analysis.

## Approach

Persona parameters are sampled from empirical Big Five score distributions
(N=307,313, IPIP-NEO-300; [automoto/big-five-data](https://github.com/automoto/big-five-data))
using stratified sampling across theoretically motivated trait combinations
relevant to the target memory. This avoids the mode collapse inherent in
purely LLM-generated personality profiles.

Each sampled score set is expanded into a biographical persona via Claude Opus 4.6,
with the explicit constraint that trait labels are never used in generation —
only concrete life events, emotional histories, and reading dispositions.
Personas then read the target memory scene-by-scene, generating emotion vectors,
alignment scores, and mismatch types as simulated first-person reader responses.

## Pipeline

```
big-five-data CSV (307K real humans)
    ↓  scripts/1_sample.js         (stratified sampling, seed=42)
data/sampled_scores.json           (15 personas × 5 Big Five scores)
    ↓  scripts/2_generate_personas.js   (Claude Opus 4.6)
data/personas.json                 (15 biographical narratives)
    ↓  scripts/3_simulate_plays.js  (Claude Sonnet 4.6)
data/plays.json                    (~250-400 plays)
    ↓  scripts/4_insert_db.js
Supabase plays table
```

## Setup

```bash
cd tools/persona-sim

# 1. Clone the Big Five dataset (one-time)
git clone --depth 1 https://github.com/automoto/big-five-data.git

# 2. Install deps
npm install

# 3. Configure secrets
cp .env.example .env
# Edit .env and set:
#   ANTHROPIC_API_KEY   (from console.anthropic.com)
#   SUPABASE_SERVICE_KEY (from Supabase project settings)
#   TARGET_MEMORY_ID    (defaults to "당신에게" memory)
```

## Run

```bash
# Phase 1 — stratified sampling (no API key needed)
npm run sample
# → data/sampled_scores.json

# ─── Optional review: check that 15 personas span distinct trait regions ───

# Phase 2 — generate biographical personas (Claude Opus, ~$2, ~3 min)
npm run generate-personas
# → data/personas.json

# ─── MANDATORY review: read through data/personas.json ───
# Are the 15 personas psychologically distinct? If any feel like
# variations of the same archetype, re-run with prompt adjustments.

# Phase 3 — simulate plays (Claude Sonnet, ~$3, ~10 min)
npm run simulate-plays
# → data/plays.json (incrementally saved; resumable)

# Phase 4 — insert into Supabase (--wipe clears existing first)
npm run insert-db -- --wipe
```

## Expected output characteristics

Targeting "Jacket on the Chair" (330 plays) as the reference for terrain quality:

| metric          | target       |
|-----------------|--------------|
| total plays     | 250+         |
| alignment mean  | 0.45 – 0.65  |
| alignment std   | ≥ 0.20       |
| alignment range | 0.05 – 0.95  |
| mismatch rate   | ≥ 50%        |

Verify with:
```sql
SELECT count(*), round(avg(alignment)::numeric,3) as avg_al,
       round(stddev(alignment)::numeric,3) as std_al,
       round(min(alignment)::numeric,3) as min_al,
       round(max(alignment)::numeric,3) as max_al,
       count(*) filter (where mismatch_type is not null)::float / count(*) as mm_rate
FROM plays WHERE memory_id = '<TARGET_MEMORY_ID>';
```

## Limitations

- Play responses are LLM-generated, not human — treat as exploratory instrument
- Persona narratives are fictional; only the Big Five scores are empirical
- No iterative refinement between plays (each scene read is independent)
- Korean-only; multilingual validation would require translation layer
