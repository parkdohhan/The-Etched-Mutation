# 순회 검수 (TEM walk critic)

작가는 총감독이다. 미술감독·공간 설계자가 걸러 줬어야 할 것이 날것으로 작가에게 올라가지 않게 하는 것이 이 검수의 일이다.
**보고만 한다. 이 검수 안에서는 고치지 않는다.** 고치는 것은 보고가 끝난 뒤의 일이고, 고친 뒤에는 걸린 구간을 다시 돈다.

출처(모두 읽고 이 작품에 맞게 다시 씀 — 원문 복사 아님):
- 걷는 순서·보고 형식 = OpenAI plugins `game-studio/game-playtest` 의 방식(켜기 → 주된 동작 해 보기 → 대표 상태마다 화면 찍기 → 화면 위 글자층을 그림층과 따로 보기 → 심한 순으로 보고).
- 화면 기준 = mike007jd/game-superpowers (MIT) `references/presentation.md`·`player-experience.md`.
- 총괄의 눈·심각도·"다시 올리지 않을 것" 목록·기록 남기기 = tdimino/claude-code-minoan (MIT) `design-critique`. 웹 화면용 점수표(닐슨 10항목)는 3D 무대에 안 맞아 쓰지 않는다.

## 0. 준비

- 시험 서버: `http://127.0.0.1:5173` (꺼져 있으면 `npx vite --port 5173 --strictPort --host 127.0.0.1 --open false`).
- 주소: `play-test.html?memory=<기억 id>&drift=1&dry=1&lang=ko` — **반드시 dry=1**(장부에 남기지 않는다). 특정 장면부터는 `&start=<장면 id>`.
- 브라우저 도구(playwright)로 열고, 페이지 안에서 `await import('/test/walk-critic.js')` → `window.__walk`.
- 걷는 동안 프로젝트 파일을 고치지 않는다(시험 서버가 창을 새로 열어 걸음이 처음으로 돌아간다).
- 먼저 읽는다: `prompt/walk-critic/rules.md`(작가 교정 목록), `prompt/walk-critic/ignore.md`(다시 올리지 않을 것).

## 1. 걷는 순서 (조각 하나)

단계마다 `__walk.<단계>()` 를 부르고 → 돌려준 숫자를 적고 → **화면을 찍어 직접 본다**. 숫자는 상태 오류를 찾고, 눈은 그게 어떻게 보이는지를 찾는다. 스크립트가 지나갔다고 처음 온 관객이 이해한다는 뜻은 아니다 — 매 화면에서 "처음 온 사람이 지금 뭘 해야 하는지 알까"를 따로 묻는다.

| 단계 | 부르는 것 | 화면에서 볼 것 |
|---|---|---|
| 들어감 | `enter()` | 첫 화면이 놀이인가, 안내판인가. 무엇을 향해 서 있나 |
| 둘러봄 | `look(0)` `look(120)` `look(240)` | 유령(말 걸 대상)이 어디 있는지 읽히나. 땅·하늘·안개의 명암. 떠 있는 말의 크기와 겹침 |
| 사물 | `toNearestThing()` → `touch(3)` | 안내 문구가 제때 뜨고 사라지나. 파낸 말·사물 글이 읽히나 |
| 다가감 | `toGhost()` | 가는 길에 걸리는 곳. 가까이서 유령·빛기둥이 화면을 덮지 않나 |
| 대화 | `talk()` → `write()` | 글이 읽히나, 뒤 장면이 비치나, 화면 위 글자층이 겹치지 않나. 쓰는 자리가 무엇을 하라는지 알 수 있나 |
| 보냄 | `send()` | 문이 생긴 걸 알 수 있나, 문이 어디인지 찾을 수 있나 |
| 문 | `toDoor()` | 문까지 갈 수 있나, 통로로 넘어가나 |
| 통로 | `corridor(3)` → `cross()` | 통로 안 밝기·조준점·발자국. 끝 문을 지나 도착하나 |

한 번의 검수에서 최소 **조각 2개 + 통로 1개**. 무대 전체를 고쳤으면 땅이 다른 장면(많이 밟힌 곳·덜 밟힌 곳·침묵 장면)을 `&start=` 로 하나씩 더 본다.
화면 사진은 `.walk-critic/<날짜-시각>/NN_<단계>.jpg` 로 저장한다(공개 저장소 제외 폴더).

## 2. 판정 기준 — 세 겹

### 가. 스크립트가 아는 것 (숫자, 걸리면 바로 결함)
- `errors` 가 비어 있지 않음.
- `stuck: true` — 걸어도 목표에 닿지 못함.
- `fps` 가 25 아래.
- `see.sprites` 에 `tooBig`(화면 절반 넘는 말) 또는 `tooSmall`(가까운데 못 읽을 크기).
- `see.overlays` — 화면 한가운데(놀이 공간)를 덮는 글자층이 걷는 중에도 남아 있음.
- `see.hints` — 이미 움직이고 있는데 첫 안내가 계속 떠 있음 / 할 수 없는 동작의 안내가 떠 있음.
- `ghostDist` 가 들어오자마자 3 아래(코앞) 또는 유령·출발 자리의 땅 높이 차가 커서 서로 안 보임.
- `send` 뒤 `door` 가 없음, `cross` 가 `arrived: false`.

### 나. 게임 화면 일반 기준 (눈으로)
- **한눈에 읽히는가**: 걷는 사람, 쓸 수 있는 땅, 중요한 신호(말 걸 대상·문)가 동시에 읽혀야 한다. 대상이 배경과 같은 밝기대에 묻히면 결함.
- **층별로 진단**: 구도 → 형태 → 재질 → 빛 → 효과 → 화면 위 글자층 순으로 어디가 원인인지 짚는다. 원인 층을 고치기 전에 장식을 더하자고 하지 않는다.
- **임시 모양과 완성 모양이 섞였는가**: 색·크기 체계가 다른 것이 한 화면에 있으면 결함.
- **반응이 원인과 붙어 있는가**: 누르면 무엇이 달라졌는지 보이는가. 소리 없이도, 색만이 아니어도 알 수 있는가.
- **결정의 순간에 알려 주는가**: 다음에 할 일이 그 자리에서 드러나는가. 안내가 건너뛰기 쉬운 첫 화면에만 있지 않은가. 누를 수 있어 보이는데 안 되는 것은 없는가.
- **주의와 조작을 지키는가**: 늘 떠 있는 것은 지금 결정에 필요한 것만. 놀이 공간 한가운데는 비운다. 창이 열렸다 닫힌 뒤 조작(마우스 고정 등)이 예상대로 돌아오는가.
- **여정이 이어지는가**: 들어감 → 놀이 → 다음(문·통로·도착·끝)이 끊기지 않는가.
- **제 매체로 본다**: 구도는 실제 화면 크기에서, 움직임은 제 속도에서, 소리는 귀로. 코드가 바뀐 것은 배선의 증거일 뿐 보이는 결과의 증거가 아니다. **소리는 이 검수가 들을 수 없다 — 매번 "소리 미확인"이라고 적는다.**

### 다. 작가 교정 목록 (`prompt/walk-critic/rules.md`)
한 줄씩 대조한다. 어긋나면 일반 기준보다 **먼저** 올린다. 작가가 새로 교정하면 그 자리에서 이 목록에 줄을 더한다.

## 3. 총괄의 눈 (전체를 한 번 더)
- 이 화면이 "아무 3D 데모"처럼 보이지 않는가. 이 작품의 것(안개 속 감각·글·유령)으로 읽히는가.
- 감정의 굴곡: 가장 센 순간이 어디였나, 끝이 어땠나.
- 잘 되는 것 2~3개를 구체적으로 적는다(다음 수정 때 지켜야 할 것).

## 4. 보고 형식
결함부터, 심한 순으로. 한 건마다:
- **[P0~P3] 무엇** — 관객이 보는 그대로.
- **어디서·어떻게 다시 보나** — 장면, 단계, 사진 파일.
- **왜 문제인가**.
- **어느 층의 일인가** — 땅 계산 / 놓인 것 / 빛·안개 / 화면 위 글자층 / 대화창 / 통로 / 엔진.

P0 = 진행이 막힘. P1 = 크게 헷갈리거나 작가 교정 목록 위반. P2 = 거슬리지만 지나갈 수 있음. P3 = 다듬기.
그 뒤에: 잘 되는 것, 확인 못 한 것(소리·실제 마우스·끝 화면 등은 매번 솔직히).

`.walk-critic/<날짜-시각>/report.md` 로 남기고, 같은 기억의 지난 보고가 있으면 P0·P1 개수의 흐름을 한 줄로 적는다.
`prompt/walk-critic/ignore.md` 에 있는 것은 조용히 뺀다(작가가 알고 둔 것). 이 파일은 작가만 늘린다 — 검수가 스스로 줄을 더하지 않는다.

## 5. 작가에게 올릴 때
- P0·P1 이 남아 있으면 고치고 다시 돈 뒤에 올린다. 고칠 수 없는 것은 "남은 것"으로 분명히 적는다.
- 작가에게는 쉬운 한국어로, 코드 용어 없이: 무엇을 봤고, 무엇이 걸렸고, 무엇을 고쳤고, 무엇을 못 봤는지.
